# 文章化前後の参照統一を確認する最小例

2026-10-24。これは**合成した会話の表示処理の例**である。モデル出力や実課題の実験記録ではない。第三者がモデル重み・非公開記録・APIなしで、P81で診断した経路とP82で共通化した処理を確認するために公開する。

## 実行

完全なリポジトリのルートで、Python 3.12を使用する。外部パッケージ、vendor、モデル、tokenizer、実験記録は不要。

```sh
python3.12 -S scripts/reproduce_protocol_fallback.py
```

標準出力に全入力、旧順序の全表示、新順序の全表示、値の保存確認をJSONで出す。`--output /tmp/protocol-example.json`で新規ファイルへ保存できる。既存ファイルは上書きしない。[実行スクリプト](../../scripts/reproduce_protocol_fallback.py)と[今回の全出力](synthetic_example.json)を残す。出力は時刻を含まず決定的であり、ファイル全体のSHA-256は `b8324077506a3301d02ea1c7a03e95d075bbf78597ebc2be1d07334840536087`。

## 何を変えたか

合成会話A/Bには、それぞれ不正な引数`{`を持つ呼出しと、正常なJSON引数を持つ呼出しを１つずつ置いた。どちらも実行しない。返答も架空の記録である。A/Bの違いは、通信参照の `example-a-1/2` と `example-b-1/2` だけで、対応する結果参照も同時に変更した。内容にはIDと同じ文字列 `example-a-1` を意図的に含め、通常のデータとして残す。内部推論フィールドは使っていない。

| 処理 | 不正引数の呼出し | 正常な呼出し | A/Bの表示全体 |
|---|---|---|---|
| 旧順序：文章化してから構造上のIDを統一 | IDがJSON文字列の内部へ移り、統一対象から外れる | 構造上に残るIDは統一される | 不一致 |
| 新順序：源の構造でIDを統一してから文章化 | 文章内にも統一済みの参照が入る | 呼出しと結果の対応を保つ | 一致 |

旧順序で第２呼出しに付く番号と新順序の番号は異なる。旧順序では第１呼出しが既に文字列へ移っているため、構造上で数えられない。この番号の違いを引数や観測の違いと混同しない。

両方の処理は既存の `ReasoningConversation`、`canonical_messages`、`StableReferenceConversation` を直接使用する。最小例だけの別実装で代用していない。原記録、通常の本文、壊れた引数、正常な関数名・引数、架空のエラーと返答が保持され、呼出しと結果が対応したままであることを確認する。既存の９検査には、複数呼出し、非object引数、ページ表示、孤立参照拒否、通常文中のJSONを変更しない場合も含まれる。

## 分かる範囲

比較対象は**モデルへ渡す会話JSONの値**であり、実モデルのテンプレート適用後の文章やtoken列ではない。この例はモデル生成、入力計数、環境API、評価、生成コード実行をいずれも０回としている。入力値の一致から、確率的な出力の一致や成功率、全仕事の費用削減は結論しない。

実保存入力をテンプレートとtokenizerへ通した確認は[閉じたP83](../../docs/P83_findings.md)、次出力への局所効果の計画は[未開始のP84](../../docs/experiments/P84_fallback_output.md)、全仕事の比較は実行中のP82に属する。ID正規化や改名への感度は既出であり、この例を新アルゴリズムとはしない。[先行研究と全件での露出範囲](../../docs/identifier_prior_and_exposure_20261024.md)および[保証する範囲](../../docs/protocol_rendering_invariance_20261024.md)を参照する。
