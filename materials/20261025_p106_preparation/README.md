# P106: 通常呼出しにも完全応答キャッシュを与える対照

[固定計画](../../configs/P106_ordinary_complete_read_cache_v01.json)はP105と同じ手書き７プログラムを、通常呼出しにも完全応答キャッシュを使う即時版と参照共有版で各１回実行する. [仕様](../../docs/experiments/P106_ordinary_read_cache.md).

P105の13対12 APIという差１回は、通常call_apiが即時版の完全応答を再利用しない段階６に由来した. 途中の取得省略は後段で相殺されたため、遅延取得の独自の利点とする事前説明は結果側で訂正済み. 今回は同一の通常キャッシュを両側へ追加し、同じ７段階の合計が12対12になるか、全出力が両側とP105に一致するかを調べる. 12対12は実行前の期待値である.

新しいキャッシュ部品の９検査、接続経路と故障・停止の５検査を含む全1,704検査が成功した. 部分値を完全応答にせず、状態変更で失効し、別の未取得参照の予約を保持する. ソース、保存結果、公開実装、既知課題説明を固定し、同じ完全headのpush/PR両workflowと両job成功後に一度実行する.

２環境、手書き14段階と設定２回、各20 API・総40 API、能動処理300秒以内. モデル生成・課題評価・未閲覧群参照・自動再試行０. この手書き列で同数でも、遅延取得全般の無効性や、自然な仕事での品質とトークン削減は判定できない. 原稿は保留し、比較と全件記録を優先する.
