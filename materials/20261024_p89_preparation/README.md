# P89 閉じた全８条件での読取候補点検の準備

P88の全８条件・399実API要求を対象に、各要求の直前に現在の公開契約で使える情報があったかを点検する。曲一覧からの部分値と、同一要求の完全応答キャッシュを分ける。後から返った値は一致確認にだけ使い、要求前の情報へ繰り上げない。

| 項目 | 固定した範囲 |
|---|---|
| 対象 | P88の既知４課題×２条件を元の順序で全件 |
| 私有ファイル | 各summary・usage・events・spans、計32ファイルのhashを固定 |
| 再利用の意味 | 既存P37の曲一覧５項目と同じ完全応答キャッシュ |
| 状態変更 | 既存６読取API以外の送信前に無効化。不明な作用以降は候補を復活させない |
| 上限 | 120秒、各ファイル16MiB、各4,000イベント・80生成境界 |
| 追加実行 | モデル、環境API、評価器、保存コード実行、DB・未見課題読取は全て０ |

全８条件の元の成否・費用・欠測を保持する。要求前に部分値があっても、後のPython処理で全項目を使う可能性がある。参照の存続や破棄はこの点検では分からず、取得を省けた件数やtoken削減へ換算しない。候補が０なら、現在の契約だけで大きなモデル比較へ進む根拠にしない。候補があっても将来参照と強い通常方式の確認が必要である。

９境界検査を追加した。未来の一覧、完全応答対照、保守的な無効化、値の矛盾、作用不明、確認済み例外、型の相違、順序・レシートの欠落を扱う。実記録の解析はまだ実行していない。

これはP88終了結果を見た後の開発用点検であり、未見課題での評価ではない。手書きの実サービス確認で得た11対10を、モデル課題の改善へ外挿しない。
