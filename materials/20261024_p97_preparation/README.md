# P97準備：通常の回復通知を全仕事で比べる

P96で認証履歴の追跡は単純な認証引数除外と同じ結果だったため、独自手法としては採用しない。一方で既知CSV課題には再観測の通知候補がある。P97は通常対照の有効性を確かめる。

|条件|回復通知|
|---|---|
|none|追加なし。共通の検出と記録は実施|
|generic|残りの要求と保持したPython変数を見直す|
|factual|再観測の事実と限界を示した上で同じ見直しを促す|

既知４課題×３条件、初期状態から１回ずつ、全12条件。対象の再観測が２モデル境界連続した直後、各実行最大１回。API省略や結果差し替えは行わない。検出器の他の２方式も影の判定として保存する。

１セル上限450,000 token/80モデル呼出し/1,800秒。全12セル予約5,400,000 token/960モデル呼出し、API1,200要求、所有サーバ32,400秒。実際に費やした量とは区別する。通知入力と制御・失敗も全仕事会計に含める。未知使用量や欠測は補充しない。事実通知の便益候補には、通常対照との成功維持・全仕事費用減少に加え、両通知の直前入力が同じで実際に通知が送信された課題を必要とする。

14合成検査と全1,516検査が成功。通知の１回性、入力計上、予算拒否と送信の区別、通信失敗時の不明使用量、停止・後片付け、記録改変の検出を確認した。公開依存・既知要求・公開ランタイムhashを照合済み。実モデルの初期入力確認と全仕事実行はまだ始めていない。同一headのpush・PR両workflow/job成功後に固定手順で一度だけ実行する。

新規性・全仕事の品質改善は未確立。未見12課題は保留。通知の一般案を新提案として付け直さない。
