## 固定実装で既にできること

[固定ソースと保存済み設定の点検](../../reports/output_budget_backend_scope_20261024.json)では、llama.cpp `620d2225` が `reasoning_budget_tokens` を受け取り、推論終了タグを強制できることを確認した。MiniMax-M3の開始・終了タグにも対応する。既存P83の６保存設定はハッシュが一致し、いずれも推論予算−1だった。

全出力上限は推論と公開出力の両方に掛かる。一方、推論予算はブロックごとの上限であり、UTF-8の終端待ち、終了タグ、後続の推論ブロックを考慮すると「残り半分を必ずコードへ割り当てる保証」ではない。遅延起動の文法制約も、全出力上限までに引数やPythonが完成する保証にはならない。

推論打切りによる出力誘導自体は[s1 §3.1](https://arxiv.org/html/2501.19393v3#S3.SS1)の既存手法である。また、[Budget-Aware Multi-Turn Agents](https://arxiv.org/html/2610.28409v1)はAppWorldを含む予算条件付き方策の学習を扱い、そのtoken costは推論・操作の生成トークンを数えるが入力を含めない。こちらの全仕事の入力・出力・失敗費用と同一の指標ではない。[読んだ範囲と未確認事項](../../reports/output_budget_prior_sources_20261024.json)を分けて記録した。

## 次の判断

普通の推論予算指定が効くかを未確認のまま、独自の適応制御が必要とは言えない。次は保存文脈で通常の予算指定の局所対照を有限に固定する。全体4,096のまま推論ブロック上限なし／2,048の２条件に限定し、途中切れ引数と公開操作なしの各１保存文脈、各２反復の計８生成を準備する。2,048は固定の半分指定であり、この数値の最適性を主張せず、閾値探索はしない。実行前に条件、予算、元要求、検査、停止条件を固定する。

これは新手法ではなく通常対照の確認である。生成コードは実行せず、引数が完成しても課題達成や全仕事削減とは扱わない。既存の欠測・全体未達・P84の局所性を維持する。新提案の中核と一般的な品質維持は引き続き未確立。
