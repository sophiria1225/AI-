# 予算通知と実時間上限の分離

P79終了後の通常部品。残時間を実測表示する方針と、現在通知には表示しない方針を明示的に選べるようにした。両方で実際の時間上限、全入力＋出力の計上、出力予約、初回の再利用なしを維持する。

[設計と適用範囲](../../docs/budget_observation_contract_20261023.md)／[実装](../../scripts/budget_observation.py)／[12項目の検査](../../tests/test_budget_observation.py)。

| 確認したこと | 結果 |
|---|---|
| 非表示方針で、現在通知だけに生じる残時間１秒の差 | 通知は同じ、実際の送信timeoutは50秒／49秒 |
| 入力も含めたtoken上限100、入力75、設定出力40 | 実際の出力予約25、全費用100を計上 |
| 実時間の期限到達、計数中の期限切れ、出力予約不足 | 新しい生成を行わず停止 |
| 送信後の不明使用量・終端記録のない通信例外 | 試行を不明として保存し、追加要求を拒否 |
| 初回要求で予期しない入力再利用 | 使用量を消さず、条件不一致で停止 |
| 過去履歴とAPI・モデル・tokenの使用量 | 保持。時間以外の資源変化は通知へ反映 |

ローカルfixtureによる接続検査であり、実モデル・環境API・生成コード実行・評価器・保留課題は０。既存の実験workerと原記録は変更していない。実タスクの品質・費用、新規性は未実証である。
