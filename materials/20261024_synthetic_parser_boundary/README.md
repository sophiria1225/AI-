# モデルを使わず途中切れの呼出しを再現する

2026-10-24。固定llama.cpp b11669のMiniMax-M3解析器へ、公開できる合成文字列５件を渡した。モデル、語彙、推論context、tokenizer、sampling、ツール、課題評価は使用していない。[合成入力と全出力](synthetic_results.json)と[出典・実行記録](../../reports/synthetic_parser_boundary_20261024.json)を保存した。

| 合成入力 | 返された呼出し数 | JSON objectとして読める引数 |
|---|---:|---|
| 完全な１呼出し | 1 | 1件とも可 |
| 引数文字列の途中で切断 | 1 | 不可 |
| 引数の閉じタグ後、呼出しの閉じタグ前で切断 | 1 | 不可 |
| 完全な１呼出しの後に途中切れの呼出し | 2 | 先頭のみ可 |
| 呼出しを含まない通常文 | 0 | 対象なし |

各入力をis_partial=true/falseの両指定で解析し、計10回の解析で表の結果を得た。この指定は解析器の引数であり、モデルの終了理由やHTTP成功を表すものではない。終端側の解析指定でも、途中切れの引数が自動的に完全なJSONになるわけではなかった。

## 確認範囲

固定コミット620d2225cc436ab0b001e3200e590e3b286ef9abのMiniMax-M3専用初期化関数を直接呼び、架空の短いtemplateと１つの合成ツール定義から解析器を作る。非空の遅延文法も構築されるが、サンプリングには適用していない。返却推論の抽出を無効にした合成入力であり、実モデルtemplate・token列・GPU状態・保存された実応答を再生したものではない。

実際の[終了済み429生成の診断](../20261024_tool_grammar_boundary/README.md)では、不正引数３応答が全て出力上限に達していた。今回の小例は、その不正引数を扱う解析器の挙動を私的履歴なしで確認するものである。どのトークンが生成されるか、文法制約が各トークンで働いたか、課題の成否や全費用への効果は検証していない。

## 再生成

[C++の合成例](../../scripts/reproduce_minimax_parser_boundary.cpp)と[実行処理](../../scripts/run_synthetic_parser_boundary.py)を公開した。必要なのは既存の固定ソースheaderと配布libraryであり、モデル重みや実験履歴は不要である。実行処理は以前のbuild記録にあるlibraryとheaderのhashを照合し、コンパイルを最大60秒、解析を最大30秒で１回ずつ行う。既存の出力先を上書きせず、失敗時に自動再試行しない。

```sh
python scripts/run_synthetic_parser_boundary.py \
  --storage-root /path/to/local/dependencies \
  --output /path/to/fresh/private/parser-probe
```

最初の開発用コンパイルはJSON wrapperのAPI指定で失敗し、解析０回だった。この記録を保持し、parse_no_throwの使用とリンク指定を直した版でコンパイル・解析を行った。５合成入力は変更していない。その後、公開する実行処理から同じ５入力を確認し、全結果が一致した。成功した実行は開発用と再生成確認の２回であり、独立した20事例とは数えない。公開処理の全時間は0.952021秒だった。

元の実験記録、P82/P84の入力・予算・順序は変更していない。これを新しい制御手法や、途中切れを修復する手法とは扱わない。[表示前後の参照統一の合成例](../20261024_protocol_minimal_reproducer/README.md)とは、解析器と履歴表示という異なる段階の確認である。
