# 同じ未取得値の参照で予約を共有する別版

即時方式が完全応答を再利用できる一方、元の遅延版は同じ対象への未取得参照ごとに予約し、予算不足や重複取得が生じる経路を、手書き模型で確認した. 課題scope・状態epoch・APIと全引数が一致し、同じ部分応答契約を持つ参照だけで予約を共有する別版を追加した.

片方の解放では予約を残し、最後の解放だけで取り消す. 未知項目は１回取得して共有する. 通常の別呼出しで完全応答が既に得られた場合も、実費を残し、次の予算判定前に予約を解除する. 状態変更前の取得と、失敗・紛失時の停止は維持する.

[仕様と元版の反例](../../docs/coalesced_read_reservations_20261025.md)／[別版hostとadapter](../../scripts/coalesced_contract_read_views.py)／[15検査](../../tests/test_coalesced_contract_read_views.py).

15追加検査・全1,685検査成功. 初回のfixture認証引数欠落による１失敗を保存し、fixtureを修正した. APIは手書き模型、adapterのコードも検査用に手書きしたもの. モデル・実AppWorld・評価器・予約群を使わず、進行中の実験には接続しない. 既存の実験ソースと結果、P104の元版24入力計画は不変.

通常の重複取得共有の実装改善であり、新手法や実課題の改善実証ではない. 異なる多数の対象の予約を減らすこと、LLM入力や全仕事費用の削減は示していない. 原稿の逐次改訂は保留を維持する.
