# 残時間表示の全仕事比較：P80

現在は実装・有限計画の準備段階。モデル生成は未開始で、効果は未確認。[固定計画](../../docs/experiments/P80_budget_visibility.md)／[土日の判断](../../docs/weekend_decision_20261023.md)。

P79では同じ入力の１秒差で公開行動が変わった。P80は実時間制限を維持したまま、残時間の表示を変えたときの課題全体の成否・費用を調べる。新規手法の主張ではない。

| 条件 | モデルへ渡す現在の残時間 | 実際の期限 |
|---|---|---|
| M | 実測整数秒 | 1,800秒 |
| H | 非表示と明記 | 1,800秒 |

両側でプロトコル参照IDを初出順へそろえる。公開本文・引数・過去の推論は変えず、モデルへ実際に渡す入力を計数する。既知４課題×２条件、seed57、各80生成・450,000 token。最初はcold cache、全履歴と通常Python例外を共通にする。

全件の成否と全費用を残す。Hで課題ごとの成功喪失０、全体token減、欠測０、監査一致なら通常設定の採用候補とする。４課題各１回の結果を一般優位や新規性の証明へ拡張しない。

新規手法の規則は引き続き未確定。土曜に候補を１つへ絞り、日曜に比較結果から主張の採否を決める。
