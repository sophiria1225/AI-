# P119: 行動と同じ応答に要約を含める比較の準備

通常の別呼出し要約と、行動の応答に古い履歴の要約も含める方式を、既知４課題×２方式の全８条件で比べる. 最初の16,384 native token以上の機会を一度だけ使い、元指示、直近２回、今回のコードと結果、その後の全履歴を残す. 追加指示、schema、要約出力、失敗、後続の再調査まで共有する仕事費用へ含める.

実装はハーネスの変更であり、モデルの再学習ではない. `run_python` の任意の引き継ぎ情報をコードから分離し、コード本文と参照IDを変えずに既存の実行器へ渡す. 原応答と実行側の引数は別に指紋で対応づける. 同じ応答の未実行結果は要約対象に含めない. 原履歴を保存し、次の入力が実測で短い場合だけ要約を採用する. この対応や形式検査は、自然言語の意味や課題成功を証明しない.

新規52テストを含む全1,936テストと構文検査が成功した. 合成試験はコードの不変性、原記録との対応、一度限りの機会、追加出力とschemaを含む予算、不明使用量の停止、不正要約、後処理、記録からの再照合を確認した. 実モデル生成、実API、独立評価はまだ行っていない. 合成のtoken値を実測節約へ使わない.

各条件80呼出し、450,000 token、1,800仕事秒で、別呼出し要約も同じ枠の内数. 所有server上限21,600秒. 同一headの両workflowと両job成功後、12入力の語彙計数を確認して固定順で各１回実行する. 成功を落として費用が減った場合は採用しない. 時点や指示も変わるため、差を専用要約入力だけの効果へ帰属させない.

P118は通常要約4/4、全保持3/4成功だったが、両側成功３課題の全費用は4,243 token増で基準未達. 今回はその通常要約を比較相手にする. 同じ応答に載せることを新規性とはしない. P111の不明２件、P118の不明１件を保持し、原稿と未見12課題は保留する.
