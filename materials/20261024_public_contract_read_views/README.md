# 返却済みの公開情報と読取ビューの接続

2026年10月24日。[P37の項目読取契約](../../scripts/field_read_contract.py)を、[新しい読取ビューの取得器](../../scripts/public_contract_read_views.py)へ接続した。実サービスへの新しい問い合わせやモデル実験は行っていない。

対象は以前から確認していた `spotify.show_song_library` と `spotify.show_song` の公開serializer関係である。既に成功して返された曲一覧から、曲ID・題名・アルバムID・長さ・アーティストを保持する。存在しない項目や未来の完全応答を使って部分値を作らない。実行ごとの範囲と状態版を分け、別課題の情報や矛盾する版を再利用しない。実サービスで使う前には、呼出し側が固定ソースの照合と課題世界の隔離を確認する必要がある。

比較対象の即時方式にも、同じ完全応答キャッシュを与える。完全応答を保持していれば、どちらも新しいAPI要求や取得予約なしに再利用する。部分応答しかない場合に限り、即時方式は完全取得し、候補は後の参照に備えて取得１回分を予約する。元の一覧取得や追加取得の費用は全て共通の台帳へ残す。これは通常の完全応答再利用を欠いた対照を置く設計ではない。

未発見のAPIや不正な引数は、キャッシュがあっても受理しない。無効なAPI操作のために保持中の応答を先回りして取得することも避ける。P37で既に確認した６つの読取APIだけは状態版を維持し、その他のAPIでは生きた応答を先に取得してからキャッシュを無効にする。ファイル操作や完了宣言を新たに無作用と認定したわけではない。

10件の追加検査を含む全1,353検査が通過した。一覧取得の実費、情報未観測時の即時取得、両方式の完全応答再利用、変更前の旧応答確保、状態版と実行範囲、矛盾、未発見APIの拒否を確認した。実際の永続Python通信ループへ、この取得器を接続する別プロセス検査も含む。全て手書きの模擬応答であり、AppWorldの課題・独立評価・LLMは使用していない。

並行して公開実装の[読取範囲とhash](../../reports/deferred_read_source_scope_20261024.json)を保存した。曲の読み出し・serializer、File/Directory/Taskの保存先や前後処理の一部を確認したが、依存する全処理や輸送障害まで含む一般的な等価性を保証したものではない。影響不明の操作を前に全取得する現在の規則で効果が消える可能性は残る。新しい変更例外は採用していない。

次は先に固定した[コンテナ確認](../20261024_deferred_view_runtime/README.md)をP88の終了後に実施する。この取得器を含む実サービスでの有効性と全費用は、その後の有限な計画で確認する。部品の完成や検査件数を新規性・採録可能性の証拠とはしない。[検査記録](../../reports/public_contract_read_views_preparation_20261024.json)。
