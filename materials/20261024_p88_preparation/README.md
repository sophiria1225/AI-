# P88：通常の推論予算を全仕事へ接続する準備

[固定計画](../../docs/experiments/P88_whole_task_reasoning_budget.md)は既知４課題×上限なし−1／固定2,048、各１回の８条件である。各課題を新しい初期状態から実行し、過去の成否を対照にしない。両条件とも残実時間を非表示にし、全返却推論・持続Python・型付きAPI・文章化前の参照統一を共通にする。

P87は４件目で停止しており、局所の主判定は不能のまま保持する。P88はその不足枠を補う追試ではなく、通常設定の効果が課題達成と全仕事費用へ届くかという別の問いを扱う。新しい方法の提案とは呼ばない。

各条件は80生成、450,000論理token、1,800作業秒。全体で640生成、3,600,000予約token、所有推論器21,600秒を上限とする。採用には、全８評価・使用量既知・監査一致、課題ごとの成功喪失０、両側成功１課題以上、全４課題の論理費用減を要求する。不明・未評価・未実行と失敗費用を残す。

[新しい接続](../../scripts/fixed_budget_local_llama.py)は入力計数と生成へ同じ専用設定を渡す。従来の残予算計算、未知使用量、timeoutの処理を維持し、旧実験コードを変更しない。[派生と同一構造の確認](../../reports/P88_runner_derivation_20261024.json)では、計数・生成・残予算処理の関数ASTの一致を確認した。設定を変える入口と明示的な継承順序は新しい検査で扱う。

17件の新しい境界・実worker接続・監査・初期計数検査を含む全1,285件が2.969秒で成功し、構文確認も通った。最初の合成初期計数検査ではfixtureのreportsディレクトリがなく２件エラーになり、fixtureを直して両方通過した。実験の再試行ではない。

[生成前の点検](../../reports/P88_offline_source_preparation_20261024.json)で68依存、P87の閉じた記録、既知４課題、導入済みAppWorldのソースと公開スキーマを照合した。４組の初期要求は専用予算フィールド以外が一致する。ここまでの実モデル生成・入力計数要求・環境API・課題評価は０。固定headの両CI/job、所有推論器、初期８計数の一致確認後に開始する。
