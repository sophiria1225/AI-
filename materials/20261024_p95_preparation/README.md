# P95：再要求と以前の値を分ける全件点検の準備

P88全８条件、全399 API要求、全150モデル境界を対象にする。公開済み集計ではCSV２条件が各10回ログインしていたが、同じAPI名だけで不要処理とは判断しない。要求引数・公開返答・間にある別操作を照合する。元の成功・失敗・不明１生成を全て保持する。

従来の読取６ APIの範囲と、それ以外の全操作による区切りを維持する。認証情報を取り除いた一致、後の返答からの事前利用許可、API０生成の自動的な重複判定は行わない。例外、不明作用、返答変化、値の大きさと記録数上限を検査する12の合成ケースと、全1,486検査が成功した。

上限120秒、各4,000イベント・80モデル境界、１入力16 MiB。32入力ファイルと８公開依存を固定。追加モデル・API・保存コード実行・DB読取・評価・保留課題の閲覧は０。固定headのpush・PR両workflowとjob成功後、一度だけ点検する。

要求・返答の一致は通常の診断であり、新規キャッシュ方式や削減実績ではない。[固定計画](../../configs/P95_recorded_request_repetition_v01.json)／[比較の規則](../../docs/experiments/P95_recorded_request_repetition.md)／[検査記録](../../reports/P95_preparation_20261024.json)。
