# P90 曲詳細４要求で事前情報が使えなかった理由の固定点検

P89は全８条件・399要求を点検し、現在の曲一覧契約に適合する取得を０件とした。次に全８条件を保持したまま、全４曲詳細要求で、対象を過去に観測していなかったのか、観測したが途中の操作で無効化されたのかを分ける。

P89の要求直前の分類を変更しない。既存の曲一覧と曲詳細の成功返答だけを、時刻順の診断用索引へ入れる。対象の過去の観測、５項目の有無、その応答単独の契約適合性、直後から要求直前までの無効化操作を出力する。後の実応答と過去の値が一致しても、過去の状態を再利用できる証明とはしない。現在の６読取API以外を除外扱いに変更しない。

元の全成否、150生成、既知1,689,160論理tokenと不明１、399要求、API例外20件を保持する。範囲はP89に固定された32ファイル、各16 MiB以下、各条件4,000イベント・80生成・履歴8,192レコード、全体120秒。点検は一度だけで、失敗時も記録を残す。モデル生成・実API・評価・保存コード実行・DB・未見課題の読取は０。

返答値・引数・認証情報・生成コードは公開しない。出力は既知の要求ハッシュ、順序、API名、項目名、分類と件数のみ。今回の点検は既知開発記録の追加分析であり、新規性・課題品質・削減量を実証するものではない。

新規９件を含む全1,376検査が成功した。未来の値、別の対象、無効化、値の不一致、不完全な事前情報、完全キャッシュ、確認済み例外、不明状態、固定対象の欠落を検査した。
