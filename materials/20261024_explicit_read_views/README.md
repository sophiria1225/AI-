# 明示的な読取ビューとPython参照の接続

[先の合成仕様](../20261024_deferred_read_obligations/README.md)の上へ、[読取ビュー](../../scripts/explicit_deferred_read_views.py)を追加した。即時取得と遅延取得の両方が同じ `ReadView` を返す。実APIとモデルにはまだ接続していない。

通常のPython参照で寿命を保つ。辞書・リスト・クロージャへ格納したビューは生存し、未取得部分の予約を残す。最後の参照が回収されたときにだけ予約を解放する。循環参照の解放時期はGCに依存し、解放されるまでは予約を残す。GCで費用を０へ書き換えたり、失敗した取得を再試行したりしない。

| 操作 | 即時取得と遅延取得に共通の意味 |
|---|---|
| `view['title']`、`view.get('title')` | 項目のコピーを返す。未知項目は完全取得してから読む |
| `dict(view)`、反復、長さ、`repr(view)` | 完全取得し、全体を観測する |
| 浅いコピー | 同じ読取権限を共有し、取得予約を切り離さない |
| 深いコピー・pickle | 完全取得した通常の辞書を渡す |
| 項目への代入 | 読取専用のため受け付けない |
| 所有者の明示的終了 | 全ビューを失効させる。課題完了を宣言する機能ではない |

`ReadView` は `dict` ではない。取得したリストなどを変更しても、ビュー内部の保存値は変わらない。JSONへ直接渡す操作も受け付けず、`dict(view)` が必要である。この明示的なインターフェースを両方式でそろえる設計で、既存の任意Pythonプログラムと透明に互換という主張はしない。

対象は単一スレッドである。並行アクセスや、実時間の締切までに遅延取得が必ず終わることは保証していない。要求回数の予約を時間の予約へ読み替えない。

８つの[Python境界検査](../../tests/test_explicit_deferred_read_views.py)で、実際のコンテナ・クロージャ・GC・コピー・直列化・失敗後の費用保持を確認した。全1,317検査が通過した。手書きのメモリ内世界を使う部品検査で、実課題の品質・実API削減・モデル呼出し削減ではない。[検査と追加ソース読取の記録](../../reports/explicit_deferred_read_views_preparation_20261024.json)。

次に必要なのは、公開APIの意味を固定した取得器、返却済み情報だけからの部分値作成、全実APIに共有する予約会計、変更を捕捉する接続である。公開Spotifyの保存版がP37と同じことと、対象関数・serializerの一部は確認したが、API全体の成功・無作用・変更依存関係を新たに保証してはいない。P88の途中記録は読まず、条件や推論器は変更していない。
