# 書出し課題の予算と既知の品質基準

2026-10-24。P81の最後の条件が進行中の時点で、既存の公開集計から同じ書出し課題 `6104387_1` の成功記録を確認した。新しい生成・API・評価・非公開評価内容・課題要件の閲覧は行っていない。

`P25_04_GUIDED` は独立評価で成功、12生成、370,343論理token、75 API、作業1,075.560141790891秒だった。[P25全結果](P25_findings.md)と[全件の対応表](../reports/P18_P25_paired_comparison.json)に保存されている。同じ成功がP27/P28/P29の比較表にも引用されているが、４回の成功実験ではなく同一の１記録である。

[P25設定](../configs/P25_guidance_transfer_v01.json)では、AppWorld 0.1.3.post1、MiniMax-M3 IQ4_XS、80生成、450,000論理token、80 API、1,800作業秒で実行していた。P80/P81の書出しにも同じ上限を用いている。したがって、過去の成功はこの予算規模で課題を達成できた具体例であり、今の未達を「80 APIでは必ず不可能」と説明する根拠はない。

ただしP25は直接API型で、公開スキーマの開示、seed、推論履歴、通知、実行形態と時期が現在の比較とは異なる。現在の状態保持Python型に対する同時に実行した因果対照ではない。P25の成功費用と現在の未達費用の差を、品質を維持した削減とはしない。過去に観測した件数や成功手順を、進行中・次の実験の追加指示としてモデルへ渡すこともしない。

P82でLがM/Hの両方を上回っても、それが同じ課題の3/4成功の範囲なら、既知の成功方式に対して必要品質を回復した証明にはならない。採用基準達成、現在の対照に対する成功喪失の有無、過去の通常方式との品質差を区別する。最終目標は必要な成果を保った全仕事費用の削減であり、現在の部分成功を目標品質へ読み替えない。

この確認は既存記録の位置づけを明確にしたもので、新規性や新たな制御規則の成立とはしない。[P29で既に記載した差](P29_findings.md)と[週末の判断方針](weekend_decision_20261023.md)を維持する。
