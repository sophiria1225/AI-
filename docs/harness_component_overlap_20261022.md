# 部品比較と費用評価の追加の近接研究

2026年10月22日。以下は原著者の公開原稿・公式実装を確認した範囲。査読採録を確認した一覧ではない。検索結果の要約だけで研究の未実施範囲を断定しない。

| 原典 | 確認範囲と重なり | 今回への判断 |
|---|---|---|
| [Beyond Token Savings](https://arxiv.org/html/2609.32961v1) | §3–4、付録A.5–A.6。圧縮の方式・時点・量を分け、成功、総token、時間、費用を比較。短い入力が速さや安さを保証しないこと、同程度の成功率でも解ける課題が違うことを扱う。費用の一部はキャッシュを仮定した推定。 | P33の「入力を短くしても総費用が増えた」という説明だけでは独自の主張に不足する。停止規則や実行状態を加えれば自動的に新しくなるわけでもない。 |
| [An Empirical Study of Harness Design for Coding Agents](https://arxiv.org/html/2609.20804v1) | §2–4。計画、操作インターフェース、履歴省略・参照・要約を切り分ける。情報の外部保存・再取得も比較済み。行動のまとめ方と呼出し数の関係も分析する。 | 「ハーネス内部を部品ごとに比較する」「コードで複数操作をまとめる」だけを新規性にしない。現在の基準実装との情報・権限・費用条件を合わせる必要がある。 |
| [BudgetBench](https://arxiv.org/abs/2609.13149) | 今回は要旨と書誌ページまで。１呼出しの入力予算を変える記憶方式の評価と、予算違反の記録を主題とする。本文・コードの再現はしていない。 | 予算を段階化する、超過を記録する、という一般的な評価設計だけを独自性にしない。１入力上限と累積入出力上限は区別する。 |
| [CLMの公式ハーネス説明](https://github.com/facebookresearch/context-language-models/blob/main/clm/clm_harness/README.md) | READMEの実行手順。入力を計数し、残枠に応じて圧縮を促し、外部ファイルのコンテキスト編集を取り込む。今回、全実装の精査や再現はしていない。 | 残枠通知、外部コンテキスト編集、終了前の通知を追加しただけの新規性は主張しない。 |

上記を踏まえ、現在は既存部品を組み合わせた完成品として投稿の主張を作らない。実際に残っている情報取得・入力・実行の負担と、単純な対処では解決しない条件を確かめる。API仕様だけの選択的な省略も、まず費用と情報損失を測る候補であり、独自方式と確定したわけではない。
