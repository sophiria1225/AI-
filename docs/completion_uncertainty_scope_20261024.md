# 完了条件の解釈が複数残る案を、そのまま新手法にしない

2026-10-24。P94終了後、P66の通常終了制御を自動化する余地を調べた。P66の既知写真１課題での費用減少は保持するが、人が書いた要求解釈を使った結果である。本調査は新しいモデル生成・環境操作・評価・保留課題の閲覧を含まない。[既存の自動作成の条件](automatic_completion_contract_scope_20261024.md)を変更するものではない。

## 候補集合に残る問題

以下は本研究側の案と論理的な点検であり、上の文献の新しい実験結果ではない。生成した完了条件の集合を $S$ とし、全ての条件が現在の公開記録で支持される時だけ終了する規則を考えた。真の要求が $S$ に含まれ、各検査が正しいなら、全候補の充足は真の要求の充足を含む。この含意自体は集合の包含関係であり、新定理ではない。

未解決なのは、真の要求が入るという前提である。「書き出してから退会する」という要求に対して全候補が書出しだけを検査すれば、退会前に全会一致しても未完了である。これは説明用の反例であり、P68の実際の出力を新しく測った結果ではない。引用箇所、JSONの適合、候補間の一致を増やしても、共通した見落としは残る。

候補の意味が衝突する場合は逆の問題もある。同じ物を残す候補と削除する候補の両方を満たす状態はなく、全候補の充足を待つ規則は停止できない。環境の追加読取で現在の状態は確かめられても、同じ要求文から読み分けた利用者の意図まで決まるとは限らない。追加検査を選ぶ方法と、要求解釈を確かめる方法は分ける。

## 今回の採否と次に必要な差

候補集合、全会一致、費用に応じた追加検査をつなぐ一般案のままでは、中核の新手法として採用しない。これは具体的な改良が存在しないという証明ではない。進めるなら、候補の被覆をどの分布・ラベル・予算で評価するか、共通欠落と矛盾をどう残すか、通常の単一判定および同じ生成予算を使う複数判定に対して何が変わるかを固定する必要がある。構築・検査・追加読取・通常継続を含む費用を初回から数える。

近い期限では、実測のあるP82/P84/P93/P94を原稿へまとめる作業を先へ進める。P94で見えた公開出力・構文・実API列の区別は局所的な実証として記載するが、新しい一般制御の成立とはしない。保留12課題は引き続き開かない。[読取範囲と取得制約](../reports/completion_uncertainty_prior_sources_20261024.json)。
