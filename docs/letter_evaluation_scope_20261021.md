# ４ページレターで主張できる評価範囲

2026年10月21日。未閲覧の12シナリオを残したことは、開発と確認を分ける準備である。**12件で一般的な品質維持を証明できる、という意味ではない。** 主方式・許容差・比較計画は未確定のまま。[群の分離](letter_scenario_reservation_20261021.md)、[従来の評価設計](evaluation_design.md)。

## 少数で全件同じ成否でも残る不確かさ

説明のため、独立かつ同じ分布の課題を一度ずつ試し、「基準は成功したが候補は失敗した」という悪化が０件だったと仮定する。悪化確率を `p` とすると０件の確率は `(1-p)^n`。これから得る片側95%上限は `1-0.05^(1/n)` となる。

| 仮定する独立課題数 | 悪化０件のときの悪化確率上限 |
|---:|---:|
| 4 | 52.7% |
| 12 | 22.1% |
| 18 | 15.3% |
| 30 | 9.5% |
| 59 | 5.0%未満 |

これは実測値ではなく計算例であり、成功率差の厳密な信頼区間そのものでもない。改善例の確率も成功率差に関係する。今回のID順で選んだ公式train内の課題群について、独立・同分布の無作為標本という仮定を保証していない。同じシナリオのseedを増やして、独立課題数を増やしたことにもしない。[計算条件と全数値](../reports/letter_evaluation_scope_20261021.json)。

したがって、12件の成否が同じだったとしても「品質低下５ポイント以内を保証した」「広く同等」と書かない。観測した全件の品質、費用、差の不確かさ、対象範囲を併記する。許容損失を締切に合わせて広げる方法も採らない。

## 今週の実行規模との関係

12シナリオ×２方式×１反復×30分上限なら、試行時間上限の単純合計は12時間。これは予測時間でも完了保証でもなく、評価・導入・サーバー準備・結果監査は別である。２反復なら同じ算術で24時間となる。比較方式やモデルをむやみに増やす前に、開発結果から一つの主比較を固定する。

レターの中心としてまず必要なのは、観測された特定の失敗条件に対する、近接方式では説明できない具体的な改善と反証可能な比較である。その上で未調整群の全結果を補強として示す。少数の一般性評価だけで主張を大きくしたり、形式の校正を新しい機構の有効性へ読み替えたりしない。

このメモは確認実験の事前登録ではない。実際の主方式・主比較・予算・反復・評価・除外条件・統計処理は、未閲覧群の要求文を開く前に別途固定する。主機構が成立しなければ確認群を使わずに残す。
