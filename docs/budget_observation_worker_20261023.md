# 時間通知部品と逐次実行・最終集計の接続

2026-10-23。[通知部品](budget_observation_contract_20261023.md)を使う[新しい実行関数](../scripts/run_budget_observation_cell.py)を追加した。旧P78の実行関数を元に、通知方針を明示的に渡し、送信処理開始後の使用量欠測を最終集計へ引き継ぐ。旧実験のコード・結果・原稿は変更していない。通常の比較基盤で、新規方式や費用改善ではない。

## 接続で守るもの

`measured` は既存の実測残時間通知、`not_exposed` は現在の通知で残時間を出さない設定。両方とも実時計の上限、正確な全入力計数、残予算に収まる出力予約を使う。過去の会話は書き換えず、初回cache無効・実測cache０を検査する。後続のcached inputも論理費用へ含める。API返却の文字列／例外という別の設定も明示して保持する。

新しい実行関数は、公開状態の初期化、持続Python、通常のAPI許可・記録、通知付き推論、公開履歴追加、終了と後片付けを接続する。`budget_observation_connection` と `BOC_` で始まる新規記録名を要求し、旧P78の計画や既存記録では起動しない。上限は呼出し80・450,000 token・1,800秒以下、API160以下・出力4,096以下で、各実行の明示値をさらに適用する。これは新実験の配分ではない。CLI・自動再試行・評価器呼出しは追加していない。

## 使用量が届かなかった試行

下位部品は `model_request_started` をモデル送信処理の入口で保存する。終端の使用量が届く前に例外が起きると、`infer.calls` だけにはその試行がない。新しい[集計関数](../scripts/budget_observation_worker.py)は、通知・送信記録と終端使用量のIDを照合し、その試行を `status=error`、入力・出力・時間は `null` として `usage.json` に残す。`terminal_usage.json` は実際に保存された終端使用量だけを保持する。

送信処理開始の記録は、推論サーバーが受信した証明ではない。この場合は `server_receipt_confirmed=false` を付け、費用を０と補完しない。既知の先行費用を保持し、最終の `model_calls`・`unknown_usage_calls` に含めて停止する。送信前に出力予約ができなかった場合は、試行０・未知０のまま区別する。

API結果の不明も別に扱う。同じ不明がAPI内側の記録とPython全体の記録へ現れるため、`unknown_effect_requests` はAPI送信を行った行だけを数える。１APIを２要求と数えない。不明な作用があれば後続のモデル・API処理を止める。

## 確認した範囲と限界

[17検査](../tests/test_budget_observation_worker.py)は、新しいworker、実際の通知・予算部品、会話整形、コード実行の分配器、API許可・返却経路を通す。モデル通信、Pythonセッション、外部API接続は合成の代替物を使う。生成コードを実行せず、手書きのRPCだけを流す。実コンテナ・AppWorld課題・実推論器への接続確認ではない。

| 確認対象 | 観測した動作 |
|---|---|
| ２通知方針×２返却方針 | ２試行の合成費用100 token、２fixture API、完了申告・後片付け。cached input20も合計へ算入 |
| １秒の処理遅延差 | 次の実timeoutは50／49秒。通知非表示では同じモデル入力、実測表示では通知だけが異なる |
| 応答欠落・使用量不明 | 初回／既知１試行後の両方で不明１件を保持。後続処理・再試行なし |
| 期限・上限・停止 | 計数中の期限、期限後に届く既知応答、API上限、明示停止で後続生成・操作を停止。既知応答費用は残す |
| 例外・資源・記録 | API例外設定、API結果不明１件の計上、後片付け失敗、初期公開状態不一致、初回cache違反、計画・ID拒否、既存記録保護を確認 |

全1,084検査は2.119秒で合格、compileallも合格。[検証記録](../reports/budget_observation_worker_20261023.json)。合成の100 tokenは実モデルの使用量ではない。新規モデル生成・実環境API・独立評価・保留12課題の閲覧は０。

次の実モデル比較は未配分。実行する場合は、目的、対象、各方針、順序、採否・欠測の扱いと有限予算、公開状態・依存版を別の計画に固定し、固定HEADのCIを確認してから接続する。単なる時間非表示を新規技術とせず、[残る制御候補](remaining_control_scope_20261023.md)の観測・判断・更新規則と、品質を保つ全仕事費用の検証を引き続き必要条件とする。
