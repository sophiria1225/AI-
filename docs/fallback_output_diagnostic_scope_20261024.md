# 入力の表現差を調べる診断と主張の境界

2026-10-24。P84は原因を切り分ける準備であり、新規手法・一般的な効率改善を確立する計画ではない。P82の全課題比較を優先し、実行中に条件を変更しない。

入力表現を変えればモデルの結果や費用が変わりうる、という広い主張は既存研究と重なる。Rohank Agarwalの[Measuring Local SLM Agents as Systems: Protocol Effects on Quality and Resource Use](https://rohankag.github.io/research/measuring-local-slm-agents/measuring-local-slm-agents.pdf)は、固定したローカル実行系で要求形式、schemaの内容・順序、サーバの起動方法を区別して調べている。§5の事前固定した順序比較は一様な改善を支持せず、§10.4では要求ごとの遅延と全体の経過時間で起動方法の評価が変わる。§11が述べるとおり主に単発のtool-call一致であり、複数ターンの実行・回復・最終成果は直接の対象ではない。著者ページでは未査読の技術報告とされている。通常の固定・照合・全体費用測定だけを本研究独自の方法とはしない。

Zhangらの[Same Simulation, Different Evidence: Where Retrieved Tool Output Costs LLM Agents Accuracy](https://arxiv.org/html/2610.26836v1)は、決定的な科学計算ツールで、正しい値の計算、モデルへの提示、最終回答のどこで誤りが生じるかを分ける。§4・付録Dでは同じ保存状態から結果の提示だけを変えた再開実験を用い、§5では参照すべき出力の明示等を調べている。§9はモデル・設定・実行時期・選ばれた再開点の範囲を限定している。保存状態を固定して表示を比較する実験設計そのものも既知である。

今回さらに確かめたい具体的な点は、構造化した呼出し参照の置換が、引数不正時の文章化経路では参照IDに届かず、同じ操作関係でも別のtoken列になること、およびその差だけで次の生成が変わるかである。P83は入力列までの事実を確かめたが、生成への局所効果は未確認。P84の結果が出ても、通常の参照正規化を新しいアルゴリズムと呼ぶ根拠や、課題全体の改善を主張する根拠にはならない。

レターに残せる候補は、先行研究との差をこの具体的な経路・条件・観測へ絞った実証結果である。ただし１つの既知文脈からの診断で一般化はできず、採録に足る中心貢献が確立したとの判断は保留する。最終目標は必要な情報・処理と品質を保った仕事全体の費用削減であり、診断の実装数を成果の代わりにしない。
