# 時間非表示でも残った文章化履歴内の呼出しID

2026-10-24。P81は第３反復を継続中である。第２反復の全８条件が終了・独立評価・読取監査済みになった時点で、P80全８条件との[追加読取](../reports/P81_second_repetition_diagnostic_20261024.json)を行った。全24条件の最終判断ではない。途中結果によって実行条件を変更せず、失敗と不明使用量を残す。

第２反復はM（残時間表示）698,592 token、H（非表示）768,173 tokenで、いずれも成功３／４、使用量不明０。H−Mは+69,581 tokenである。非表示の最初の３課題はP80と保存要求・公開出力・返却メッセージhash列が一致したが、CSV書出しは14生成目の要求から異なった。

第２反復の全８対を同じ手順で照合した。Mの４対は最初の要求差が現在の残時間欄だけであり、Hの３対は要求差が観測されなかった。H書出しの最初の差は、13生成目の不正引数呼出しを文章として保存した履歴中の `tool_call_records[0].id` だけだった。両方の要求は元の保存応答・実行観測から再構成し、その文章化が既存表示処理の出力そのものであることを確認した。生成された任意のJSONをプロトコルと決めつけて書き換えてはいない。

既存の正規化は表示後の構造化された `tool_calls[].id` と `tool_call_id` を扱う。文章化した内部のIDは残る。この差は非表示で必ず安定するという説明への制約であり、最初の３成功課題だけを選んで再現性を一般化してはならない。元のP80書出しには使用量不明１生成が残り、その対の全体一致判定を補修した扱いにもしていない。

新しい[通常の表示部品](../scripts/protocol_stable_history.py)では、検証済み会話の構造化参照を表示前に統一し、その後で既存の文章化・ページ表示を行う。原記録を変更せず、コード・引数・観測・エラー・返却推論を保持する。引数の修復、追加実行、成功認定は行わない。通常経路、文章化、複数呼出し、ページ表示、似た形の生成JSON、原記録保持、診断の区別を合成検査した。実モデルの安定性・品質・費用改善は未検証である。

この部品は通常の比較条件整備であり、新規アルゴリズムとはしない。読取は生成・API・再評価・token化を追加せず、ID差だけを除いた要求JSONの一致を確認する。元のモデル入力token列、数値状態、差の因果効果は確認していない。新しいモデル比較を固定する前に、この経路を共通条件で扱う必要がある。[後半表示の準備](late_clock_control_preparation_20261024.md)とは別の問題として記録する。P81全件終了後には、同じ補助照合を全24対へ適用する。
