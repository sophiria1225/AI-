# 10月24〜25日の判断と実行

ユーザーは10月23日、停止指示まで実行を続け、土日の２日で新規性を主張できるところまで進めたいと再確認した。最終目標は必要な情報・処理と品質を保ち、制御・失敗・再取得を含む全仕事費用を下げること。月末は採録確定ではなく、10月31日までの投稿完了が目標である。

現時点で独自の規則と一般的な費用改善は確立していない。「土日で採録水準まで必ず届く」とは判断できない。到達目標を、候補１つの実装・強い対照との比較・採否の決定とする。

| 時点 | 出すもの | 判断 |
|---|---|---|
| 金曜夜〜土曜 | [P80](experiments/P80_budget_visibility.md)の有限８条件と全件監査 | 時間表示という通常設定をどう扱うか判断する。これだけを新提案とはしない |
| 土曜 | 観測入力、保持状態、判断、更新、出力を具体的に書ける主候補１つ | 通常の保持・cache・取得前絞込み・例外回復と機能差が説明できること。根拠のない候補名を増やさない |
| 土曜〜日曜 | 候補と同じ情報・予算の強い通常対照、構築費込みの比較 | 開発段階で品質喪失や全費用増なら、改善成立とは扱わない。失敗を消して条件を選び直さない |
| 日曜夜 | 原稿の中心主張と残る不足を固定 | 支持された範囲だけ記載する。新手法未成立なら実証結果としての原稿に戻し、成立済みの表現を使わない |

既存のP54/P60/P61、P66、P70/P74等で確認済みの通常対照や適用候補０を、未実施の新候補として再計上しない。ただし近接研究の一般構想が存在することだけで、具体的な機能差の検討まで禁止しない。比較の前提・利用できる公開情報・構築費の違いを手順まで落とす。

保留12課題は主規則・対照・予算・品質・欠測分析が固定できた場合のみ確認へ使う。期限を理由に開発結果と混ぜない。原稿は現在の４頁＋英文１頁を維持し、Professor用の日英題名・456字あらましを勝手に変更しない。Projectとmaterialsには実装、実行中、終了・不採用を区別して記録する。
