# 実行領収に基づく履歴候補と先行方式

2026年10月25日、P109終了後に原典を確認した. ここに書く実行結果による表示切替は未評価の候補であり、先行研究がないことの証明ではない. 学習や追加判定モデルを使わないことだけも独自性にしない. 原稿の更新は保留する.

| 原典・確認範囲 | 既存の扱い | 当研究で混同しないこと |
|---|---|---|
| [ICLR v1](https://arxiv.org/html/2609.29875v1)、§3.1–3.2 | 行動と観測を保持し、完了した手順の推論をproxy entropyで選別する. 変更は後続の経路へ影響する. | 推論だけを減らすこと、実行後に不要性を考えることは既にある. ICLRは方式名で、ここでは会議採録を意味しない. |
| [StateComp v1](https://arxiv.org/html/2609.27298v1)、§3.1–3.3 | 現在の状態で元の情報が置換可能かを注釈し、未来の依存は不適切な候補を除くために使う. | 後で解けたことを、前の時点で捨ててよかった根拠にしない. 成功領収だけでも意味的な不要性は証明できない. |
| [ContextRender v1](https://arxiv.org/html/2609.37743v1)、§3、付録A.2–A.4 | 実行履歴の値の再出現を最初のtool結果へ帰属し、再利用・新しさ・意味的関連から予算内で結果を選ぶ. 全値は保持する. 帰属は因果的依存の証明ではないと明記する. | 実行依存に応じる選択や、非表示の原文保持は既にある. 文字一致と型付き領収は異なる信号だが、それだけで優位性は言えない. |
| [TRACE v1](https://arxiv.org/html/2608.06503v1)、§3.3–4.1 | 同じAppWorld状態から圧縮前後の継続を比較し、ブロックされた操作や再取得を検査する. | 実行に基づく圧縮評価や境界からの比較自体を新しい貢献にはしない. |
| [Agent-Controlled Forgetting v1](https://arxiv.org/html/2610.10590v1)、§3.1–3.4 | モデルがtool結果を注記へ置換し、原文を再取得できる. 取得可能性と将来判断の保持を区別する. | 可逆な保管・再表示だけで品質を保証しない. |

次に具体化する候補は、成功した非空のAPI実行、既知の失敗、未送信、作用不明をホストの領収から区別し、どの過去推論を次の要求へ含めるかを決定するもの. API値、提出コード、観測、ユーザー指示は保持する. 失敗や不確かな境界で原文を再表示するなら、その入力とcache再処理も費用へ含める. 私有推論の内容を別モデルへ判定させない.

これは現段階では素朴な制御候補である. 正常に実行されたコードが推論中の全ての予定を外部化したとは限らず、回復時に戻せることも失敗を防ぐ保証ではない. 全保持と直近保持を対照にし、同じ予算と実行基盤で最終品質・全仕事費用を評価しなければ採用しない. P107の１課題に合う閾値や指示を探索せず、保留群も方式選定に使わない.

上記の本文と明記した範囲の確認であり、著者の実装再現や網羅的な新規性調査は未実施である.
