# 実装レベルでの重複確認

2026年10月21日。P16の生成内容の意味監査前に確認した記録。

ProtoLinkの[公式説明](https://nmaroulis.github.io/protolink/docs/llm/)には、送信前拒否を実行成功として扱わず、修正用の情報を返す動作がある。
コミットe18712983c2d85ca525dcd764bff16043b280b10（2026年10月19日）の関連コードを読み、次を区別した。

- `base.py`の`reject_tool_request`は、変更なしの拒否を履歴へ返し、回数制限のある修正を続ける。
- `remember_action`は成功した操作の署名を直近の重複検出用リストへ入れる。これはLLMが作る長期記憶の意味検証そのものではない。
- `compaction.py`の要約処理は、古い会話からLLMで要約を生成して履歴を置き換える。読んだ関数には、要約中の操作完了という主張を実行記録へ一つずつ照合する処理は見当たらなかった。

読解範囲は該当関数と履歴処理。ライブラリ全体の再現、既定の全設定、実モデルでの不具合確認は行っていない。
「拒否を成功署名へ記録しない」と「生成された要約が未実行を完了と書かない」を混同しない。
この確認からProtoLinkに実際の誤完了があるとは主張できない。

本研究への含意は、拒否状態の記録と修正フィードバックだけを独自機能としないこと。
検討対象は、正しく区別された実行記録をLLMで記憶へ変換する際にも区別が保たれるかである。
ここにもMemTX・HaluMem等との重複があるため、対象を言い換えただけでは新規性が成立しない。
P16の単純対照と意味監査を経て、追加で示せる現象・対処の有無を判断する。
