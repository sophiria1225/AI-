# 通常計算対照を実行記録へ接続した準備

2026年10月21日。P22とは別の作業ブランチで、通常Pythonによる観測の処理を、全履歴実行器・保存状態・監査へ接続した。P22の凍結49ファイルに変更はない。次のモデル実験はまだ設定・開始していない。

## 目的と範囲

転記や集合処理の失敗に対し、計算手段のない基準だけで専用機構を正当化しないための比較準備。モデルは `compute_data` へ既存の観測IDとPythonを渡す。モデル応答前の公開観測だけを参照し、同じ応答内の未取得結果・私的推論・評価情報は入力しない。

計算は既存の固定Pythonコンテナで実行する。結果はモデルのプログラムの出力であり、要求の独立検証や完了判定ではない。API要求と計算の回数を分け、計算の実時間は課題全体の壁時間にも含める。拒否された引数、計算回数超過、実行失敗も記録する。実行基盤の異常後は、同じ応答に残る環境操作を止める。

既定の全履歴方式は変更しない。追加方式は明示した `native_compute` と計算上限の両方を要求する。実行器内の識別子P23は準備用であり、課題計画・バッチ登録・自動起動は未設定。P22の全件分析後に対象と予算を固定する。

## 確認したこと

383件の検査に合格。追加検査は、応答前の観測を固定すること、同じ応答内の未来IDを拒否すること、回数制限、異常後の操作停止、費用集計、履歴・保存境界の照合、入力ハッシュの改変検知を扱う。

モデル・アプリを模擬した全体実行では、実際のPythonコンテナを２回動かした。選択観測数の計算は期待値と一致し、計算部分は約0.255秒・0.256秒、各４境界の保存と全監査で不一致０。２回目は入力サイズ拒否の会計を補正した後の確認。実モデル呼出しと実AppWorld操作は０。模擬の各33トークンは研究の推論費用へ加えない。[機械可読記録](../reports/native_compute_runner_preflight_20261021.json)。初回の一般名の単体検査ログは最終検査で上書きされたため、そのハッシュを利用可能な原本とは扱わず、最終ログと両方の実行記録を保存した。P22と並行した追加負荷はこの軽いコンテナと単体検査であり、別LLMの同時推論はない。

初回の統合検査では、模擬応答に監査用の状態・予測トークン項目がなく、旧監査器が新しい方式IDを受け付けなかった。模擬記録を実記録と同じ形式へ揃え、計算の記録も監査対象へ追加した。監査を省いて通す案は採らない。

## 採らなかった案と限界

ホスト上の直接実行、隠し正解からの対象集合作成、計算費用の除外、P22途中への追加は採らない。通常Pythonそのものを新方式やCodeActの完全再現とは呼ばない。外部APIをコードから呼べる公式のコード型エージェントとは範囲が異なる。

この段階では研究上の性能改善も新規性も示していない。入力やコードの誤りはそのまま誤った結果になり得る。計算の実行制限10秒と、起動・検査・片付けを含むツール全体時間は区別する。全体時間を記録し、実験で用いる値は別途固定する。
