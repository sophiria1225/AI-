TSCGとMCP設計比較は著者公開原稿として扱う。正式採録と実装再現は未確認。TSCGの理論的主張の証明や公開実装の全経路を検証したという意味でもない。JSON Schemaの[公式エラー仕様](https://python-jsonschema.readthedocs.io/en/stable/errors/)にも検証規則・値・スキーマ位置を返す一般機能がある。詳細な修復情報そのものを新技術に数えない。

P47で切り分けるのは、同じ途中状態・残予算で、既公開の詳細契約を拒否時に返しても表示省略が有効か、引数名だけより追加価値があるかである。両対照に成功喪失がなく総費用が減るという開発基準を満たしても、独自性や未閲覧課題への一般化は別に検証する。

金曜に残す主張には、不要な処理を判別する実行時の根拠、必要処理を残す規則、最も近い方法と異なる具体的な結果が必要。一般的な機能の重なりだけで研究余地を否定せず、違いの名前だけで主提案へ昇格させない。P47の全件監査後に、保存済みの事実へ結び付く範囲を決める。
