# P73停止後の読取診断の範囲

P73は69入力の処理を終えた後、GGUF内の原文テンプレートとライブラリの保持するテンプレートのSHA-256が異なり、元の規則どおり `stopped` となった。元監査は全69入力の所在を確認したが、親処理が比較の前に停止したため、33対を検証済みとはしていない。

静的な差分は末尾LF１byteだけだった。固定版の [Jinja lexer](https://github.com/ggml-org/llama.cpp/blob/620d2225cc436ab0b001e3200e590e3b286ef9ab/common/jinja/lexer.cpp) は末尾改行を１つ除き、[chat.cpp](https://github.com/ggml-org/llama.cpp/blob/620d2225cc436ab0b001e3200e590e3b286ef9ab/common/chat.cpp) はその正規化後のsourceを保持する。準備時の照合対象の取り違えであり、旧planのハッシュ条件を事後に差し替えない。

次の追加作業は、元出典と固定実装・ライブラリ・保存69出力を読むだけに限定する。生成・語彙ロード・テンプレート再適用・token再計数・環境API・評価器は呼ばない。全33対、未変更／ID変更／本文変更の３対照を除外せず、保存されたtoken列・文章・生成制約・元実測入力数・対応IDの整合性を照合する。結果が不一致でも残し、同じbatchの再試行はしない。

元の原文11,756 byteと保存された実効原文11,755 byteについて、末尾LF１つ以外の差を認めない。一般的な空白除去で一致へ丸めない。元の停止結果・原監査・33対が元判定で未検証だったことは保持する。新しい出力は事後の読取診断と明示し、固定版で再構成した入力に関する限定的な根拠として使う。過去のGPU状態、乱数器、隠れた評価項目、成功率の一般性は検証しない。

読取上限120秒。実施に新しいモデル費用や環境操作を追加しない。元のP66/P68の全文不一致・成否・費用は変更せず、独自方式・因果効果の一般保証とはしない。
