# P82の費用指標を分ける終了後集計

P82の全24条件が閉じた後、全件監査・推論器集計・[条件付き区間](P82_interval_preparation_20261024.md)を用い、論理token、cacheを除く入力、出力、API回数、実時間を別々に集計する準備である。**実結果はまだ作っていない。** 使用量不明を確認した後の事後解析であり、主解析や採用基準は変更しない。

## 欠測が両側にある場合

既知分の差だけでは全費用の差を判定できない。合成検査の一例では、Lの既知分が対照より60 token少なくても、不明分を含めた条件付き区間では80〜100 token多い。この数値は検査用で、P82の結果ではない。

不明呼出しについて、固定ソース・保存要求・数値ログの照合が全て成立する場合に限り、事前入力数を`I`、正の生成進捗を`g`、要求出力上限を`C`として以下を用いる。

| 指標 | 不明呼出しの条件付き範囲 | 意味 |
|---|---|---|
| 論理入力＋出力 | `[I+g, I+C]` | cache入力も含む論理費用 |
| cacheを除く入力 | `[0, I]` | cache量が不明なので全範囲を残す |
| 受理された出力 | `[g, C]` | 取消し後に進んだ生成も上限内に含める |

既知呼出しの各計数を加え、条件間の差は`[L下限−対照上限, L上限−対照下限]`とする。cache量を０や他の反復の値で推定しない。既知分のCSV列は`known_`を明記する。これは前提付きの範囲であり、信頼区間、終端レシート、FLOPs、電力、請求額ではない。入力処理と出力生成を足して計算量と呼ばない。

## 全件と重複を保持する

全24条件を保存し、各反復と２反復合計についてL対M、L対Hを分ける。全体、成功同士、失敗同士、成否不一致を併記する。24比較区分と48側別集計を作るが、独立課題は既知４つである。同じL条件を二つの対照比較に使うため、比較表の費用をさらに合算しない。

準備・作業・後片付け・評価・モデル読込・推論器滞在は重なりを明示し、共有時間を条件へ割り振らない。実測時間差を通知だけの因果的な高速化とは扱わない。P80/P81は履歴処理が異なるので、このP82合計には混ぜない。

## 検証と実行

[７検査](../tests/test_late_clock_resources.py)で、両側の欠測による差の反転、未知cacheの範囲、失敗条件の保持、異常な計数・非有限時間・不整合区間の拒否、全24行・48側別CSVと上書き拒否を確認する。モデル・私有履歴・環境API・評価器へのアクセスはない。

全件終了後、同一hashで保存した公開集計３件を用いて実行する。

```sh
python scripts/summarize_late_clock_resources.py
```

入力は`reports/P82_comparison.json`、`P82_server_session.json`、`P82_usage_intervals_20261024.json`。出力は新しい`materials/20261024_p82_resource_accounting/`のJSON、全24行CSV、48側別CSV。既存の出力フォルダーは上書きしない。元の４採否比較は再計算・照合してそのまま保持する。
