# 実行状態を新規性と誤認しないための追加照合

2026年10月22日。P28実行中の調査。対象課題の途中内容や独立評価を使わず、公開原稿の機能を確認した。[確認範囲・取得記録](../reports/runtime_state_sources_20261022.json)。以下の正式採録先と実装再現は未確認。

| 原典 | 今回読んだ範囲と重なり | 今回の判断 |
|---|---|---|
| [Agents Learn Their Runtime](https://arxiv.org/html/2603.01209v1) | 3.3、4.2、付録B.2。学習時と実行時の変数保持を交差し、実行可能な変数名も提示する。 | 変数保持・初期化の比較、名前の表示、状態不一致の検出だけでは新規性を主張できない。今回の通常比較はこの一般問題と重なる。 |
| [CaveAgent](https://arxiv.org/html/2601.01569v1) | 3.1.2、4.3、付録E.3。状態を実行環境に保持し、必要箇所を出力でモデルへ渡す。共有実行状態による担当間連携も記載。 | 値をPythonへ残すこと、printで部分閲覧すること、共有オブジェクトで連携することだけを新提案にしない。 |
| [Agent Memory: Characterization and System Implications](https://arxiv.org/html/2606.06448v1) | 要旨・導入のみ。記憶構築・検索・生成を分けた費用分析を扱う。 | 記憶管理の全費用を測っただけでも独自性は足りない。詳細な条件比較は今後の本文確認が必要。 |

既に確認した[What Does Context Compression Cost an Agent?](https://arxiv.org/html/2608.16370v1)も、状態の欠落、再取得費用、最終成功だけでは見えない影響を扱う。したがって「短縮しても再取得で高くなる」という一般論だけを再発見として主張しない。

本研究で今確定しているのは、同じモデル・課題を使い、接続の案内、プログラムの状態、操作予算などを分けて評価する比較基盤と開発結果である。状態付きの通常方式を完成させることは、弱い比較相手を置かないために必要だが、それだけで研究の新規性は成立しない。

会話履歴の保持とPython状態の保持を交差する追加実験も考えられる。ただし、二つの軸を並べるだけでは独自技術ではない。既存原稿が示す状態依存と異なる条件・効果が、予算と成功率をそろえて確認できるかが必要である。現時点ではこの案を新規性の確定や追加試行の開始として扱わない。
