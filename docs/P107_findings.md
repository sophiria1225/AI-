# P107: 両方式とも未達で、遅延取得の対象APIは使われなかった

既知CSV１課題の即時取得と共有遅延取得を、同じ参照インタフェース、通常の完全応答キャッシュ、有限予算で各１回実行した. 両側とも独立評価で未達、21生成、427,234論理token、53実APIで終了した. 不明使用量０、監査不一致０. 事前の採用基準は未達で、新規性や品質を維持した費用削減は示していない.

両側とも次のモデル入力と出力枠の予約が成立せず、`token_reservation_limit`で終了した. 450,000は上限であり、実使用量ではない. APIは80枠中53を消費し、停止時の取得予約は０、残枠は27だった. API上限に達したための停止ではない. 実行エラーとその後の回復も費用に含めた. 全21位置の入力token、出力token、API送信数は条件間で一致するが、これだけでコードや全ての出力内容が一致したとは主張しない.

## 機構の不使用と対象の不一致

モデルは両側とも`read_view`を呼ばなかった. さらに閉鎖後の全API名の点検で、対象の`spotify.show_song`自体の送信も０だった. 送信は文書取得15、file_systemのloginとdirectory_exists各１、Spotify login１、album８、album_library２、artist14、playlist６、playlist_library２、song_library２、supervisorのaccount_passwords１で、合計53となる.

これは遅延取得が発動したうえで効果がなかったという比較ではない. 実際の経路に今回の対象APIがなく、機構による変更が生じなかった. この既知１課題の結果から、遅延取得がどの課題にも不要だとも、使わせれば改善するとも結論しない. 不要なshow_song要求を新たに作って方式の利用機会を製造しない.

[P108](P108_findings.md)では全42プログラム、108制御要求、106API返答に対応する保存記録を使い、当時のホスト処理と返答指紋を照合した. 不一致０、未取得参照の群０. 生成PythonやAPIを再実行した確認ではない. [API名の全件点検](../reports/P107_api_name_inventory_20261025.json)は結果閉鎖後の事後点検で、引数値、生成コード本文、内部推論、個別評価項目を解釈していない.

## 費用と実施範囲

新しい生成は42回、854,468論理token、106実API、独立評価２回. 生成Python42回と共通helper初期化２回を保持した. 所有推論器の稼働は3,345.011916秒、ロード10.056647秒、独立評価subprocess合計3.233249秒、最大観測RSS236,391,333,888 bytes、swap０. ロードや評価、設定、終了は推論器の全稼働と重なるため重複加算しない. １課題各１回の固定順序から速度差を主張しない.

固定head `983bdebed74654b5fa80af8a61a98d0af4147458`のpush workflow40121919860/job120955148933とpull_request workflow40122008111/job120955413958の成功後に一度開始した. 初期完全要求と入力計数を照合し、全304ソース結合を維持した. 全２条件の終了と所有プロセス停止後に、監査、資源集計、全件CSVを一度ずつ作成した. 条件、seed、上限の変更と再試行は０. 未見12課題は開いていない.
