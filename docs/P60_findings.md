# P60：明示的な所属判定の通常対照

既知１課題の保存観測で、両方の関係者一覧と終端がそろう場合に26依頼を肯定10・否定16へ分類した。通常の集合照合との不一致は０。行だけを渡して終端を与えない場合は、肯定10を保持し、残り16は不明になった。

これは要求の種類を分析者が指定した補助部品の確認である。元の検索を省いた実行、モデルが自律的に要求を選んだ比較、品質維持や総費用削減の結果ではない。通常の問い合わせ再利用を新手法とはしない。

## 固定と結果

[固定計画](experiments/P60_membership_evidence.md)と部品・16境界検査をcommit `2d6e054728dad3c208527bfc2b49ff2ba79cc382` に保存した後、全６条件を一度実行した。ソースの保存データと公開API実装はhashで照合。追加生成・計数・環境API・評価器・保留群閲覧はすべて０、実行0.0138秒。DB・隠れたテストは読んでいない。

| 取得済み証拠の条件 | 肯定 | 否定 | 不明 |
|---|---:|---:|---:|
| 観測なし | 0 | 0 | 26 |
| 一方の関係だけ・終端あり | 0 | 0 | 26 |
| 両方の関係・終端あり | 10 | 16 | 0 |
| 同じ両方の行・終端証拠なし | 10 | 0 | 16 |
| 状態版の変更後 | 0 | 0 | 26 |
| 別の利用主体 | 0 | 0 | 26 |

一方だけの条件はroommateを先に使う固定順序で、今回の26依頼には肯定する対象がなかった。肯定に全件列挙が不要であることは合成の境界検査でも確認した。全156要求は同じ26依頼への補助要求であり、156課題でも156回のLLM生成でもない。既知の１課題を選んだP59の事後選定を引き継ぐ。

## 実装の意味

[membership_evidence.py](../scripts/membership_evidence.py)は明示的なOR条件の所属だけを返す。メールの比較は完全一致で、勝手な大小文字変換を行わない。肯定は有効な観測、否定は全条件の連続ページと終端、不足・変更・不整合は不明を根拠とする。行上限・ページ上限で黙って打ち切った集合から否定せず、不正なページ列はリセットまで使わない。

終端と状態版を供給する接続側を信頼する。部品自体には外部更新の検知も、タスクから述語を導く機能もない。今回の保存観測は固定版公開APIの短い先頭ページを終端として扱った。検索返却全体を返す契約には対応しない。

全788検査合格。今回追加した16検査は、不完全なOR条件、空の最終ページ、状態・主体・情報源・契約の変更、欠けた値、矛盾、重複や順序、保持上限、リセットなどを対象とする。[全６条件の機械記録](../reports/P60_membership_evidence.json)の不一致は０。

## 次の判断

通常の照合を安全に部品化できた。研究として残るのは、実行中に必要な出力の範囲をどう得るか、そこに掛かる判断・再取得・失敗費用を含めても強い通常対照より改善するかである。既に表示済みの11行を再利用できただけでは、後の６検索の全返却やLLMの判断を自動的に消せない。

実LLM接続を伴う新比較の予算はまだ配分していない。次は、明示的な補助要求と状態更新を実行器に接続する条件を定義し、通常の取得・再利用で十分な部分を比較に含める。中心的な新規性と投稿に足る有効性は未確定のまま。
