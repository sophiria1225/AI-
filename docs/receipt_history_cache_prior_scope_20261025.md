# 履歴の復元とprefix cacheに関する追加照合

P111の全件成否を読む前に、キャッシュと復元可能な履歴管理に関する一次資料を照合した. P111/P112の固定規則を変更せず、実装再現や成績の直接比較は行っていない. [先の５方式](receipt_history_prior_scope_20261025.md)と[追加３方式](receipt_history_additional_priors_20261025.md)に続く範囲の確認であり、網羅的調査ではない.

| 一次資料と確認箇所 | 本文で確認した範囲 | 本研究で新規性に含めない一般構想 |
|---|---|---|
| [CADOC](https://arxiv.org/html/2609.37012v1), §2、§3.1–3.3、§4.1、§5.1、Appendix A.1–A.2 | 構造化内容を不変版として外部保存し、短いCardから正確に再取得する. 待機中の入力負担とcache再構築費を基に、追加LLMを使わず編集をまとめる. 定常条件での最適性と、固定履歴の計数、実際の継続評価を区別する. | 外部保存からの正確な復元、追加LLMなしの制御、cacheを考えた編集時期の調整. 論文の主費用はcached/uncachedを重み付けした入力費用で、P111のinput＋output論理tokenと同一ではない. |
| [Self-GC](https://arxiv.org/html/2607.00692v1), The Self-GC Framework、Recoverability and Cache-Aware Commit、Limitations、AppendixのEvaluation ArtifactsとPrompt Contracts | 別経路のplannerが索引付き履歴へfold等を提案し、harnessが対象、境界、復元情報、表示を管理する. cache喪失とplanner費用を考えてcommitを遅らせる. assistant turnは直接の対象にせず、主なオフライン評価は未来の履歴を用いるjudge判定である. | 保存履歴と実表示の分離、harnessによる復元可能性や形式の検査. オンラインの無作為品質比較やplanner費込みの対応する請求費監査は未実施と本文にあるため、報告された入力削減を一般的な品質維持へ読み替えない. |
| [TurnCost](https://arxiv.org/html/2610.15093v1), 今回は§7の限界を追加確認 | 既存の[読了記録](decision_log.md)では§1–4を確認済み. 今回、軌跡の選別、共通tokenizer、cacheモデルの前提、圧縮品質を直接測っていない点を確認した. 呼出し数と費用の関連を、呼出しを省いても品質が変わらない因果的証拠とはしていない. | cacheを考慮する会計、過去軌跡の再計数、呼出し数と総費用の関係の分析. 出版情報の独立照合とコード再現は今回も行っていない. |

以下は本研究側の解釈である. P111で評価する限定的な差は、過去の推論表示を、実行済みのホスト記録へ結び付けた固定規則で選び、直近が不適格なら原文を再表示する点. 上表の一般構想とこの実装上の差を混同しない. API正常終了は、推論の意味的不要性や課題成功の証明ではない.

P111では論理token、実測cached token、時間、API、生成回数を別々に残す. 金額を示すための価格を仮定していない. P112は同じ実軌跡上の表示差を数える診断であり、cache再構築費の最適化法や、別方針の品質を証明する方法ではない. 現段階で新方式の新規性、品質維持、総費用改善は未成立として扱う.
