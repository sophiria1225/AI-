# 遅延計算と将来費用の予約に関する先行範囲

2026年10月24日。今回の接続確認とは独立に原著の一部を読んだ。外部実装や証明を再現したものではない。

MoreiraらのIFL 2020論文は、遅延計算の資源上界を型で扱い、§2.4で未評価計算の費用と事前支払いを説明する。将来の実行費用を保持する発想を新規性には含めない。[著者公開論文](https://www.dcc.fc.up.pt/~pbv/research/ifl_2020.pdf)。

LorenzenのICALP 2026論文は、遅延計算に保持した資源の共有を扱う。§6では可変参照を導入した場合の制約も述べる。持続する参照と費用の対応だけで新規性を主張しない。[原著](https://drops.dagstuhl.de/storage/00lipics/lipics-vol374-icalp2026/html/LIPIcs.ICALP.2026.185/LIPIcs.ICALP.2026.185.html)。

ここからの研究上の判断は、通常の遅延取得、部分値再利用、将来要求の予約、参照解放の組合せだけでは独自性の根拠が不足する、ということ。実装上の対象は逐次生成されるPythonと状態を持つ公開APIだが、その対象の違いだけでは新手法の成立を主張しない。既存のLazyAgentの動的な計画更新も比較対象として残す。

[実サービス確認](../materials/20261024_public_read_views_live_results/README.md)は、手書き６段階の値を保ち、実APIを11回から10回へ減らした。しかし、既知項目だけを使って捨てる操作をこちらで作っており、その出現頻度やLLMによる課題達成は測っていない。次のモデル比較を計画するには、強い通常方式との差分と、実際に回避対象になる取得の範囲を具体化する必要がある。
