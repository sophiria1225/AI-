# P99の原稿化準備

通常auto/required比較を閉じた後に作る、別の検討稿を準備する. 現在のP98全件実証稿と教授向け456字あらましは変更しない. P99はまだ開始しておらず、この段階で実験の成績や採否を記述しない.

生成処理は全８条件、全４対、提出形式の二次指標、cacheと費用、失敗と不明使用量を取り込む. 全件の評価と使用量が既知で事前基準を満たした場合、既知だが満たさなかった場合、欠測や未評価が残る場合で要旨と結論を分ける. 未実行があれば全８条件を実行したとは書かず、予定枠を保持する. CSVの最終成果と形式の指標を分ける.

P98の全426生成の閉じた内訳を動機として記載する. 元の24実行の総数、397提出完了、４提出未完了、21提出なし、４応答不明と出典hashを照合し、397を課題成功数にしない. P99の新しい８条件は別の開発比較であり、過去の欠測を埋めない.

文法制約と入力依存文法は [Gengら](https://aclanthology.org/2023.emnlp-main.674/) の既存研究である. 文法適合性と制約下の生成分布の区別は [Parkら](https://papers.nips.cc/paper_files/paper/2024/hash/2bdc2267c3d7d01523e2e17ac0a754f3-Abstract-Conference.html) にもある. 今回確認した範囲は両論文の公式要旨と書誌情報であり、実装や定理を再検証したとはしない. 固定したMiniMax-M3用ソースのrequired/auto分岐も確認し、通常設定の比較であることを明記する. [確認範囲と出典](../reports/P99_manuscript_sources_20261024.json) を参照.

日英題名は維持し、和文要旨120字以内、英文50語以内、日英５キーワードを検査する. 著者情報は推測しない. 閉じたP99の監査、初期計数、activation、開始headと両CI/job記録、サーバ終了資料、全固定ソースがそろわない場合は実結果稿を作らない. 同じ出力先には上書きしない.

組版確認に合成fixtureを用いる場合、私有作業領域に置き、実験成績のPDFとして公開しない. 実結果稿は全頁を確認してから、現在の原稿への採否を決める. 良い結果でも新方式や一般的品質保証へ自動的に昇格しない. 保留12課題は閲覧しない.
