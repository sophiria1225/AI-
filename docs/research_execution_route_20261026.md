# 最終目標へ進む実験方針：2026年10月26日

ユーザーは、時間が限られているため実験を優先し、「止めて」と言うまで継続することを改めて指示した. バッチ終了を研究の終了とせず、全件の確認、採否、次の有限な比較まで進める. 個々の実行の予算上限と異常時の停止は守り、停止した場合も原因と次に進める条件を判断する. 同じ実験の許可を毎段階で聞き直さない.

## 最終目標と現在地

最終タスクの性能を保ち、要約・制御・失敗・修復・再取得を含む仕事全体の入力＋出力トークンを減らすハーネス制御を実証し、その具体的な機構に新規性を持たせる. 入力だけの短縮、安い失敗、成功課題だけの小計、実装や監査の件数を目標達成に置き換えない.

P122は別要約10/12対同時要約9/12成功で、全体目標は未達. 写真は３対中２対で減少、１対で増加し、CSVでは成功を失った. CSV seed257の最後の要求は使用量不明で、正確な全体費用も未確定. この不明値、失敗、旧自動判定falseを保持する. P123は、閉鎖済みのP122とは独立した新しい比較である.

現実装は、形式に適合し、次の入力が実測で短くなる要約を採用する. これは必要情報の意味的な保持や、要約作成費の回収を保証しない. 同時生成は追加指示、schema、出力配分、後続行動も変えるため、成否や費用差を圧縮だけへ帰属させない.

## 今回の固定比較

P123は単発別要約・反復別要約・反復同時要約の３方式を、既知の写真・精算・返金・CSVで１回ずつ比較する全12条件. 固定済みの順番、world seed42、model seed57、閾値、要約機会上限、予算を変更しない. １条件は80モデル要求・450,000 token・1,800作業秒、全体は960要求・5,400,000 token・1,200 API・12評価を上限とする. 同一headの両CIと通常の実機検査を通して一度だけ実行し、途中成否で設計を変えない. 実際の稼働状態はプロセスと更新時刻で別途確認する.

開発採用には、全12条件の評価、使用量既知、監査エラー０に加え、反復同時方式が双方の対照の成功課題を１件も失わず、全４課題と全方式共通成功課題の双方で総トークンを減らすことが必要. 共通成功は１課題以上、両反復方式とも少なくとも１課題で２回以上の要約採用が必要である.

## 全件閉鎖後の分岐

| 結果 | 次の有限な作業 |
|---|---|
| 全採用条件を通過 | ４既知課題に限った正結果として保存. 作成費、採用後の入力、追加取得、行動数を分けて便益を確認し、必要な反復と機構比較を絞る. seed157/257の同一３方式反復は候補であり、まだ固定済み計画ではない |
| 反復が動いたが成功損失または費用増 | 不採用とし、保存記録から情報欠落の候補、行動変化、再取得、予算停止を区別する. 終端理由を根本原因と断定しない. 診断に対応する１因子の変更を新計画にし、全４課題と強い対照を残す |
| 反復が２回以上採用されない | 意図した機構は未検証. P123の閾値を事後変更して救済しない. 必要なら追加開発群で別計画を固定し、確認群を開発用に使わない |
| 使用量不明・実行異常 | 原記録を保存し、正確な費用優位を判定しない. 作用、後始末、所有server、評価の閉鎖を確認した上で、独立した次の判断を新しく記録する |

追加方式の実装前に、削る費用、判断時点で観測できる信号、保持すべき情報、同じ予算の単純対照、棄却条件の５点を１案へ絞る. 課題・seed・閾値を成功するまで選び直さず、無制限な基盤追加や新しいベンチマーク導入へ広げない.

## 確認評価と新規性

未見12シナリオは露出を防ぐための予約であり、確認実験の事前登録が完成したことを意味しない. 現在、品質許容差、区間推定法、必要件数、実行方式・対照・seed列・予算・除外・分析は追加の固定が必要. 要求文を開く前にこれらを決め、確認群で調整しない. 期限や資源に合わせて品質許容差を緩めない. 12課題で悪化０でも、小標本の観測を一般的な非劣性の証明とは呼ばない.

新規性も未確立である. 既存の原典照合では、反復要約、状態と行動の同時生成、型別保持、出典確認、可逆な履歴保存、適応的な圧縮時点に近接方式がある. P123を通過しただけで新規手法成立とはしない. 具体的な観測信号で保持・実行判断が変わり、通常方式にない便益が強い対照との比較で残るかを確認する. 独自の名称や４欄のschemaだけで差分を作らない.

実験を優先し、まとまった結果の節目でProject、materials、原稿次版を更新する. 10月31日の投稿目標と29–30日の執筆時間を意識し、方法の新規性が支えられない場合も隠さず、観測から支えられる主張へ整理する. 一回のwrapperにはその後の研究判断を続ける機能がないため、全件回収後の判断まで担当を継続する.
