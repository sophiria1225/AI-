# P100：P97の不明費用と条件付きの大小関係

P97全12条件・223試行の保存使用量と保存要求を一度だけ点検した. 既知221生成は事前入力計数・要求出力上限と整合し、不明２生成は不明のまま保持した. 追加生成・API・評価・保存コード実行は０、CI照合込み2.828851秒. 課題DB、私有推論の意味内容、P99途中成否、未見12課題は読んでいない.

## 全仕事の区間

単位はcached inputを含む入力＋出力token. 上限は記録された入力計数と要求出力上限がサーバで守られたという仮定下の値で、実測値の補完ではない.

| 方式 | 成功 | 既知token | 不明生成 | 条件付き合計区間 |
|---|---:|---:|---:|---:|
| 通知なし N | 3/4 | 769,281 | 1 | [769,281, 809,337] |
| 一般通知 G | 3/4 | 797,644 | 1 | [797,644, 840,244] |
| 事実通知 F | 3/4 | 872,641 | 0 | [872,641, 872,641] |

| 差 | 要求ごとの上限による区間 | context上限だけの緩い区間 | 仮定下の符号 |

| G−N | [−11,693, 70,963] | [−37,173, 93,899] | 不明 |
| F−N | [63,304, 103,360] | [37,824, 103,360] | 正 |
| F−G | [32,397, 74,997] | [9,461, 74,997] | 正 |

不明なNのcall_020は入力計数35,960、出力上限4,096、合計上限40,056. Gのcall_021は38,504＋4,096＝42,600. サーバ受領も断定しないため下限は０としたが、０を実使用量として採用していない. 既知費用2,439,566＋不明２という元の会計を維持する.

成功３課題は各方式448,825 token、差０. 区間差は全未達のCSV課題に由来する. そのためこの結果を成功に要する費用差や効率改善として報告しない. 入力計数を使わずcontext65536だけを上限とした緩い区間でも、Fの費用増という符号は同じ. GとNの大小は識別できない.

## 限界と判断

サーバが上限を守ったことは、欠測した２生成では証明されていない. 正常221生成の整合から欠測への保証を導かない. 定義した論理費用に未記録の再試行がなく、事前計数が該当要求へ適用されることも仮定する. これらを置かない無条件の有限上限は示していない. サーバ時間・消費電力・内部処理費用の区間でもない.

通常の区間演算による、既知の結果を見た後の感度分析である. P97の元の採用基準・欠測・評価・途中集計出力の逸脱は保持する. 新しい採用基準でやり直した実験ではない. Fを主提案に採用しない判断を補足し、新手法・一般品質維持・全仕事削減を主張しない. P99の固定比較は変更しない.
