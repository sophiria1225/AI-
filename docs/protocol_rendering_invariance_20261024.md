# 表示前の通信参照統一が保証する範囲

2026-10-24。対象は、検証済みの会話に含まれるツール呼出しIDとその結果の対応参照である。ファイルID、商品ID、API引数中の文字列、生成文中に引用されたIDらしい文字列は対象外である。

会話Hに対し、対応を保って通信参照だけを一対一に改名する操作をρ、初出順で参照を統一する操作をC、既存の表示処理をRとする。源の会話構造へCを適用すると、通信参照以外が同じである範囲で C(ρ(H)) = C(H) となる。したがって R(C(ρ(H))) = R(C(H)) である。表示処理が不正な引数を文章に戻す場合や、長い観測をページ表示する場合にも、改名済みの同じ構造を渡す。

先にRを行い、その後で構造化された参照欄だけを統一する処理には、この性質は成立しない。文章になった参照が処理対象から外れるためである。P81第２反復の補助読取はその具体例を示した。これは通常の構造化データ処理の性質を当該実装に適用したもので、新しいアルゴリズムや一般的な再現性保証とはしない。

統一処理は原記録を保持し、コード・引数・観測・エラー・返却推論の値を変更しない。呼出しの順序、結果の対応、不正引数が不正であることも保持する。しかし、モデルへ渡す文字列自体は変わり得るため、成果の品質維持をこの性質から証明することはできない。モデルの実行、独立した成果評価、制御費用を含む全仕事の比較は引き続き必要である。

[実装と検査](../scripts/protocol_stable_history.py)、[第２反復の診断](P81_fallback_reference_diagnostic_20261024.md)、[モデル入力再構成の計画](experiments/P83_fallback_prompt.md)を対応させる。時間通知の選択は別の規則であり、通信参照の統一から時間情報の必要性を推定しない。
