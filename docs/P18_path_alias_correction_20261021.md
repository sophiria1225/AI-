# P18の移動元パス集計の訂正

2026年10月21日。P20生成中の終了済み記録点検で判明した分析側の不備。モデルの追加呼出し・環境操作は０。

初版の`listed_without_move_receipt`は42と出力していた。列挙・メタデータの絶対パスと、移動要求の`~`表記を直接比較したため、実際には同じ27対象の対応が失われていた。

先行する成功メタデータ返却から、要求パスと返却パスの対応を取得するよう修正した。ホストのホームディレクトリや推定による文字列置換を使わない。送信していない操作は除外し、対応不明の移動があれば正確な未処理件数を出さない。

| 項目 | 訂正前 | 訂正後 |
|---|---:|---:|
| 列挙した異なるパス | 42 | 42 |
| JSON返却を伴う移動要求 | 27 | 27 |
| 既出メタデータで対応できた移動元 | 未計数 | 27 |
| 対応不明の移動元 | 未計数 | 0 |
| 列挙集合のうち移動返却がない対象 | 42（誤り） | 15 |

[初版](../reports/P18_public_evidence_diagnosis.json)は訂正履歴として残し、今後この項目は[訂正版](../reports/P18_public_evidence_diagnosis_v02.json)を使う。原記録のハッシュは全４件で一致し、曲の欠落診断の値は全て不変。P18の成否2/4、送信API187、生成49、総トークン1,017,215にも変更はない。既存説明資料の「42件と27件」および差15件は変わらない。

別名の対応、未送信の除外、対応不明時に値を確定しない制御を追加し、対象の５検査が通過した。JSON返却があることだけで、移動先や最終状態の正しさを証明したとは扱わない。
