# P102の保存出力実行処理を準備

P101の生成中に、[生成前に固定したP102設計](experiments/P102_choice_action_execution.md)を実装した. P101の途中出力・途中使用量は読んでいない. 既存P94の先行操作照合と通常実行口を再利用し、P94のコードと結果は変更しない.

実行前に、P101の全36枠の閉鎖監査、元の要求と応答、所有推論器とPIDの不在、P101の計画と初期確認を照合する. 準備段階の計画では実行できない. 閉鎖後の全既知応答と先行操作のhashを最終計画へ結びつけ、P102自身の実行headの両CIを確認してから一度だけ実行する.

終端が既知なら、本文のみ、形式不整合、途中切れでも元の出力のまま確認対象に残す. 静的形式がよいものだけを選ばない. 不明と未実行は実行可能な出力に補完せず、全36枠へ理由を記録する. 先行操作の不一致や未知作用では停止し、それまでのAPI試行と後片付けを記録して後続を補充しない.

全12条件内36比較と全66条件組594比較を保持する. 双方に非空の送信API列がある対と、双方でPythonが実行された対を区別する. 両方とも空のAPI列は非空要求の一致に数えず、Pythonが動いてもAPIを送らなかった対は別の分母にする. 実行例外も記録された実行の一部であり、API列や実行記録の一致を正しい最終成果としない. 途中切れを含む比較の数も残す.

追加検査は、全枠・順序と欠測の維持、本文のみや途中切れの非選別、元の計画上限、66組の全比較、空API列、先行不一致時の後続停止と既発生費用、推論器PIDが残る場合の拒否、停止した古いサーバ記録だけでは閉鎖としないこと、JSON整形だけが違う同一終了記録の扱いを対象にした. 検査は合成fixtureとmockを使い、実AppWorldのAPIやモデルは呼んでいない.

実際のP102、最終計画、終了後の資料生成は未実施. P101の実行木を変えず、P102の実環境処理もP101閉鎖前には開始しない. 新手法、最終課題品質、全仕事削減は未確立.
