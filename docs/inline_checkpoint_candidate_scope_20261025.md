# 通常処理と同じ応答に引き継ぎ情報を載せる候補の範囲

2026年10月25日、P118の全８条件終了前に整理した検討案. 実装、実モデル比較、性能確認、新規性の確立はいずれも未実施. P118の中間成否や要約本文は参照していない. P118の固定条件を変更する資料ではない.

削減候補は、要約専用の要求で長い履歴をもう一度入力する費用である. 通常のコード生成に引き継ぎ情報も含めれば、専用要求の再入力を避けられる可能性がある. 追加する出力、tool schemaと指示の増加、出力上限の競合、形式失敗、後続の再調査は費用へ残る. 同じ応答に載せるだけで総費用が下がるとはしない.

## 時点を混ぜない

同じ応答にはまだ実行していないコードが含まれる. このコードによる結果を、引き継ぎ情報の確定した完了事実へ先取りしてはならない. 少なくとも次の二つを区別する必要がある.

- 既に閉じた古い会話だけを要約し、今回のコードとその返却は原文で残す方式. これは実行結果の予測を必要としない通常対照になり得る.
- 今回の処理後の状態まで提案し、実行後に照合して採用する方式. 対応する記録が存在すること、正常返却、指紋一致だけでは、自然言語の要約内容や元依頼の充足を証明できない.

実行後に照合する案は、何を機械で判定するのかが未確定である. 参照先の一致を意味の一致へ読み替えない. 保留や棄却を増やせば表示が長いままとなるため、その費用と適用率も比較対象にする.

## 既存方式との境界

[MemTXの方法](https://arxiv.org/html/2607.23929v1#S3)には、候補記憶の段階的な確定、出典と有効性の検査、操作前の判定、依存する記憶の失効がある. 従って、記憶を提案してから検査するという一般構想は独自性にしない. 既存の[確認範囲](evidence_commit_prior_scope_20261025.md)を引き継ぐ. 今回の再確認は同じ原典の時点と判定対象についてであり、新しい実装再現ではない.

P111の実行記録による推論表示の選別も、正常なAPI返却が将来の不要性を保証するわけではなく、全件の採用基準に届いていない. その条件を要約の採用判定へ移しただけで、問題が解決したとはしない.

## 比較を開始する前に必要なもの

1. P118を全件閉鎖し、専用要約の起動、採用、不採用、生成費用、後続費用を全４課題で確認する. 専用要約の負担が実際の改善対象になっているかを判断する.
2. 同じ応答に載せる通常方式と、追加の実行情報で採否を判断する方式を区別する. 単に呼出しを統合した効果を、判定規則の効果へ帰属させない.
3. 追加の判定が読む情報、判断時点、保持範囲、失敗時の扱いを実装可能な形で定める. 自然言語の意味を確認していない場合は、その範囲を明記する.
4. 共通の入力条件とtool schemaを持つ対照、全仕事の共有予算、有限な対象と順序、成功損失と全費用の判定を固定する. 追加出力でコードが切れる場合も失敗へ含める.

具体的な判定規則と通常対照との差が定まるまでは、新しいモデル比較を開始しない. この案を見送る場合も理由を残す. 原稿と未見12課題は保留する.
