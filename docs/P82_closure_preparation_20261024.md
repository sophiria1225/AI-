# P82の終了後集計と入力比較の準備

P81の実行中に、P82の全24条件を終了後に集計する処理を準備した。P82の最終JSON計画・モデル割当て・初期入力計数・実行は未開始。判断条件は[比較規則](experiments/P82_late_clock_comparison.md)に記載し、P81/P83の終了結果を確認してから最終計画へ結ぶ。

追加した処理は、所有推論器の停止と全時間の確認、全生成・全Python実行の費用分類、同じ条件の反復12対と同じ反復内の条件24対の照合、全24条件を載せる７枚の資料生成である。旧P80/P81の生成は新規比較の費用に混ぜない。成功・未達・未評価・不明使用量を保持する。

時間表示の補助照合では、現在の通知だけを正規化する。Lの切替規則を０秒へ再適用すると、元は非表示だった通知まで表示へ変わるため、実際の表示状態を維持して秒数だけを取り除く。別に、現在の通知を共通の非表示形へ置く照合も保存する。過去の履歴や別の予算欄は消さず、要求JSONの一致をモデルtoken列の一致や全費用の因果効果とはしない。

追加４検査、全1,160検査を2.573秒で通過。４つの新しいCLIの構文検査と資料CLIの読み込みを確認した。模擬24条件・36対を一時ディレクトリへ流した資料生成では、未知使用量１件と基準未達が残り、７枚・全件CSVになることを0.633秒で確認した。模擬値は実験結果へ保存していない。実結果のPDF生成・全頁目視確認は終了後に行う。

通信参照の表示前統一が保証するのは、対応を保つ参照改名に対する表示の一致という限定した性質である。[保証範囲](protocol_rendering_invariance_20261024.md)を明記した。新手法、品質維持、全仕事削減の成立とは扱わない。
