# 時間通知の結果を何の貢献として扱えるか

2026-10-24。P80とP81は時間通知という通常設定の比較である。新規の制御方式や、品質を保つ全仕事費用の削減は確立していない。P81は固定した全16追加条件を実行中で、途中の一致や成功を全体の結論へ広げない。

| 原典と読んだ範囲 | 既に扱われている点 | 今回の解釈 |
|---|---|---|
| [On the Clock v1](https://arxiv.org/html/2610.10833v1) §4.2、§5（前回確認） | 時間情報の提供と期限の強制、期限遵守と生産的な時間使用を分ける | 実期限を維持して通知の有無を変える構成自体を新手法にしない |
| [Timely Machine](https://aclanthology.org/2026.acl-long.211.pdf) §4.1–4.3、A.2.1–A.2.3、Limitations | 推論とツールの遅延を分け、時間を使った学習を行う。Timer Toolは倍率とjitterを含む | 時刻情報や計算機速度が判断へ影響し得るという一般論だけでは差にならない。学習方式の再現・比較は今回行っていない |
| [Numerical Sources of Nondeterminism](https://proceedings.neurips.cc/paper_files/paper/2025/file/f80094a824ba5912d4a2de169c404a40-Paper-Conference.pdf) 導入、§2.1–2.2 | seed固定だけでは数値計算・実行構成による出力変化を抑えきれない | seedが同じでも経路が違う、という観察自体を新発見にしない。通知入力の差と数値的な差を区別する |
| [ReproEvalCard](https://aclanthology.org/2026.acl-short.22.pdf) §3、§4、§5 | 多段LLM評価の出典・中間履歴・乱数制御などの報告を扱う | 記録・hash・資料の整備は妥当性を支える実務であり、それだけを中核貢献にしない |

現在の限定した問いは「必要な状態を残した逐次エージェントで、実期限を変えず、現在の残時間の見せ方を変えたとき、成否と失敗を含む全論理費用・実時間・経路の再現性がどう変わるか」である。P79の保存入力に対する１秒の局所介入、P80の全課題比較、P81の同一seed反復を区別する。

P80では全体の削減基準は未達であり、[補助的な費用下限](P80_usage_lower_bound_20261024.md)でも非表示Hの全体費用は表示Mを上回る。写真・精算・返金だけを選んで改善を主張しない。時間通知を消せばよい、という設計推奨も現時点では支持できない。

P81終了後は、全８条件それぞれの３回について、入力が先に違ったか、同じ要求で出力が違ったか、成否と費用が一致したかを示す。現在の残時間だけをそろえた事後hashが一致しても、実際に同じモデル入力を与えた証明や因果効果の同定にはしない。非表示側が安定しても時間表示側の変動原因をすべて特定したことにはならず、両側が変動すれば非表示による再現性改善も主張しない。

この組合せが限定的な実証レターの中心になり得るかを検討する。現状は同じモデル・既知４課題であり、一般化・安定した平均削減・採録に足る独自性には不足が残る。検索で同じ文言が見つからなかったことを未研究の証拠にしない。単なる閾値通知や時間の段階表示へ改名しても、独自の観測・判断・更新規則ができたことにはならない。最終目標は必要な情報・処理と品質を保った全仕事費用の削減である。
