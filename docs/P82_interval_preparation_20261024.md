# P82の条件付き費用区間：終了後解析の準備

P82の途中14条件が完了し、終端使用量が不明な２生成を確認した後に準備した**事後解析**である。全24条件の監査・所有推論器停止までは実ログへ適用しない。現在は合成入力による検査だけで、実結果の区間はない。

目的は、不明使用量を残した全仕事の論理token費用について、保存記録からどこまで言えるかを調べること。採用基準の変更や終端使用量の復元には使わない。実行中の閾値・順序・予算も変えない。

## 計算と範囲

[P80/P81で固定した計算](P81_usage_intervals_20261024.md)を再利用する。全呼出しを単一スロットの保存ログと順番で対応させ、既知の全呼出しで入力処理数・出力数・事前入力数を照合する。不明呼出しは、取消しと正の生成進捗があり、固定した推論器ソースと出力上限を確認できる場合だけ扱う。

- 下限は事前入力数＋観測済み生成進捗、上限は事前入力数＋要求出力上限。
- 既知呼出しは終端の入力＋出力数を点区間として保持する。
- 全24条件を残し、L対M、L対Hを各反復および合計で計算する。差の区間は`[L下限−対照上限, L上限−対照下限]`。
- 成功同士、失敗同士、成否不一致を併記する。失敗費用を捨てず、２反復を８独立課題と数えない。

この対応は既知レシートで裏付ける順序照合であり、暗号学的な要求IDの結合ではない。全ログの完全性、外部生成なし、同じ入力を事前計数したこと、固定版の生成数・上限の意味を前提とする。条件付き区間は信頼区間ではなく、計算量・請求額・経過時間でもない。どれかの照合が不成立なら結果を作らず、欠測を０で補完しない。

## 元の判断を保持する

全24行の成否と元の既知費用・不明数は監査結果と一致させる。元の４採否比較を再計算して一致を要求し、そのまま出力へ含める。仮に補助区間全体が負でも、使用量既知を要求する元の採用基準を通過したとはしない。P84自動接続の全使用量既知条件も変更しない。

新規方式の提案や効果の実証ではなく、既に観測した欠測に対する感度確認である。[実装](../scripts/inspect_late_clock_usage_intervals.py)、[検査](../tests/test_late_clock_usage_intervals.py)、[準備資料](../materials/20261024_p82_interval_preparation/README.md)。

## 終了後の実行

全件監査済みの`P82_comparison.json`と`P82_server_session.json`を、この解析版の`reports/`へ同一hashで保存してから実行する。`--storage-root`は既存の私有記録、`--backend-source-root`は固定commitのソース置場を指定する。

```sh
python scripts/inspect_late_clock_usage_intervals.py \
  --storage-root /path/to/storage \
  --backend-source-root /path/to/llama.cpp-620d2225cc436ab0b001e3200e590e3b286ef9ab
```

出力先は`reports/P82_usage_intervals_20261024.json`。既存結果は上書きしない。モデル生成・入力計数・環境API・評価器の追加呼出しは行わない。原ログ・要求内容・推論文を公開しない。
