# P81の終了後集計の準備

2026-10-24。P81は実行中で、全件の結果はまだない。終了後に全24行と全24対を取り込む資料作成器、追加16条件の推論器滞在の確認、全追加生成の公開計数集計を用意した。今回この集計器からの実験生成・API・評価・PDF作成は０。既存の固定workerと反復の実行順・上限は変更しない。

## 終了後の順序

1. 実行木 `p81-run` のpipelineとbatchの終了、および所有推論器の停止を確認する。
2. 同じ固定実行木で `audit_budget_visibility_repetition.py` を実行し、全16新条件と元の８条件の監査を保存する。途中結果で全件監査を作らない。
3. 同じ実行木で `compare_budget_visibility_repetitions.py` を実行し、全24対の要求・公開出力・opaque messageのhash比較を保存する。意味的な推論解析は行わない。
4. 完成した２報告を編集木へコピーする。編集木の [推論器集計](../scripts/inspect_budget_visibility_repeat_session.py)で、新しい16条件だけのサーバー・評価・後片付け時間を保存する。過去のP80の時間を二重計上しない。
5. [公開計数集計](../scripts/profile_budget_visibility_repeat_calls.py)で全追加生成・API・例外・実行状態を確認する。API０回の生成を不要とは判定しない。
6. [全件の資料作成器](../scripts/build_budget_visibility_repetition_report.py)で全24行、８条件の３反復、全24対の比較をCSVと資料へ出す。実データでの描画確認は終了後に行い、全ページのはみ出し・可読性・未知費用表現を確認する。

実行木には集計準備用の新しいscriptを追加しない。全件監査が検証する固定source一覧は、実際の実行開始時のまま保つ。追加の集計は編集木で行う。

資料は７枚を予定し、元のP80、P81反復２、反復３の全８行を別々の表にする。使用量不明は既知費用の三角印で示す。各条件３対は同じ３実行を共有し、独立した24標本ではない。判定不能な一致を不一致０件へ置き換えない。P80の補助下限は終端使用量を補修するものではなく、元表へ上書きしない。

実行中の同じホストで編集、読取解析、軽量検査も進めている。ホスト負荷を排他的に固定した実験ではなく、モデルseedと初期状態の一致から計算機の実行状態まで同一とは推定しない。実際の時間差や未知費用も保存する。

初期確認は３CLIの読込みと構文検査までである。実記録による最終集計・描画・目視確認は未実施。この準備や資料枚数を、新手法・品質維持・費用改善の成立として数えない。
