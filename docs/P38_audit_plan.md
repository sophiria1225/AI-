# P38終了後の追加監査

実行中のコード・条件は固定したまま、別の解析作業木で監査器を準備する。全３方式が終了するまで実データの監査を開始しない。

再利用した要求について、元の要求列を別の模擬環境で再現し、当該時点でAPIを実際に呼んだ結果と照合する。通常の実送信は全返却を比較し、明示項目の再利用はその項目、原API全体の再利用は全体を比較する。エラーや完了状態の差を一致にしない。発見済みAPIと最終保存DBの一致も確認する。

不一致があれば、その条件は最初の不一致で止めて記録し、残りの条件も試す。合った条件だけを結果に残さない。未知の操作結果や復元不能な状態を、キャッシュの正しさを確認した条件へ含めない。

この監査は追加の環境APIを使うため、回数・時間は実行時の費用と分けて記録する。監査用の返却を元のモデルへ渡さず、最終成果物を選び直さない。独立評価器や正解情報は呼ばない。モデル・追加生成・未閲覧課題の使用も０。

同じ要求列での事後一致は、モデルの将来の選択や一般的な正しさを保証しない。状態版の前提が実行した記録で破れていないかを見る補助検査として扱う。監査なしに、単体検査の合格を実際の再利用の正しさへ広げないために行う。
