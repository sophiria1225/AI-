# P102の終了記録監査と全枠資料を準備

P101の途中生成を読まず、P102の終了後に一度だけ使う監査と資料生成を準備した. 実環境でのP102は未実行である.

監査は全36枠と元生成の対応、全12条件内36対と全66条件組594対、全API試行とPython実行の合計を照合する. 保存されたbridgeの送信開始と型付き返却、Pythonの実行結果、先行プログラムの元入力と結果hash、後続のAPI要求列と実行証拠hashも確認する. 既知の途中停止に使った費用を除かず、元出力不明と実行未着手を区別する. 所有bridge PIDの不在とPythonコンテナの終了記録を照合する. コンテナの現在状態の再検査や、元の全DB状態の同一性を独立に保証する監査ではない.

監査は180秒、各保存ファイル16 MiB以内で、追加生成・環境API・Python再実行・課題評価を行わない. 不整合時も終了監査の記録を保存し、自動再試行や実験の補充はしない. 監査が通らなければ結果資料の通常生成を拒否する.

資料には全36枠、全12条件、条件内の全12比較組、条件間の全66比較組と費用をCSV/JSONへ保存する. ８ページの資料で、静的形式、Python実行、非空API列、双方空のAPI列、未知出力・未実行を分ける. 生成費用と実行再構成費用を分け、重複する時間を加算しない. 課題の最終品質、新手法、全仕事の削減を成立済みとは扱わない.

追加12検査・全1,644検査が成功した. 合成fixtureの８ページを描画し、全ページを目視確認、レイアウトエラー０. 合成値は実験結果として公開しない. 既に閉じたP94の１枠を読み、保存形式と新しい記録照合処理の適合も確認した. この確認ではAPI・モデル・コードを再実行していない. P101の途中出力・使用量は未閲覧.

次はP101の閉鎖監査と全結果の確認を待ち、既知の原応答すべてをP102最終計画へ結びつける. 固定実行headの両CIを確認してから、事前設計の順序・上限内で一度だけ実行する. [実行準備](P102_execution_runtime_preparation_20261024.md)と[生成前に固定した設計](experiments/P102_choice_action_execution.md)は変更しない.
