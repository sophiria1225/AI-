# P80と時間通知の近接研究

P80の条件固定・開始後に確認した資料。進行中の条件・予算・対象は変更しない。

[Wangほか, On the Clock, v1](https://arxiv.org/html/2610.10833v1)の要旨、§4.2、§5を確認した。時間通知と実行期限の強制を分け、残時間・生成時間の通知、コマンド時間の短縮／拒否を比較している。時間内に停止できることと、追加時間を品質へ変えられることも区別する。したがって、通知と強制の分離そのものを当研究の新規性とはしない。こちらでの再現、正式採録、全実装は未確認。

P80で調べるのは、同じ実期限と通常例外処理の下で、現在の残時間を表示するかどうかが既知４課題の成否・全費用へどう現れるかである。P79の局所的な１秒差は通知を消すと品質が保たれる証明ではなく、P80の結果も未確定。別のモデル・環境への移植だけで中心的な新規性が成立するとは判断しない。

処理一括化については[TraceCompiler v1](https://arxiv.org/html/2608.02680v1)の§2、§3.2–3.5、[Agent JIT Compilation v1](https://arxiv.org/html/2605.21470v1)の§3.1–3.3も確認した。前者は複数軌跡から依存・引数の出自を検証し、曖昧な場合の委譲を含む。後者は事前・事後条件による計画検査と費用選択を含む。一般的なバッチ化、再利用、費用に応じた選択だけで独自性を主張しない。単一実行内の具体的な観測・更新規則との機能差、構築費込みの便益が残るかは未判定である。

上記は候補をすべて否定する結論ではない。新しい主規則を選ぶ際に、既存方式が何を前提としており、その前提をどの公開観測で置き換えるかまで固定する。[土日の判断](weekend_decision_20261023.md)。
