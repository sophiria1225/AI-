# API一覧と引数詳細の保持：近接研究とP55の位置

P55の条件を固定した後、生成実行と並行して原典を追加確認した。実行中の結果に合わせて条件・閾値・予算を変更しない。主目的は、通常の段階的開示を新手法として説明することを防ぎ、今回確かめる問いを狭く記すこと。

| 原典・実際に読んだ範囲 | 既存の内容 | P55で残る限定的な問い |
|---|---|---|
| [Anthropic, Introducing advanced tool use](https://www.anthropic.com/research/advanced-tool-use)、2025-11-24、Tool Search Tool節 | 初期表示を抑え、検索で該当ツールの定義を展開する。検索による追加時間と入力削減の釣合いも説明する。 | P55は検索製品の再現ではなく、一度読んだ一覧／詳細の履歴表示を共通境界で変える。Python・APIスキーマ・アーカイブを保持した継続での差を調べる。 |

長文QA研究は上記の方法節までを確認した。表にない実験の全数値、コード、査読採録の有無、追試を確認したという意味ではない。公式ツール記事の効果量も、現在のモデル・AppWorld課題へ移せない。

## P55で実際に変わるもの

Fは元表示、Dは古い詳細のうち出自が完全に照合できた部分を省略し一覧を保持、BはDと同じ詳細に加えて一覧を省略する。省略印とメタデータは共通。会話中の過去の操作コード、公開の `api_schemas`、Python変数、保存原文への参照経路は全条件で残る。[固定計画](experiments/P55_inventory_comparison.md)。

[全４境界の文字列点検](../reports/P55_initial_inventory_visibility.json)では、写真の一覧にある26 API名のうちBでも８名、電気代でも10名が入力中に残った。書出の３一覧も各９／91、２／26、６／６名が残る。返金は追加で省ける一覧がなくD/Bの基礎入力は同じだった。名前の文字列一致は意味理解・APIの発見可能性・正しい使用の証明ではなく、別アプリの同名APIによる偶然の一致もあり得る。生成・計数・API・評価器の追加呼出しは０。

したがって、今回の介入を「APIを完全に忘れさせる」「ツールが存在しない状態にする」と説明しない。記憶が実行環境に存在することと、それが会話に表示されていることを分ける比較である。後続行動が変わっても、モデルの内面状態や単一原因をこの比較だけで特定したとはしない。

## 投稿の主張への条件

採録の中心にするには、既存の索引／段階的開示の一般論を超えて、限定した条件での追加価値と失敗条件を示す必要がある。P55が良い結果になっても、通常の一覧保持を独自アルゴリズムと呼ばない。既知４課題各１回の結果は開発上の判断であり、未調整群での検証や生成変動の検討を済ませたことにはしない。[現状の率直な評価](letter_assessment_20261023.md)。
