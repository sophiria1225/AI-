# 要約の出典確認と型別保持を新規性へ読み替えない

2026年10月25日. P118の固定８条件が実行中に、公開原典だけを追加確認した. 途中の成否、要約本文、課題の正解は読んでいない. [版・取得指紋・確認範囲](../reports/checkpoint_source_and_type_prior_scope_20261025.json)を保存する. 著者の実装再現と正式採録は今回確認していない.

## 確認した方式

[Source-Judged Compaction (SJC), v1](https://arxiv.org/html/2610.20927v1#S4)は、通常の生成要約を項目に分け、関連する環境出力を検索し、出典の確率を返す判定モデルで項目を選別する. 過去に採用した要約も出典に含め、元の課題指示は文脈として渡す. 残す項目は書き換えない. 付録Fでは、長すぎる要求を分割する例外と、判定が得られない項目を残す処理がある. 費用図は実行役＋要約役のtokenで、判定役の要求と料金は別表で報告される. これを全役割の論理token総量と読み替えない. 出典があることと内容が正しいことも別である. [費用](https://arxiv.org/html/2610.20927v1#S5.SS3)／[実装](https://arxiv.org/html/2610.20927v1#A6).

[Knowledge Triage / TypeCompact, v1](https://arxiv.org/html/2608.22752v1#S3)は、項目を型で分け、制約・手順を強く保持し、他の種類へ異なる圧縮方針を適用する. 判定は前段で行い、保持対象が予算を超える場合の処理も定める. 正規化した制約の検査は意味保存の万能証明ではなく、分類の見逃しや限定条件の脱落が残る. 型付け、強制保持、曖昧な項目を保守的に扱う一般構想を独自性へ数えない. [方式](https://arxiv.org/html/2608.22752v1#S3.SS3)／[検査と行動評価の限界](https://arxiv.org/html/2608.22752v1#S4.SS5).

[SelfCompact, v2](https://arxiv.org/html/2606.23525v2#S3)は、既にv1を[確認済み](memory_cost_review_20261021.md). 今回は§3を再確認した. 同じモデルで定期的に圧縮の可否を判断し、必要時だけ要約する. 判定・要約指示を履歴末尾へ追加してKV再利用を狙う. 適応時点、作業の区切り、追加役の費用を扱うこと自体は新規性ではない.

## 現在の実装との関係

| 比較項目 | P118の固定実装 | 新規性へ使えない一般形 |
|---|---|---|
| 判断時点 | 入力16,384 native token以上で一度だけ検討 | 適応的に圧縮する、作業の区切りで要約する |
| 要約検査 | 四つの欄、文字数、完了理由、操作要求なし、次入力が短いこと | 構造化する、型ごとに残す、形式を確認する |
| 内容の根拠 | 要約本文の意味は検証しない. 誤り得る通常要約として渡す | 環境出力へ照合する、出典のある項目を残す |
| 保持状態 | 元指示、直近２ターン、Python状態と完全保存履歴 | 値をモデル外に残す、一覧や参照で再アクセスする |
| 費用 | 要約と実行役の共有枠. 不採用・失敗・未知も残す | 制御費用や回復費用を含めて測る |

P118は上記原方式の完全再現ではない. 同じM3を使う通常要約に現在のハーネスを接続した開発比較であり、SJCの判定モデルやSelfCompactの適応判断を追加していない. この調査を理由に実行中の条件を変えない.

次の候補が実行記録に基づく保持判断なら、何を観測したか、その情報から何を保証できるか、省略する処理、失敗時の戻し方、通常対照と同じ予算での効果を分けて示す必要がある. APIが正常に返った記録から、課題全体の完了や古い推論の不要性は導けない. 出典判定をホストの規則へ変えただけでも、対象の制約と新しい便益がなければ独自貢献とは判断しない.

P111の採用基準未達と元の未知使用量２は変更しない. 原稿と未見12課題は保留する. 新規性、一般的品質維持、採録見込みの改善を確定した報告ではない.
