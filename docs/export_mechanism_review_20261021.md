## P18から言えることと、まだ言えないこと

P18では、情報を取得していない場合とは区別できる、取得後の１件欠落を観測した。しかし、コードで出力すれば解消する現象か、専用の検証や状態管理が必要かはまだ分からない。P20は、この順番を守るための比較である。

P20で使う分析側の集合照合は、人が課題を読んで定義した。これを実行器へ移しただけでは、未知の要求から正しい仕様を自律生成したことにならない。形式が通るコード、コードが生成仕様を満たすこと、生成仕様が本来の要求を満たすこと、実環境の仕事が完了することは別に確かめる必要がある。

## 次の方式を提案するために必要な追加証拠

まず通常計算の比較結果を閉じる。その後に検討する方式は、次の４点を１つの主張に結び付ける。

1. 強い単純対照でも残る具体的な失敗がある。
2. 実行中に観測できる情報から、追加機構の対象を選べる。
3. 追加の情報や正解を与えず、同じ途中状態と総予算で効果を比べられる。
4. 機構を決めた開発事例以外でも、成功と悪影響を測れる。

この条件は採録を保証するものではない。機能名や「検証＋記憶＋実行」という組合せを先に新規性と呼ぶことを避け、近い既存方式との具体的な差を実測するための基準である。２段組４ページの原稿でも、主張が未確定の状態を文章量で補わない。


## 追加照合：未実施事項と履歴依存の照合

[ObligationBench / ObligationGuard](https://arxiv.org/html/2610.11773v1)は、安全上必要なのに未実施の事項を特定する研究である。今回は要旨、2.3節、3.1節を確認した。正例だけでなく未実施事項のない負例も対にする設計を含む。「禁止操作の検出から、やるべきことの未完了へ着目を移す」という一般構想も独自性とはしない。安全上の義務を対象とするため、CSV行の完全性を直接評価した研究だとは扱わない。著者公開版の確認で、正式採録・モデル性能の再現は未確認。

[Formal Runtime Verification for Tool-Using LLM Agents](https://arxiv.org/html/2610.09793v1)の要旨、3.1〜3.2節、4.1節冒頭では、履歴を型付きイベントへ変換し、過去の前提と操作との対応を時相論理で検査している。実行中にモデルを再稼働する研究ではなく、保存軌跡の検出率を実際の阻止後の成功率と区別する。同様に、今回の公開観測照合で欠落を検出できても、追加監視を入れた全体実行が改善した証拠にはならない。著者原稿にはCPSIoTSec 2026ワークショップの書誌があるが、出版社の正式記録は別途確認が必要。

両原典も取得ハッシュと確認範囲を上記の出典記録へ追加した。関連分野の存在だけで具体的機構の余地を否定せず、具体的な状態・更新規則・比較上の差を問う。


## 最も直接的な既知機能：完了時の証拠と計算の照合

以前のR18で確認した[Evidence-Carrying Termination（ECT）](https://arxiv.org/html/2608.23623v1)の方式節と信頼境界を再確認した。必要な回答項目、許可した変換、対象・時刻の範囲、必要な証拠数を、信頼する要求契約へ定義する。提案された完了証明と観測の記録を対応付け、閉じた変換言語で値を再計算する。集合の和や集計も含むため、「元データとCSVを決定的に照合して完了を制御する」だけでは機能的に重なる。

明記された前提は、要求契約が意図を適切に表していることと、アダプターが証拠を正しく記録すること。実行中のエージェントがこの契約を自動作成する方式ではない。ただし、この前提を指摘しただけでも新技術にはならない。VeriGuard等の仕様生成・検証方式も含めて、どの入力からどんな契約を得て、その誤りをどう区別するかという具体的機構が必要になる。今回その機構の新規性や有効性はまだ示していない。

P20は「普通のコードで書き出せばよいか」を先に確認する。ECTに相当する人手定義の完全な契約をこちらだけへ与える比較は採らない。原典の人工課題・限定された変換言語という範囲と、今回の実行環境の範囲も区別する。採録先確認・公開成果物の性能再現は未了。

## 補助検査の位置づけ：入力を変えて出力関係を確かめる

[ARMetaの著者原稿](https://arxiv.org/html/2605.28321v1)の要旨とIII-A〜B節を確認した。OpenAPIから入力変換と出力関係を作り、仕様との整合確認、実行可能な検査への変換、反復実行を行う。関係の違反と、そこへ到達する前の実行失敗を区別している。著者申告のCOMPSAC 2026採録は、出版社の記録を別途確認した状態ではない。

P21の補助検査も既存のメタモルフィックテストの考え方を使う。ただし、４関係は分析者が課題に合わせて手で定義し、LLMによる自動導出や生成物の修復は行わない。新しい研究機構の比較へ進む前に、通常計算という対照を正しく評価するための検査である。全生成終了前に条件を固定し、主評価の成績と分ける。[補助評価仕様](experiments/P21_supplementary_robustness.md)。
