## 判定と保存

API順序は `api_docs.show_api_doc`、`phone.login`、`api_docs.show_app_descriptions`。返却区分は `returned`、`raised`、`returned`。１件目のPython実行エラーは意図したAPI例外であり、２件目は正常終了を要求する。呼出し前の状態保持、送信数・記録数・返却区分の対応、完了や不明の混入がないことを点検する。

完全な返却、エラー文、初期公開状態、生成した無効入力はローカルのprivate記録へ保存する。公開レポートには型・件数・時間・hash・終了確認を出し、資格情報や応答本文を含めない。DB内容、保存済みモデルコード、モデルの非公開推論、保留12課題、個別評価項目は読まない。実行環境が課題DBを通常利用することと、研究者がその内容を調べることを区別する。

P76の認証失敗を直して元の成功率を変更する検査ではない。接続確認後も、実タスクでの品質・総費用改善は未測定のまま。次のモデル比較は、両対照へ同じ通常部品を与えたうえで残る具体的な制御差と反証条件を先に示す。
