# 型を区別するAPI返却を通常の実行系へ接続する

2026年10月23日。[返却契約の部品](public_api_result_contract_20261023.md)を、元のAPI許可・予算・記録・持続Pythonへ任意で接続する準備。新規方式やタスク性能の実験ではない。既存のbridge・worker・過去結果は変更しない。実タスクへ使う場合は、その比較の全対照に同じ契約を与え、追加の制御を別に評価する。

## 接続

`appworld_typed_bridge.py`は独立した起動先で、公開API名とJSON引数から呼出しコードをホスト側で作る。任意のモデルコードや評価器操作は受け付けない。タスクを初期化する場合もground truthを読み込まず、AppWorldの実行制限を維持する。旧bridgeへ自動で戻る機能は持たない。

`public_api_result_transport.py`の`TypedBridgeProcess`と`PublicResultTransport`を通常の`ApiChannel`へ渡し、`PublicResultProgram(session.run)`を元のコードツールへ渡す。返却文字列が`"null"`や`"1"`であっても文字列のまま扱う。元のAPI許可、残予算、完了判定、記録時点を使い、各送信に返却区分・nonce・hashを添える。

- 捕捉できた呼出し例外はAPIエラーとしてPythonへ返す。自動再試行や作用の取消しはしない。例外前の変数・作用はそのまま残り得る。
- 不完全・不正・異なる呼出しの返却は作用不明として停止し、同じtransportを別のPython実行へ渡しても送信を再開しない。元の持続Pythonも不明結果では閉じる。
- 完了を報告した後のAPI送信も、別プログラムを含めて止める。呼出し例外と完了が同時に報告された場合も完了状態を落とさない。
- 新しいプロセス通信は読書きに同じ期限を置き、途中の１行が届いてから停止した場合も待ち続けない。重複keyや大きすぎる返却を拒否する。停止時は所有する子プロセスだけを終了する。

この契約で業務失敗を含む正常辞書はそのまま返る。例外の通知は、タスク未達の原因が直ったことや、外部作用がなかったことを意味しない。現行のモデル実験workerへはまだ配線していない。

## 固定する合成接続検査

[preflight_public_api_result_transport.py](../scripts/preflight_public_api_result_transport.py)を、全検査と固定HEADのpush/PR両CI合格後に１回だけ実行する。３コンテナ・８プログラム、作業120秒、各プログラム最大15秒。実行器の起動・停止には既存の有限timeoutがあり、その時間も全wallへ記録する。期待するfixture送信は６回。出力が既にあれば再実行を拒否し、失敗も保存する。

| セッション | プログラム数 | 確認すること | fixture送信予定 |
|---|---:|---|---:|
| 通常 | 6 | 値の型、例外前の変数保持、業務失敗辞書、予算０、引数拒否、完了後の抑止 | 4 |
| 不明返却 | 1 | API後に余分なstdoutを混入。Pythonが例外を捕捉しても次APIを送らず、セッションを閉じる | 1 |
| 完了と例外 | 1 | fixtureが完了状態を立てて例外を出しても、後続APIを送らない | 1 |

元の`execute_response`と`PersistentApiPython`を通す。ホストで動かすのは、このスクリプトが作った公開fixture呼出しだけで、保存したモデルコードは実行しない。各返却の生成にはインストール済みSafetyGuardを適用する。全14コンテナ制約と全３コンテナの除去を確認する。

モデル生成・AppWorldタスク・実API・評価・DB内容・保留12課題の読取は全て０。これは接続の検査であり、元課題の成否を付け替えず、実LLMの品質・総費用改善には数えない。合成検査の結果はこの固定計画の後に追記する。現時点では正式な８プログラムの接続検査は未実施。
