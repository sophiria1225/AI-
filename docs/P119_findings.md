# P119: 任意の同時出力では要約が生成されず、成功維持の基準も未達

2026年10月25日. 既知４課題×２方式の全８条件を終了した. 別呼出し要約は4/4、任意の同時出力は3/4成功で、後者のCSVはAPI上限で未達だった. 同時出力の要約機会は２回あり、いずれも任意の`checkpoint`引数がなく、履歴の要約置換は一度も起きていない. この結果から、同時出力による圧縮の有効性や品質を維持した削減を主張しない. 事前の採用基準は未達である.

## 要約の要求と実際の採用を分ける

| 課題 | 別呼出し要約 | 任意の同時出力 |
|---|---|---|
| 写真 | 実行役14回後に要約し、採用 | 実行役15回目に要求したが、checkpointなし |
| 精算 | 起動条件に達せず | 起動条件に達せず |
| 返金 | 起動条件に達せず | 起動条件に達せず |
| CSV | 実行役12回後に要約し、採用 | 実行役13回目に要求したが、checkpointなし |

任意の同時出力で要求した２応答は、どちらも通常の`run_python`で、終了理由は`tool_calls`、形式上の状態は`checkpoint_absent_keep_original`だった. 当該要求のinput/outputは写真16,928/190、CSV18,199/1,379 token. 4,096出力tokenへの到達や要約の形式不正による棄却ではなく、任意欄そのものがない. 要約のための再試行はせず、元の履歴を残した. 私有の推論や課題データを公開せず、監査済みの形式記録で確認した.

従って「要約を入れたが品質が下がった」という結果ではない. 今回の任意出力による要求が、２機会とも要約を発生させなかったことと、その方式全体でCSVの成功を失ったことが観測された. ２機会の結果を、同時生成が一般に不可能という結論へも広げない.

別呼出し要約では、写真の次入力が16,425から8,708へ、CSVが17,696から7,143へ短くなり、両方採用された. 要約生成費用は写真18,455、CSV21,419、計39,874 token. 同時出力側には採用された要約や短縮後入力の測定値がなく、その欄は`null`のまま残す. 精算と返金は両方式とも要約を使っていないため、２件の成功を圧縮の成果としない.

## 写真の減少にも、要約による圧縮は起きていない

写真の別呼出し方式は実行役121,416＋要約役18,455＝139,871 token. 同時出力方式は全て実行役の136,201 tokenだった. 費用の分解は次のとおりである.

```text
同時出力 − 別呼出しの全仕事token
  = 実行役の増減 − 別呼出し要約の費用
  = 14,785 − 18,455
  = −3,670 token
```

写真では約2.62%少ないが、同時出力側の履歴は短縮されていない. 「要約生成の費用を省いた額」と「最終的な差」も一致しない. CSVは実行役の差−91,348と要約役21,419の差で−112,767だが、成功と未達の比較であり、必要な仕事を終えた費用同士ではない.

## 入力条件と解釈の範囲

最初の介入より前の完全要求ファイルは、写真14位置とCSV12位置で全て一致した. 介入のなかった精算24位置と返金13位置も全て一致した. 計63位置の一致は、初期入力や介入前の要求の照合であり、介入後の行動の不変や因果効果を保証しない. [全４対の集計](../reports/P119_pair_controls.json).

要約の時点、追加指示、schema、出力配分、後続行動が方式間で異なり得る. 欄が出力されなかった今回も、追加指示とschemaはモデルへ渡っている. 同時出力側を「無介入の全保持」と呼び替えない. ４課題は既知の開発課題で、各条件１回. 今回の別呼出し方式の結果で、過去の不明使用量を補完したり、未見課題への品質保証を主張したりしない.

## 次の判断

任意の同時出力は採用しない. 次は、要約欄を`run_python`の必須引数として指定する通常対照を、新しい有限計画で比較する. 生成を要求することと、実際に生成・採用されることを区別し、欠落、打切り、不正、追加出力、行動の変化も費用と失敗へ含める. 現在の結果を上書きせず、失敗したCSVだけの再試行もしない.

同時出力、型検査、記憶の実行、原履歴への参照は既存研究との重複がある. 必須欄を加える変更自体も新規性とはしない. 独自の保持判断や品質維持は未確立である. [原典との照合範囲](inline_memory_prior_scope_20261025.md).
