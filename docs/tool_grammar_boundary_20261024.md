# 文法制約と有限出力の境界を終了済み記録で調べる

2026-10-24。固定backendのソースを読むと、MiniMax-M3ではtoolsとauto指定からツール呼出し用の遅延文法を構成する。引数不正が観測されたことだけを理由に「文法制約なしの基準」とは扱えない。これは通常機能の確認であり、新しい手法の提案ではない。

## 読取前に固定した範囲

P80/P81の既存全24条件・429生成と、P83で保存済みの全６入力のsession controlsを対象にする。既存の監査hashに照合し、P82の途中結果や保留課題は読まない。実験後の診断であり、事前登録とはしない。

全429要求・応答から、tools/auto指定の有無、出力上限、終端理由、引数のJSON構文とobject型の可否だけを集計する。使用量不明は観測不能のまま残す。引数・通常文・返却推論を公開せず、推論の意味を読まない。文章化対象は元のNativeConversationと同じ判定にするが、履歴を書き換えたり呼出しを実行したりしない。

P83は保存済みファイルのhashと公開controls hashを検査し、文法の非空、遅延指定、format、trigger数だけを取り出す。追加のレンダリング、語彙ロード、計数、モデル生成は０とする。固定ソースは保存済みtar.gzのhashとファイル内容へ照合し、推論器を変更しない。

終了理由lengthと不正引数の共起を示しても、全てのトークンでの文法適用、途中切れを防ぐことの品質改善、全未達の原因は証明しない。有限出力枠を増やす、呼出しを修復する、tool_choiceをrequiredにする等の別条件へ、この診断から自動的に切り替えない。

結果は別の[全件資料](../materials/20261024_tool_grammar_boundary/README.md)へ記録する。元の実験・監査・P82/P84計画は保持する。
