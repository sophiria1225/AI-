# 通常のPython計算を比較対象にするための準備

2026年10月21日。P21の生成中に行った基盤確認であり、P21の提出内容は見ていない。モデル呼出し０、課題環境への要求０。主評価の制限付き言語やプロンプトは変更していない。

P20・P21では、データ変換用の限定したPython構文を自作の解釈器で実行する。この制限が失敗の原因なら、通常計算の有効性を否定できない。より広いPython構文と標準ライブラリを利用できる比較環境を別途準備した。これはCodeActの完全再現や提案方式ではない。

## 選定と実測

以前のmacOS `sandbox-exec` によるPython実行は終了コード134で失敗した。そのため限定解釈器を使ったが、既存のコンテナ環境まで利用不能と確認したわけではなかった。今回、研究用Colimaと専用Dockerクライアントが既にあることを確認した。通常のPATHで見つからないことを、不在とは扱わない。

Docker公式Pythonイメージの3.12.15-slim-bookworm、linux/arm64を選び、可変タグではなくプラットフォームmanifestのdigestを固定した。圧縮レイヤ合計44,921,692バイト。取得は4.45秒で終了。既存のSWE-benchイメージはリポジトリや検査データを含み得るため使わない。別VMや巨大な追加環境も不要だった。[公式イメージ](https://hub.docker.com/_/python)、[Docker実行設定](https://docs.docker.com/engine/containers/run/)。

ホストをマウントせず、ネットワークなし、読取専用root、非root、権限除去、256MiB・1CPU・64プロセスの上限で実行する。入力はJSONの標準入力だけとし、CSV整形補助は行の選択を行わない。生成コードは標準Pythonで処理する。実行前にコンテナ設定を照合し、終了時に自分で作成したコンテナだけを除去する。コンテナを使っただけで完全な隔離を証明したとはしない。

| 実確認 | 結果 |
|---|---|
| import、集合化、整列、CSV生成 | 期待する文字列と一致、Python 3.12.15 |
| rootへの書込み、ホストの研究ファイル参照、外向き接続 | 試した３操作は利用不可 |
| 無限ループ | ２秒で期限処理、所有コンテナを除去 |
| 大量標準出力 | 2MiBの記録上限で実行エラー、所有コンテナを除去 |
| 既知の例外 | 実行エラーとして保存、成功へ変換しない |

最初の事前検査はDockerが返す `no-new-privileges=true` の表記を受け付けず、コード実行前に拒否した。真の設定表記を追加し、`false` は拒否する単体検査を加えた。失敗記録は保持した。また、期限時にまだ動作しているコンテナの終了コードは未確定なので、Dockerの暫定0を記録せずnullにした。旧記録も保持した。全372単体検査合格。

## 今後の利用条件

P21の全生成と固定した主・補助評価を先に終える。通常Pythonで再検査する場合も補足結果として分離し、元の制限による失敗を消さない。標準Python向けに指示を変更して生成し直す場合は、別の実験として入力・予算・比較条件を先に固定する。成功例だけを選んで通常Pythonへ渡さない。

この準備は、通常の計算を弱い比較対象にしないためのもの。プログラム実行、隔離、型・形式検査自体を研究の新規性には数えない。OOM挙動、任意パッケージ、一般ファイル操作、環境API操作は今回検証していない。
