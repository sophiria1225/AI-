# P2の検証記録

2026年10月20日。移管・計測基盤の確認後、MiniMax M3の実機測定を開始した。

| 検証 | 結果 | 解釈 |

公開検査では最初にイメージのHEAD不一致で停止した。調査で課題元コミットとGit treeが一致することを確認し、内容の一致を検査するよう修正した。詳細は[判断D027](decision_log.md#d027-評価イメージの準備コミットとソース内容を区別する)。失敗した初回検査も`records/p2_public_baselines/`へ保持した。

モデル接続では、サーバーの`/v1/chat/completions/input_tokens`で整形後の入力を数え、生成後の実使用量との一致を検査する。推論テキストを履歴から勝手に削除せず、生成上限で途切れた応答のツール操作は実行しない。実モデルでの往復校正を終えるまでは、接続成功としない。

初回の往復校正は`thinking_mode=enabled`、temperature 1.0、top_p 0.95で合格した。短文生成3呼び出しのサーバー計測値は約17.1〜17.9 tokens/sで、長いコード出力や長文入力の速度を保証しない。8Kロード後の観測RSSは約192.3GiB、system swapは0。RSSとMetalの総割当量は同一ではなく、容量判断には後続の長文実測も使う。初回ロードには直前のダウンロード・照合によるファイルキャッシュの影響もあり得る。

原記録は`records/p2_probes/20261020_111428_enabled/`と`records/p2_servers/20261020_111402/`。この後、6Kから入力を段階的に増やし、容量を確認してから実課題の設定を固定する。

| 入力枠 | 実際の入力 | 処理時間 | 抽出結果・計数 | 観測swap |
|---|---:|---:|---|---:|
| 8,192 | 5,993 tokens | 49.19秒 | ともに一致 | 0 |
| 16,384 | 14,000 tokens | 123.53秒 | ともに一致 | 0 |
| 32,768 | 27,975 tokens | 266.15秒 | ともに一致 | 0 |
| 65,536 | 55,993 tokens | 606.90秒 | ともに一致 | 0 |

64K枠では最終生成設定のツール校正が8確認とも合格した（4呼び出し、1,668トークン）。56K入力の処理も完了し、2開発課題の実行へ進む。ここまでの接続・容量校正は12呼び出し、107,276トークン。表は異なる架空レコードから値を取り出す容量確認で、コード修正能力や複雑な長文推論の評価ではない。時間はHTTP呼び出しの実測で、速度計測専用に他のホスト処理を完全隔離した結果ではない。

最終成果物は公開検査の前に凍結し、検査後の差分変化も確認する。独立評価は指定した凍結実行にのみ行い、既存結果を上書きしない。
