# P114: 過去推論の非再入力でも全仕事費用は改善しなかった

2026年10月25日. 同じ持続Pythonと公開API経路で、過去assistantの推論欄をすべて次の入力から外す通常対照を、既知４課題の初期状態から各１回実行した. 全４条件と所有serverが終了し、監査不一致０、全件評価済み. 79生成、1,000,544論理token、使用量不明０、210 API、４最終評価. 原文の保存、公開コード・引数・観測、Python状態、新しい推論の生成設定は保持した.

成功は３／４で、過去P111の３方式も同じ３課題が成功しCSVは未達だった. CSVの425,348は使用量の実測値で、450,000という予約上限に置き換えない. 生成を伴わなかった最終予約停止の表示は１件あり、25回目の生成として費用へ加えていない.

全件の使用量が既知な直近保持に対して、非再入力は445,513 token、80.27%増えた. 各課題でも全４件で費用が増えていた. 成功した共通３課題に限る記述比較では、全保持より126,371 token／28.16%、直近保持より121,564／26.80%、選別より140,154／32.22%高かった. この３課題の集計を全４課題の費用差として扱わない.

全保持と選別の全４課題には未知使用量が残るため、その全体と今回の正確な差は未確定. 既知部分だけを引いた193,081、336,876 tokenは、それぞれ「今回−過去参照」の上限であり、確定した増分ではない. 原報告の不明を０に補完しない.

P114の事前に固定した記述上の費用・品質条件は、３参照のいずれについても満たさなかった. P114は通常対照の校正であり、新手法の採用試験ではない. P111の選別方式も元の採用基準未達のままで、この結果を使って基準を緩めない.

## 入力・出力・cache・時間は分けて読む

今回の全入力971,345、出力29,199の和が1,000,544. 入力のうちcachedは871,911、noncachedは99,434だった. 直近保持の全入力538,749、出力16,282、noncached入力119,386と比べると、今回の総論理tokenは多い一方、noncached入力は少ない. したがって論理token、cache、実時間の大小を同じものとして扱わない.

今回の仕事時間の合計は2,678.468秒、setupとcleanup込みの各課題合計は2,690.301秒. 所有serverはload、初回照合、評価、記録等を含め2,725.679秒で終了した. 評価7.097秒とload10.053秒はserver時間に含まれ、重ねて加算しない. sampled peak RSSは236,156,059,648 byte、swapは０. RSSをGPUを含む全統合メモリ使用量の測定とは扱わない. 所有プロセスが残っていないことを確認した.

成功３課題では非再入力55生成、全保持53生成だったが、精算は非再入力22生成、全保持24生成でも費用が増えた. 回数だけでは費用差を説明できない. 新しい入力差診断で、同じ実軌跡に推論欄を足し戻す局所差を数える. 行動列、観測量、出力長等を特定原因の因果効果と断定しない.

## 次の判断と範囲

非再入力を、低費用の標準方式として次へ採用しない. 「保存しているのだから毎回見せなくてもよい」という実装上の可能性と、実際に仕事全体が安くなることは別だった. 全保持も含めた通常対照を保持し、次の介入点には、具体的な不要処理と品質を失わない根拠が必要である. 単純な閾値・seed変更で好成績を探さない.

P115は結果を読む前に範囲とコードを固定し、今回の閉鎖後に405公開ソース、197私有ファイル、79実要求×４表示=316入力をbindingした. 保存要求欠測０. 計数はまだ始めていない. 完全計画の同一headで両workflow・両jobが成功した後、一度だけ実施する. 新しいモデル生成、API、生成Python、評価は０で、未知使用量を埋める診断でもない.

この比較は既知４課題・各１回で、P111を過去参照に使う. P111の結果を知ってから通常対照を追加しており、同時実行の対照、未見確認、一般的な品質維持や因果効果の証明ではない. 既存の[推論再入力](reasoning_replay_vendor_scope_20261025.md)と[計画保持・cache制御](reasoning_state_and_cache_prior_scope_20261025.md)の先行研究も踏まえる. 新規性と採録に足る貢献は未確立. 原稿保留と未見12課題未閲覧を維持する.
