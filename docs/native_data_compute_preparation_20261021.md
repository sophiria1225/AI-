## なぜ準備したか

P18では取得後の書出に欠落があり、P21では同じ情報から直接書出とコード生成を診断した。ただし、通常の計算ツールを持つエージェントが、検索から操作完了まで進める比較はまだしていない。計算手段を持たない基準だけに勝って、新しい記憶や検査器が必要だと結論するのを避ける。

既存の[CodeAct](https://proceedings.mlr.press/v235/wang24h.html)や[公式AppWorldのコード型](appworld_baseline_scope_20261021.md)と同じ一般原理に属する対照の準備である。ここでは環境APIを呼ぶプログラムを生成せず、取得済み観測の計算に限るため、どちらの完全再現とも呼ばない。

## 何を実装したか

Pythonは標準ライブラリと変数・集合演算・条件・反復を使える。結果は文字列として戻し、構造化した結果はモデルがJSONへ変換できる。出力を完了宣言や独立検証へ昇格させない。計算は模擬アプリの状態を変更せず、API送信数に混ぜない。計算の実時間と入出力、その結果を読むモデルのトークン費用は記録対象にする。

実行器への追加は明示的に有効化した場合だけで、既存の標準カタログにはこのツールを出さない。完了後・停止後に続く呼出しは、従来どおり実行しない。失敗・未知ID・出力超過は成功扱いにしない。
