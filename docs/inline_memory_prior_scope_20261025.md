# 同時出力と実行可能な記憶の原典照合

P119の全条件が閉じる前に確認した. 中間成否や私有要約本文は参照せず、実行中の条件とソースは変更していない. [取得記録と確認範囲](../reports/checkpoint_inline_and_query_prior_scope_20261025.json).

[MEM1 v1 §3.1、§4.1、付録A.5](https://arxiv.org/html/2506.15841v1#S3)は、内部状態の更新と行動を同じ生成過程で出し、過去の文脈を更新する. 強化学習した方式に加え、通常の指示モデルへ切詰め手順を与えた対照も置く. 同時出力と学習不要だけをP119の新規性にはしない. 付録A.4.1の最大系列長や依存量はsystem指示を除く定義で、今回の全要求の論理入力＋出力とは別の指標である.

P119は既知４課題の通常要約方式間の比較で、MEM1の再現ではない. 古い完結履歴の一度だけの要約と、直近のやり取りとPython状態の保持を使う. モデル、課題、学習、更新頻度、計数規則が違うため、原典の性能値を今回の見込みや削減率へ移さない. [固定計画](experiments/P119_whole_task_inline_checkpoint.md).

[TallyMem v2 §6](https://arxiv.org/html/2610.19474v2#S6)は、モデルが指定した対象イベントと演算を、型付きの計画として台帳上で決定的に実行する. 出典の照合や計算の正確さと、対象の意味が質問に合うかを区別している. 引用文の存在確認も意味の検証ではない. 付録Kでは台帳作成とオンラインの計画生成の費用を報告する. 確認したのは本文の該当節であり、実装の再現ではない.

この原典から、記憶を実行記録へ結び付け、型付き計算や文字列一致で確かめるだけでは新規性にならないと判断する. API返却の値を正しく参照できても、その値が元依頼に十分か、捨てた履歴が将来不要かは別に残る. これは原典と今回の設計を比較した判断であり、あらゆる実行情報の利用が不可能という結論ではない.

[SKILL.state v1 §3、§7](https://arxiv.org/html/2608.26263v1#S3)は、分野ごとに定めたschemaで状態を保持し、同じ生成から状態差分と行動を得る. 記載された手順は状態差分の検査と適用の後に行動を実行する. 原典も、将来必要な情報が状態に集約できるという前提、当初は重要性が分からなかった情報の欠落、履歴自体を必要とする課題を限界として挙げる. 形式不正には再試行があるが、形式適合を意味の完全性と扱わない. 確認した本文は§3.1〜3.3、§5.7、§7と付録の更新例で、コードの再現ではない.

P119は原文の直近履歴も残す１回要約であり、SKILL.stateの再現や全状態方式の評価ではない. また、固定個数の欄があることと、その内容のtoken数が一定なことを区別する. 実行後に値を取り出す案についても、出典と値の対応、課題への十分性、追加費用を個別に定める必要がある.

次の候補では、検査できる命題、履歴の採否が変わる規則、普通の出典照合との違い、追加費用を先に定める. 現時点でその中核は未確定であり、P119へ新しい意味判定器を追加していない. 原稿と未見12課題は保留する.
