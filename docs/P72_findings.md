# P72：全未完了状態で完了通知だけを変えた結果

2026年10月23日、固定した全14ケースを実行・独立評価し、監査不一致０で終了した。写真Dは作業アプリの保存状態を変えず、完了通知１回だけで未達から成功へ変わった。精算・書出しの６状態は通知後も未達だった。**原P71の成否・不明費用は変更せず、自律エージェントの成功数にも加えない。**

最終目標は、必要な情報・処理と最終品質を保ち、制御・失敗・再取得を含む仕事全体の費用を減らすこと。この診断は成否差の解釈を明確にするもので、新しい終了規則や一般的な品質維持を確立したものではない。

## 固定した対象と手順

[P71全12件](P71_findings.md)の閉鎖・監査後、完了APIを一度も送信しなかった全７元記録を選んだ。公式成否による選別はせず、写真Dだけに絞らなかった。既知３課題の７状態であり、新しい７課題ではない。[開始前の条件](experiments/P72_public_completion_scope.md)／[設定](../configs/P72_public_completion_scope_v01.json)。

各状態で無介入→通知１回の順に別の模擬環境を作り、前半と継続の送信済み公開APIだけを再送した。全返却・スキーマ公開と、介入前の全13保存ファイルのハッシュを元記録に照合した。モデルが生成したコード、拒否され未送信だった要求は実行しなかった。通知は元P71写真Bで観測した `supervisor.complete_task(status="success")` の１回だけとし、引数・回答・作業操作の探索をしなかった。

元写真D・書出しDの使用量不明２生成は、最後の未実行応答であり、対応するAPI操作がないことを確認した。環境への作用・片付け・評価は確定している。費用不明とAPI作用不明を分け、元の不明tokenを０や推定値で埋めていない。

各120 API・実行120秒・片付け45秒・評価180秒、全体1,800秒・最大1,680 API・14評価に固定した。不一致時は全体停止、再試行・元状態交換なし。全14件が閉じる前に成否を使って条件を変えていない。

## 解釈と採らない主張

公開名で継続する条件でも、同じ作業保存状態の成否差が完了通知だけで変わる例を確認した。一方、精算・書出しでは通知を足しても未達を解消できなかった。したがって、通知追加を一律の救済策にはしない。

元[P56](P56_findings.md)では写真F/Bへ空引数の通知を追加し、Fだけが成功へ変わった。P72は明示的な成功引数で、対象も全未完了状態へ広げた別診断である。いずれも同じ既知写真の事後確認であり、別の写真課題による独立追認ではない。全18ケースを独立18課題、自律実行の新成功数、統計的非劣性へ数えない。

P55/P71の詳細省略の費用不採用は変わらない。P66の通常終了制御の局所改善とP68の未達を別条件として保持する。[原稿への反映](P72_manuscript_integration.md)／[５枚資料](../materials/20261023_p72/README.md)／[金曜の判断表](letter_friday_decisions_20261022.md)。新提案の中核・一般的品質維持・採録に足る貢献は未確立。
