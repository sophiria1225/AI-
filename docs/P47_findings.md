# P47：詳細な契約返信を備えた表示比較の全結果

**18:12 JSTに事前の停止規則で終了。採用基準は満たさない。** 予定12条件のうち９件を評価し、書出の全表示は最後の生成中の時間上限で使用量不明・未評価となった。残り２条件は未実行として保存した。写真で選択表示の成功喪失が残り、返金では詳細返信が引数名だけより低費用でも全表示には届かなかった。４課題全体の優劣や一般的な品質維持は主張しない。

## 固定した比較

全表示＋契約、選択表示＋引数名、選択表示＋契約を全４既知課題で各１回。全表示にも同じ詳細返信の規則を適用した。固定８応答後の会話・環境・Python状態から、16生成・120,000総token・480秒、元のAPI上限を共通化した。初回のキャッシュ不使用を実行済み10条件すべてで実測確認。以後の同条件内の再利用は許可し、使用量を別記する。

既公開APIの未知引数による送信前拒否だけに、元の契約または引数名を返す。新しいAPIの公開、自動的な引数修正や再送は行わない。P45の既知失敗後に選んだ通常方式の比較であり、保留12シナリオは未閲覧。[事前条件](experiments/P47_contract_comparison.md)／[固定実装de0988f](https://github.com/sophiria1225/AI-/commit/de0988ffc385ab3ba4d82e1c7d165b96345ff64f)。

６返信すべての次のプログラムで、同じAPIの送信があり、同じAPIの形式拒否はなかった。直後に同じ`api_schemas`項目を読む構文は０件。ただし、構文の不在だけで別の参照や内部判断まで否定せず、同じAPIの送信を正しい意味修復の証明としない。返金は両選択条件が最終成功し、引数名だけの条件に取引確認APIが１回多かった。この１例を確認処理一般が不要という結論にしない。

写真の選択＋契約では、契約返信の対象となる拒否がなく**付加０件**。未公開APIへの拒否が残り、移動APIの送信は０、ディレクトリ作成３件までだった。選択＋引数名は返信後に42移動を送信したが最終評価は未達。全表示も42移動であり、回数の一致を操作内容・成果物の一致と取り違えない。したがって「詳細返信を受け取ったのに写真の修復が失敗した」という説明は不適切である。

電気代は３条件とも現在時刻の拒否後に同じAPIを送信し、その後も取得を続けたが、支払要求まで届かなかった。書出は60件の曲詳細取得後にプログラムエラーを記録し、その後の２生成を経て、５回目の生成で時間上限に達した。早い段階のエラーと直接の停止理由を同じ原因として扱わない。

継続中の完全一致要求の重複は全表示の写真で５件、それ以外は０。これは引数の異なる同義要求を網羅せず、正当な再確認も含む。エラー前の作業を大量に再実行したという仮説を、この件数だけで支持しない。返信の次の生成費用や、その後の全費用は削減実績・削減可能量ではない。

## 採否とレターへの反映

この選択表示＋拒否返信を、主方式として採用しない。未完遂の全４課題比較を、完全な改善率へ変換しない。詳細な契約が返金の局所比較で低費用だったことも、全表示を上回る品質維持・総費用削減や独自性を意味しない。

仕様圧縮・段階的開示・詳細エラーの近接性は[原典照合](schema_control_overlap_20261022.md)に記録した。途中で引数だけを修正する、未完了コードを置換する案も[ControlScopeとの照合](revision_scope_overlap_20261022.md)を踏まえる。修復粒度の変更や通常のAPI案内を、そのまま新規の主提案へ改称しない。

次はこの全件診断から、必要な新規取得・既取得情報の再利用・修復と計画の費用を区別し、10月23日の主張に必要な具体的な不足を絞る。既知課題を成功まで反復したり、API枠・時間を拡大してP47を埋め直したりしない。主機構と比較条件が決まるまで、確認用12シナリオは開かない。独自の中核と、最終品質を維持した仕事全体の費用削減はまだ確立していない。
