# P118: 通常の一度だけの要約は４課題成功、総token削減の基準は未達

2026年10月25日. 既知４課題×全保持・一度だけの通常要約の全８条件を終了した. 要約条件は4/4、全保持は3/4成功で、要約条件のCSVは予算内で完了した. 一方、両側で成功した３課題では要約込みのtoken費用が4,243増え、全保持のCSVには使用量不明１件がある. 事前の通常対照の採用基準は未達のまま保持する. 新規性や一般的な品質維持を確立した結果ではない.

## 写真の費用差は、要約生成を除くと符号が変わる

写真の実行役費用は135,628から121,416へ14,212 token減少した. しかし要約役に18,455 tokenを使ったため、全仕事では139,871となり、4,243 token、約3.13%の増加である.

```text
写真の全仕事の差
  = 実行役の差 + 要約役の費用
  = -14,212 + 18,455
  = +4,243 token
```

直後の入力減少7,717 tokenは、この全仕事の差とは異なる. 要約条件の写真ではAPIも99から102へ増えており、後続の行動を固定した単なる文字数短縮の比較ではない.

両側成功の写真・精算・返金だけを、全件表から別途集計すると、全保持448,825、要約453,068で、4,243 token、約0.95%増える. 固定監査の`paired_successful_token_difference`は全８件の使用量既知を前提にしているため`null`を維持し、この３件の導出値で上書きしない. 採用基準の判定も変更しない.

## CSV成功の意味と限界

CSVの要約条件は440,461 token、77 API、約1,301仕事秒で独立評価に成功した. この既知課題と固定予算で、通常要約を使う経路が完了に到達した実例となる. 全保持は同時期の比較で未達だった.

要約前の完全要求ファイルは、写真の14位置とCSVの12位置で全て一致していた. したがって、入力の異なる初期条件から比較を始めたものではない. ただし、一致は要約後の行動や費用の不変を保証せず、この１対の差を要約本文、長さ、予算通知、cache再処理などの個別要因だけへ帰属させない. [全４対の費用分解と要求照合](../reports/P118_pair_controls.json).

４課題は既知の開発課題、各条件１回である. 4/4成功は、この４件の観測結果であり、一般の成功率100%、未見課題への品質保証、新提案の独自性ではない. 全保持の不明費用があるため、全４課題の正確なtoken増減も判定しない.

## 次の判断

通常要約でCSVまで完了した経路を、今後の品質の比較対象として保持する. 全保持への勝敗だけで追加方式の有用性を判断せず、この通常方式に対して追加の費用削減があるかを問う. 一方、現在の規則を「品質を維持して全仕事tokenを削減した方式」として採用しない.

[同じ応答に引き継ぎ情報を載せる案](inline_checkpoint_candidate_scope_20261025.md)は、独立した要約要求の再入力という具体的な費用へ対応する. ただし、新しい指示とschemaの増加、追加出力、生成上限の競合、行動の変化も数える必要がある. 実行後の判定を加えるなら、通常の同時生成との差を別に測り、正常返却を意味の保存へ読み替えない. 現在は候補の範囲を整理した段階で、追加方式の実装・性能・独自性は未確立.

元のP111の未知２件と採用基準未達、P114〜P117の全件結果を変更しない. 今回の不明１件は新しい別の要求で、以前の欠測を埋めていない. 条件を変えたCSVだけの再試行はしない. 原稿と未見12課題は保留し、まとまった結果をProjectとmaterialsへ反映する.
