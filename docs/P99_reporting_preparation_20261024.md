# P99の全件報告準備

通常のauto/required比較が終了した後、全８条件と全生成を報告する処理を追加した. 準備段階で実験は開始していない. P97の途中出力や成否を使わず、[事前の比較条件](experiments/P99_whole_task_tool_choice.md)を維持する.

`inspect_whole_task_tool_choice_session.py` は終了済みパイプライン、監査、サーバ終了記録のhashと所有関係を照合し、所有PIDと監視PIDの不在を確認する. モデルロード、初期計数、初期化、作業、後片付け、idle確認、独立評価を含むサーバ滞在時間とメモリを残す. 重なる時間は加算せず、別の実験セッションを混ぜない. モデル/API/評価の追加はない.

`build_whole_task_tool_choice_report.py` は全８条件の固定順序、全４対、計画、初期計数、activation、終了監査と開始時の両CI/job記録を照合する. 初期入力の内容と推論設定は共通、tool_choiceは指定どおりであることを要求し、入力token数の差は許容して記録する. 全固定ソースのhashと採否の計算を確認する.

出力は８頁のHTML/PDF用資料と以下のCSVである.

- `all_eight_conditions.csv`：全８条件の成否、費用、停止理由、cache、時間.
- `all_four_pairs.csv`：全４課題の対照、課題ごとの成功喪失と獲得、費用差.
- `all_eight_submission_counts.csv`：各条件の提出形式と実行記録数. 未計測を空欄で保持する.
- `all_recorded_generations.csv`：全生成の数値と要求/応答hash. 本文、コード、引数、認証情報は出さない.

未知の応答を提出なしとして数えず、使用量、cache、未実行を０で補完しない. 生成数、外側の実行記録数、API要求数は異なる単位として表示する. 出力上限到達と形式拒否は重なり得る. Python通常例外も構造化提出と両立し、構造化提出の改善を最終成果の改善へ読み替えない. 全API要求が生成記録へ対応しない、生成が抜ける、未知の形式を既知０とする場合は報告を拒否する.

10件の追加検査を含む全1,572件が成功した. 合成fixtureで全件保持、同数成功でも課題別成功喪失、欠測、偽の採否、変更された出典、未終了サーバ、開始記録不一致、全生成のCSV出力、出力先の上書き拒否を確認した. 合成fixtureの結果は実験成績として公開しない. 実資料とPDFはP99終了後に一度作成し、全頁を確認してから採否と原稿へ接続する.

P99は通常設定の開発比較であり、新手法ではない. 現在の原稿候補は引き続き [P98全件実証稿](../papers/202610_letter/execution_evidence_cohort/README.md). 保留した12課題にはアクセスしない.
