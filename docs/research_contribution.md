# 研究のアプローチと、狙う新規性

2026年10月20日改訂。旧中間資料は実装・測定の報告が中心で、何を新しく明らかにするのかが弱かった。本書では研究の問いを先に置く。10月13日の引き継ぎに従い、目的は**分担の品質上の利点を保ちながら、仕事全体の総トークンを減らすこと**。担当変更は、そのための候補であって結論ではない。

## 一文で説明

**情報を共有し、共同方針を決めても残る負担が、関連する判断と実行を別担当に置くことから生じているかを調べ、その負担を減らせる局面だけ、未完了作業・文脈・更新責任を一つの担当へ移すハーネスを研究する。**

仮題は「情報共有と作業担当変更の効果を分離した、品質制約下のAIハーネス実行制御」。タイトルや移管という解法の採用は、実験結果で見直す。

## 背景から研究課題まで

複雑な仕事を分担すると、各担当の調査範囲を限定できる。一方、調査後に共通の仕様や条件が判明すると、その条件を複数担当がそろえて判断・実行する必要がある。このとき生じる再読、方針の説明、修正依頼の往復は、総トークンを増やす可能性がある。

しかし、往復があるだけでは担当の分け方が悪いとは言えない。必要な資料がない、履歴が散らかっている、共通方針がない、モデルが課題を理解できない、という別の原因もある。本研究はこれらを区別し、**「情報を渡せばよい」のか「判断・実行する範囲を変える必要がある」のか**を問う。

例えば、認証担当と保存担当が、識別子の形式と既存データ互換性を同時に決める状況を考える。資料を共有する、中央で仕様を決めて各担当へ戻す、両方の未完了作業を一人が引き受ける、という対応を比べる。この例は機構を説明する仮想例で、現在の実験で観測した事実ではない。

## 狙う貢献を三つに絞る

1. **機構の分析**：同じ状態から、情報の整理、共同方針の決定、判断・実行の担当変更を比較する。担当境界を変える追加効果がある条件と、ない条件を示す。
2. **限定した制御方式**：その追加効果が確認できた場合に、相互修正などの履歴、必要文脈量、残予算から対応を選び、関連する未完了部分だけを移す。移管の入力・要約・検査費用も含める。
3. **設計指針**：共有で十分な範囲、中央調整で十分な範囲、担当変更に利益がある範囲を、品質と総費用の関係として示す。

これらは**狙う新規性**であり、現在成立した研究成果ではない。比較設計だけで技術的新規性が確定するわけでもない。最も近い動的方式に同じ機能を与えた比較と、複数課題での再現が必要になる。

## 提案する処理を具体化する

ハーネスが管理する単位を `U = (未完了作業, 根拠参照, 作業文脈, 更新責任)` とする。モデルの重みは変えない。

1. ツール操作、成果物の版、公開検査、未解決作業を記録する。
2. 関連する二担当を候補にし、相互修正や同じ事項の確認往復、文脈量を観測する。同じファイルを読んだだけでは依存の証拠としない。
3. 継続・情報整理・中央調整・担当変更それぞれの品質と費用を見積もる。最初は単純規則と比べ、複雑な学習器を必須にしない。
4. 担当変更を選んだ場合、操作の区切りで状態を保存し、関連部分の作業・文脈・更新責任を移す。元の担当の古い出力は適用しない。独立部分は元の担当に残せる。
5. 共通の公開検査で進め、最後の成果物を独立評価する。独立評価の正解は途中判断に戻さない。

許可された対象・操作の総範囲は拡大しない。担当変更は役割名を変えるだけでなく、作業の割り当てと適用する更新の責任を実際に変更する。一方、中央役が同じ作業を引き受ける場合は機能的に等価であり、名称で区別しない。

## 「反復実験」を研究の証拠につなぐ

| 比較 | そろえるもの／変えるもの | 結果が示すこと |
|---|---|---|
| A：継続 → B：情報整理 | 担当を維持し、取得済み情報から共通の状態文書を作り文脈を更新 | 整理・履歴更新という処置全体の効果。整理とリセットの個別効果ではない |
| B → C：中央調整 | Bと同じ情報・文脈更新を使い、共同方針を作って元の担当が実行 | 共同方針を明示する処置の追加効果 |
| C → D：担当変更 | Cと同じ取得済み根拠・文脈更新・共同方針作成手順。Dは関連する判断と更新を一担当が継続 | 方針を各担当へ渡す構成に比べた、判断と実行の配置変更の効果 |
| Dと柔軟な中央実行方式 | 中央役も必要時に直接実行できる、強い実用的比較対象 | 制限したCに勝つだけでは説明できない追加価値があるか |

復元するのは会話だけでなく、ファイル、一時ファイル、作業管理、予算、ツール環境など。B/C/Dだけで異なる要約器を使わない。共同方針を生成するLLMも費用に含める。情報の配置や再入力回数は処置によって変わり、それ自体も測定対象となるため、全プロンプトの完全一致とは言わない。

四条件は個々の機構を調べる対照であり、最良の実用システムすべてを代表しない。Cに意図的な情報不足・ツール不足を与えない。C/Dには役割や継続規則の差もあるため、「権限だけの純粋な効果」と言い切らず、[介入仕様](experiments/E1_intervention_contract.md)で処置を定義する。

## 成功条件と、仮説を見直す条件

主目的は、品質の条件を満たす範囲で総費用を下げること。開発・確認課題を分け、品質の許容差 `δ` を結果を見る前に決める。

`min E[C(π)]  subject to  E[Y(π)] − E[Y(reference)] ≥ −δ`

`C` は全担当・制御・失敗を含む入力＋出力、`Y` は独立評価による成功。有限の標本では差の信頼区間を用い、非有意差を同等と呼ばない。品質を失って安く終わる方式は成功ではない。`δ`、件数、採否の閾値は未確定。

開発時の同じ状態の分岐から品質差と費用差を推定し、最終評価ではその情報を見ずに選ぶ。各状態で観測した最高の分岐を後から選ぶ値は、運用成績にしない。最良の非移管方式を選んだ推定値には選択による偏りもあるため、比較対象の選択を開発側で行い、確認側で固定して個別差も報告する。

次の場合は主張を縮小・変更する。

- Bで同等なら、担当変更の追加価値は示せていない。
- Cや柔軟な中央役で同等なら、中央調整・実行で十分な範囲として報告する。
- 固定時点や往復回数の単純規則で同等なら、学習器の必要性は主張しない。
- 移管費用で利益が消えるなら、運用上の改善とはしない。
- 依存が強いとされた課題でも差がなければ、仮説と依存の定義を再検討する。

## 現在の実測が支えること

P3では2開発課題について単一と固定2担当を各1回実行し、一方の課題は両方式とも合格、他方は両方式とも未解決だった。P5では同じAnsible課題を共通条件で比較し、2担当580,169／単一571,839トークン、双方とも差分0、要求0/4、既存21/21で終了した。[P3](P3_findings.md)、[P5](P5_findings.md)。

これらは実行・計測基盤と課題条件の観察である。P5では相互修正や更新責任の衝突を示せておらず、**まだ担当変更の必要性も費用削減も実証していない**。実時間差はキャッシュ利用差を含み、意味的な調整負担とは同一視しない。

次は同じ基準試行を漫然と追加せず、①修正・整合判断まで進める課題条件、②完全な状態保存と復元、③四条件の処置の一致を確認する。状態保存契約の実装・制御検査は測定基盤の成果であり、E1本実験や新手法の性能成果には数えない。

## 得られる成果の形

成果物は、限定した実行単位変更機構、同じ状態で比較する基盤、全費用付きの実験記録、そして「何を共有し、何を一緒に判断・実行させるべきか」という条件付きの設計知見。論文の中心にするのは実験回数でなく、**どの処置がなぜ必要だったかを比較で説明できること**である。
