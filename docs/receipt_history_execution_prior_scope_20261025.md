# 実行結果を使う履歴制御との追加照合

2026年10月25日. P111全件の途中成否を読まずに確認した原典の追加記録. 実験の規則、比較、予算は変更しない. 著者実装の再現と同条件での性能比較は行っていない.

## PruneTIR

[原論文 v1](https://arxiv.org/html/2605.09931v1)の4節、5.1節、付録A、G〜Iを確認. エラー後にツール実行が正常化すると、修正途中の呼出しと返却を省き、最終の正常な組を残す. 初期推論に、コード類似度で検出した方針変更の推論を継ぎ足す. 解決しない場合は過去の文脈から再生成し、反復上限後はツールなしの推論へ切り替える. 付録Hは別モデルによる判断も検討する. 主な対象は数学とGPQAで、付録Iは保持文脈量と総token消費を区別する. 同論文のTNを、本研究の全要求の入力＋出力と同一の尺度とは扱わない.

本研究側の差分候補は、呼出しと観測を全て残し、失敗した手順の推論も残す点にある. P111は実行記録と呼出しの対応を確認した古い推論だけを非表示にし、直近が不適格なら原文を再表示する. 再生成や環境巻戻しは行わない. この違いだけで優位性や新規性が成立するわけではない. **実行成否を使った学習不要の履歴削減そのものは既存**である.

## AutoCompact

[原論文 v1](https://arxiv.org/html/2610.02163v1)の2節と3.1節を確認. 圧縮時点、要約、圧縮後の行動を学習対象とし、データ収集時のjudge修正を実行へ反映する. SFT後に課題成功報酬でRLを行い、評価時のjudgeは不要になる. compactは元の課題を残して過去履歴を作業要約へ置き換える. 推論予算別評価の費用はcached入力も区別した推定料金である.

P111は重みの学習も要約生成もせず、元の推論文の表示をホストで切り替える. ただし、進捗に応じて圧縮時点を選ぶ一般構想を新規とは呼べない. 異なるモデル、課題、予算、費用尺度の数値を横並びの性能比較に使わない.

## ICLRの会計と復元に関する追加確認

[原論文 v1](https://arxiv.org/html/2609.29875v1)の付録B.5〜B.6、C、D.2を追加確認. 外部状態で推論を置換できる十分条件は、保持状態を条件に次の行動分布が一致するという仮定を含む. 正常なAPI返却だけで成立する条件ではない. また、局所削除と後続の入力、出力、呼出し回数を含む総費用差を区別する会計式を示している. 本文の集約量は入力＋出力で、cache readを入力へ二重加算しない.

P112の同じ実軌跡での表示差診断も、会計的な整理として位置づける. この整理や「入力短縮と全仕事費用は異なる」という問題設定自体を独自の貢献にしない. P111の型付き実行記録は意味的な十分性の証明ではなく、採否を調べている安価な候補信号である. 本文中のproxy評価と本研究のホスト処理について、同条件の費用比較は未実施である.

## 確認時点の判断

P111では全保持と直近保持の両対照へ、最終成否と全仕事費用で比較する. この追加確認を理由に、途中で比較条件を差し替えない. 仮に基準を満たしても、実行記録が単なる保持量の違いを超えて役立つかと、近接方式に対する追加価値は別に検証する必要がある. 未見12課題と原稿保留を維持する.
