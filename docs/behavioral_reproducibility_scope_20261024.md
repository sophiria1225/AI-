# 反復・通信参照・ハーネス改善に関する追加の先行研究確認

2026-10-24。以下は一次資料の明記した範囲を読んだ記録であり、既存手法を再実装した比較ではない。自分たちの反復や修正を新規性に言い換えないために整理する。

[Yagubyan, How Consistent Are LLM Agents?](https://arxiv.org/html/2605.28840v1) の§3.2の指標定義、§4.3–4.5の実行・評価条件、§6.5を確認した。構造化ツール呼出しの反復に対し、ツール列、引数、最初の分岐、出力を区別して評価する。決定的な模擬ツールと温度1.0を用い、正しさには構造化された代理基準の限界があると述べる。したがって、ツール列の反復照合や分岐位置の記録自体を本研究の新規性とはしない。自分たちは保存された制御入力の差を照合し、AppWorldの独立評価と未達・不明費用を別に残すが、それだけで先行研究より優れた評価が成立したとはしない。

[Zhaoら, Beyond Prompts](https://arxiv.org/html/2609.05736v1) の§3の評価対象、§4.2–4.3の比較条件と編集面、§5.3、付録E.4のモデル設定を確認した。固定モデルのハーネス探索で、修正・選択・最終評価のデータを区別し、反復・費用・選択結果の信頼性を評価する。middlewareでは引数修正、エラー遮断、前提確認という既存の編集面を扱う。ハーネス改善、局所的な実行時検査、費用付きの比較という広い主張は既存研究と重なる。現在の参照統一は表示整形であり、生成コードや引数を修復する新しい探索法ではない。

[vLLM公式のTool Calling資料](https://docs.vllm.ai/en/stable/features/tool_calling/#mistral-models-mistral) のMistral節を確認した。通信IDの形式とチャットテンプレートの対応に既知の互換性条件がある。この資料は今回使っているモデル・テンプレートや、文章化された不正呼出しのID差の効果を検証した資料ではない。

以上から、今回のID経路の発見は、具体的な実装上の交絡を説明する根拠として扱う。一般的な再現性向上、新しい制御方式、品質を保った総費用削減の根拠には拡張しない。モデル入力token列や実行効果は、保存JSONの一致から推定せず別に確認する。
