# 推論表示と回復に関する追加照合

P111実行中、成否を読む前の追加確認. [先の５方式](receipt_history_prior_scope_20261025.md)を置き換えず、P110/P111の固定規則も変更しない. 以下は本文の指定箇所を確認した範囲で、実装再現や網羅的新規性調査ではない.

| 一次資料と読んだ箇所 | 確認した内容 | 今回の主張への制約 |
|---|---|---|
| [Why Pay for Long Reasoning When Rewrite Do Trick?](https://toni.foo/papers/ShortReasoning/paper.pdf), §2、§3のSetup and accounting、§4、Limitations | 要約モデルで過去推論だけを短い状態記録へ書き換える. 制御された分岐では後続tool結果を見せる前に処理し、他のメッセージを保持する. 継続生成と、要約費を含むエージェント費用を区別して評価する. | 推論履歴だけの介入、後続生成への影響、要約費を含む評価は既存の研究課題. 論文は削除や切詰め等との対応する対照がない点も限界として明記する. 本研究の両通常対照との比較は必要だが、それだけで新方式とはならない. |
| [Sentry](https://arxiv.org/html/2610.02994v1), §3.1–3.3、§4.1、Appendix A.4 | 失敗を診断した場面で外部playbookの回復知識を提示し、回復を確認してから知識を追加する. 検出・検証・更新にもモデル呼出しを使う. AppWorld指標はtask内のtest pass率. | 失敗に応じて情報を提示する一般構想は先行する. 今回は原文推論の表示を決定的に切り替えるが、回復の意味的成立を判定したり、知識を学習したりする機構ではない. 指標と対象が異なるため成績を直接比較しない. |
| [AgentRewind](https://arxiv.org/html/2608.14380v1), Frameworkの３節とExternal Environment Recovery Boundary、Appendix C.1–C.5 | 文脈と管理対象filesystemの対応したcheckpointを記録し、選んだ時点へ戻して続きを実行する. 外部serviceやネットワークの作用にはundoがない境界を明示する. | 実行履歴の保存や復元自体は新規性としない. 今回の再表示は過去の推論文を現在入力へ戻す操作で、環境やPython変数を過去の状態へ戻す操作を含まない. |

ここからの判断は本研究側の解釈である. 成功領収は、環境が要求どおりになったこと、将来の推論が不要なこと、過去の失敗が解決したことを保証しない. P111の候補は限定された機械的な選別仮説であり、品質と全仕事の費用で両通常対照を超える必要がある. 全件結果がまだない時点では、先行との差も性能も未成立として扱う.

P111のモデル、予算、seed、課題、表示規則、途中結果を見る時点は変更しない. 未見12課題と原稿保留を維持する. [固定した比較](experiments/P111_whole_task_receipt_history.md).
