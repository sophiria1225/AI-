# P72の診断結果を原稿へ反映する範囲

元P55/P71の全24表示条件は維持する。P56の４ケースとP72の14ケースを、本文の完了通知の別表に全て掲載する。元の成否、P55の不明１生成、P71の不明２生成を変更しない。

P72の対象は、成否によらず完了API未送信の全７元状態（既知３課題）。各状態で、全公開返却と介入前13保存ファイルを照合した無介入／通知１回を比較した。写真Dだけが未達→成功、精算・書出しの６状態は通知後も未達。非supervisor保存ファイルは全14ケースで不変だった。

旧P56は空引数、P72は観測済みの `status="success"` を固定したことを本文へ明記する。同じ写真の反復診断を新しい課題の追認とせず、18ケースを自律エージェントの成功率へ加えない。費用の既知下限による不採用と、終了手続きの効果を分ける。

新しい `scripts/build_public_completion_report.py` は全14ケースのCSV・５枚資料と全18診断のTeX表を作る。`scripts/build_public_completion_paper.py` は従来のP55/P56/P62/P63/P64/P66/P68/P71検査を維持し、P72の固定ハッシュ、全７対の成否、追加709 API・14評価・生成０、原稿部品との一致を検査する。旧生成処理と[P72反映前のPDF・出典](../papers/202610_letter/archive_before_P72_20261023/README.md)を保存した。
