# 10月24日：レターの中心を実行の証拠へ絞る

現在の作業用主張を「制御入力の表現をそろえた後でも、生成の一致と有効な操作の一致は別に測る必要がある」に絞る。新しい制御方式が成立したという主張ではなく、閉じた実測を基にした実証稿の編集判断である。題名は合意済みの日英を維持する。実行中のP97の途中結果は、この選択に使っていない。

## 提示する具体的な事実

中心は、壊れた引数を含む呼出しを文章化すると通信参照が文字列へ移り、その後の構造上の参照統一から外れる経路である。[合成した最小例](../materials/20261024_protocol_minimal_reproducer/README.md)はモデル・環境APIなしで再現できる。既存の正規化手順の順序修正であり、正規化一般を独自の方法とはしない。

実保存入力の診断では、統一後に同じ入力になったC/Dから、各３回とも同じ公開本文を得た。しかし全６出力はツールを提出せず、通常の実行口では形式エラーになった。別のA/Xではコード構文と標準出力が異なる一方、引数を含むAPI要求列が同じだった。したがって「出力が同じ」「コードが同じ」「有効な操作が同じ」を一つの一致率へまとめると、この事例の挙動を誤って記述する。[P93](../materials/20261024_p93_results/README.md)／[P94](../materials/20261024_p94_results/README.md)。

新しい環境で先行12プログラム・28 APIを毎回実行し、保存された公開履歴に照合した後、全18出力を通常の実行口へ渡した。元のプロセス・DB全体を復元したわけではない。１文脈の各３出力の組合せを、独立９課題として数えない。ツール提出なしの２出力を「同じ空の操作に成功」と採点しない。

P82の既知４課題24条件は、残時間通知の比較として全件を残す。参照統一は共通処理であるため、この群から統一の因果的な品質効果は識別できない。全４採用基準が未達だったこと、使用量不明４生成、成功・失敗を含む全仕事費用を保持する。P84/P94の局所診断と同じ実験として合算しない。

## 新規性と有効性についての判断

最も近い先行研究は、参照の改名感度・正規化、ツール列・引数・出力の行動再現性、ハーネス編集、時間通知の評価である。[既存の照合](behavioral_reproducibility_scope_20261024.md)と[時間通知の位置付け](time_observation_contribution_scope_20261024.md)を維持する。「一般的に出力の一致は正しさを保証しない」という既知の注意だけでは中心貢献として弱い。

今回の候補は、具体的な文章化経路と、保存入力から実際のAPI要求までの対応を一つの実装・測定条件で提示したデータと解釈である。読者が行える判断は、参照統一の前後で入力だけを確認せず、呼出しの提出可否、実行した要求、最終評価を別に記録すること。ただし、この失敗の頻度、他モデル・他課題への広がり、追加検査による一般的な費用削減はまだ示していない。新手法の新規性と採録に足る中核が確立したとは判断しない。

[和文論文誌Dの査読基準](https://www.ieice.org/jpn/shiori/iss_5_1.html)を2026-10-24に再確認した。新しいデータ・解釈・事例も評価対象で、信頼性を満たした上で新規性または有効性を評価する。新アルゴリズムだけを唯一の出口とはしないが、チェック項目に該当するだけで採録可能になるわけではない。[公式の書き方](https://www.ieice.org/iss/iss_r/jpn/publications/wabun_ronbunshi/how_to_write/)も、近い研究との差と、証拠の範囲に合う主張へテーマを絞るよう求めている。いずれも既存判断の再確認であり、今回初めて得た基準ではない。

## P97終了後と25日の判断

P97は独立した通常対照の比較として閉じる。全12枠の監査後、通知の実送信、同じ通知前入力、CSVの完了、成功喪失、成功／失敗別の総費用を確認する。条件の途中結果を見て本稿へ成功例だけ追加したり、通知を新手法へ改名したりしない。

25日は、上の具体的な事例と最も近い研究との差を中心にした短い実証稿を投稿候補として評価する。P97が基準を満たしても、その通常方式の効果を別に報告する。基準未達・通知なし・不明量が残る場合も全件を残し、同じ条件での閾値探索を自動追加しない。新たな主方式を提案するには通常対照を超える規則と実際の追加価値が必要である。
