# 大規模文書の実機導入結果

2026年10月21日、P13終了後にBrowseComp-Plusの固定配布物を取得し、**100,195文書すべての原文を読み出せること**を確認した。質問は本文を取得する前に固定したID規則で12件を選び、IDと質問だけを実行用へ投影した。モデルによる回答生成、回答判定、主実験はまだ行っていない。

## 何を確認したか

| 項目 | 実測・確認結果 |
|---|---|
| 質問側の配布 | 6 Parquet、2,781,428,153バイト。固定版の配布ハッシュと全件一致 |
| 公式BM25索引 | 15ファイル、2,170,624,147バイト。固定版の配布ハッシュと全件一致 |
| ID抽出 | query_id列だけを読み830件・重複なし |
| 開発用選定 | 本文取得前のコミット`f2fb527`の規則で12件。結果を見た交換なし |
| 実行用の質問 | 選ばれた12件だけを復号。出力列はquery_idとqueryのみ |
| 索引の全件走査 | 100,195件、ID重複0、原文なし0、空原文0 |
| 取得した内容量 | UTF-8で3,247,640,161バイト。保存形式の容量とは異なる |
| 検索の確認 | 課題と無関係な固定クエリの上位3件をIDで再取得し内容一致 |
| 負の対照 | 存在しないIDはNone、存在しない固定語の検索は0件 |
| BM25の実設定 | k1=0.9、b=0.4。文献の成績を再現したという意味ではない |
| 全件検査 | 56.79秒、プロセス最大RSS約4.01GB（macOSのバイト値） |
| 作業ディレクトリ | 7,153,636KiB。QA・索引・専用venv・JDK・アーカイブ等を含む |

原文を全件読む処理はプログラムによる整合確認で、内容をLLMへ渡す処理ではない。結果公開は件数・サイズ・ID・ハッシュに限定した。正解、gold_docs、evidence_docs、negative_docsの列は選定・実行入力生成・索引確認で読み取っていない。配布Parquetにはそれらの列も含まれるため、配布全体の取得と列内容の解析を区別する。

## この構成を選んだ理由と代案

- **質問側＋公式索引を先に使う。** 索引に全原文があり、全件数と再取得を確認できたため、別形式コーパスParquetの重複取得は初期条件から外した。検索対象は縮小していない。
- **BM25を導入の基準にする。** 埋め込みを全件作り直さず同じコーパスへ接続できる。強い埋め込み検索が劣るという実験結果はない。検索段階が主な失敗原因なら検索器の比較を追加する。
- **PythonとJavaを専用環境へ入れる。** Python3.12、Pyserini2.4.0、PyArrow26.0.0、PyJNIus1.9.0、Temurin21.0.12.1+1。既存AppWorld・推論・資料環境を更新しない。Pyseriniの通常importは符号化器の依存も辿るため、独自に上流を切り貼りせず公式パッケージの依存を専用環境へ導入した。133パッケージの版と取得記録を保存し、pip checkが合格。
- **選定と質問投影を二段階にする。** ID以外を選定へ入れる、全問を復号して手作業で選ぶ、正解文書を実行入力へ付ける案は採用しない。残り818件も依存関係を未調査なので、独立な盲検評価と認定しない。

## 導入で起きた問題も残す

Adoptiumのassets APIはHTTP403だったため、そのエラーを記録して公式GitHubリリースのメタデータへ切り替えた。200,073,404バイトのJDKアーカイブをSHA-256で照合し、専用ディレクトリへ展開した。システム全体のJava設定は変えていない。[公式のアーカイブ導入方法](https://adoptium.net/installation/archives/)。

索引確認v01のsimilarity欄はJavaバインディングの文字列表現になり、パラメータを取得できていなかった。全件走査の成否はそのまま残し、同じ索引への読み取りだけの追加確認で`BM25(k1=0.9,b=0.4)`を取得した。元レポートを都合よく書き換えていない。

Pyseriniのimport時にはmacOSでプロセス出力リダイレクトをサポートしない旨のTorch通知が出たが、importと検索の正負対照は成功した。この通知だけから検索失敗とは判定しない。

## 次に必要な実装

固定された全索引に対する検索と文書取得だけを許す実行インターフェースを作る。長い文書は位置と全長を示してページ単位で取得できるようにし、検索結果の範囲・原文アクセスを全方式でそろえる。任意のシェルやQA配布ファイルへのアクセスをモデルへ渡さない。

回答評価は終了後の別プロセスへ分離する。公式のQwen3-32B判定への接続・モデル版・数値精度・判定の校正は未完了。文字列一致だけを公式スコアへ置き換えず、生成側の終了成果物を固定してから正解を使う。開発12問は環境確認と失敗観察用であり、独自機構の有効性を確定する件数ではない。
