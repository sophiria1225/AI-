# P21：同じ書出比較に対する生成上限の感度

2026年10月21日、P20全件終了後に選択した追加診断。P20の全６件が4,096出力で提出前に停止したため、内容の比較に到達できるかを確認する。P20を最初からこの予算で実行したことにはしない。

## 変更と固定

同じ１開発局面・66観測、直接CSV／制限付きデータ処理コード、seed51/52/53、交互の順序、M3 IQ4_XS・64K・thinking有効・temperature 1.0を維持する。入力ファイルはP20とハッシュが一致。全６要求をP20の記録と比較し、送信ペイロードで変わるのは`max_tokens`だけと確認した。

| 項目 | P20 | P21 |
|---|---:|---:|
| 各生成の出力上限（思考を含む） | 4,096 | 8,192 |
| 各要求の時間上限 | 600秒 | 1,200秒 |
| 全６生成の総トークン上限 | 250,000 | 250,000 |
| 全体の実時間上限 | 5,400秒 | 5,400秒 |
| 実行・採点時の環境API | ０ | ０ |

要求タイムアウトの延長は、増えた出力枠を通信側で先に打ち切らないため。原稿では総トークン、実時間、停止理由も全件報告する。成功した呼出しだけを費用に含めない。同seedでも完全な再現は保証しない。

## 評価と継続判断

全６生成が終了してから、P20と同じ集合照合と制限付きコード解釈を適用する。コード、CSV、対象集合の意味を途中で確認して条件を変えない。形式不備・制限外コード・生成上限・提出後の欠落を区別する。未提出は内容上の欠落０と数えない。

- コードで完全書出できた場合：通常計算で解決できる範囲を記録し、次の比較における強い対照として扱う。
- 両方できた場合：元のP18の１失敗や入力整理の影響を留保し、専用の追加制御が必要と判断しない。
- 提出後の誤りが残る場合：データ選択・変換・実行器の対応範囲を分けて調べる。
- 再度全件が未提出の場合：生成上限の自動倍増を繰り返さず、入力構成・モデルの利用形態を再検討する。

１つの既知の開発事例に対する事後的な感度比較であり、６独立課題・確認実験・一般のCodeAct再現・新方式の性能実験とは呼ばない。保留12シナリオは使用しない。

## 実装上の訂正と準備検査

P20で評価を止めたJSON再整形を防ぐため、凍結した設定・入力・入力来歴を元のバイト列で保存する。変更された入力を拒否し、保存先を以前の内容で残す制御も確認した。評価にはP20の訂正版と同じ内容判定を使い、phaseの表示をP21へ対応させた。P20の旧作業木・旧評価器・全記録は保持する。
