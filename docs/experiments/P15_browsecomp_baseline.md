# P15：全コーパスを使う最初の２問

2026-10-21、R31 / [Issue #67](https://github.com/sophiria1225/AI-/issues/67)。P14と同時に推論を開始しない。実行前に実索引・モデル入力・ソースを確認して固定する。

## 目的と範囲

BrowseComp-Plusの約10万文書を調査する全履歴基準を動かし、検索、原文の続きの取得、モデルのツール利用、最終回答の固定、独立判定がつながるか確認する。探索や入力上限のどこで止まるかを記録する。２問の結果は方式の優劣やベンチマーク全体の精度ではない。

質問本文を読む前に固定した12問の先頭`353`、`234`をこの順に使う。結果に応じた入替え・自動再試行はしない。検索対象100195文書は維持する。残り10問は、接続・評価が成立してから、別の固定計画で扱う。

## 基準方式

MiniMax M3 IQ4_XSと既存のllama.cpp、64K入力枠、推論有効、temperature 1.0を維持する。担当は１つ、標準のassistant/tool履歴を全保持する。変更するのは領域用ツールと課題・最終回答の扱い。AppWorldとのスコアを平均して共通性能としない。

ツールは`search`と`get_document`。最大10件の検索結果に冒頭2048文字を添え、ID・全文長・次位置を返す。原文は8000文字ずつ続けて取得できる。最終回答を促すための追加の無料生成や、人による情報補完は行わない。

各問80モデル呼び出し、80ツール要求、450000入力＋出力トークン、1800秒。１回の出力は4096トークン。無効な要求も試行枠に含め、未知使用量は不明として残す。部分出力から処理を実行しない。

検索器は１試行につき１プロセスを起動し、全ツール要求で再利用する。起動はモデル・ツールの1800秒とは別に計測し、バッチ側で起動を含むプロセス実時間を残す。初回２問では障害を切り分けやすいこの構成を使う。試行間でも常駐させれば起動を節約できるが、まず実行と費用の境界を確認する。１要求ごとにJVMを起動する実装にはしない。

## 提出と評価

最初の正常終了・非空・ツールなしのモデル応答を最終回答にする。正解を使って途中の回答から選び直さない。生成終了時に実応答・回答・使用量・履歴・ソースのハッシュを保存する。

２問とも生成が終了してから、全提出物の整合を検査する。質問・回答列だけを評価側へ投影し、生成時の質問と一致することを確認する。未提出の問題は提出なしとして残し、正解の復号とモデル採点を省く。評価側で読む暗号化行数と、選定分の復号数を分けて記録する。証拠・正解文書の列を最初から全部読むことはしない。

公式コードのQwen3-32B用テンプレート・判定パーサを使う。MLX BF16を候補にしているが、重み取得・実行環境・採点動作は未確認。独立モデル判定が済むまでは「生成・提出あり」とだけ報告する。引用IDの存在を引用内容の正しさとはみなさず、今回の最初の接続では正解文書ラベルとの引用指標は未計算とする。
