# P45：仕様返却の選択表示と全表示の継続比較

2026-10-22、生成前の固定計画。通常の選択的Observation Maskingの対照であり、独自方式ではない。P44は初回入力だけの計数なので、最終品質や終了までの総費用を判定していない。[P44全結果](../P44_findings.md)の設計基準を通過したため、その穴を同じ４既知課題で調べる。保留12シナリオの要求文は読まない。

## １．比較対象と変更範囲

P29の写真整理・電気代・返金・書出の全４課題、８応答後の固定境界。P44の入力削減が1,000 token未満だった返金も含む。各１回、全８条件。全表示→選択表示を課題１・３、逆順を課題２・４とし、結果による交換や追加試行はしない。

`full_keep`はP44と同じ全表示。`documentation_origin_keep`は同じP44認識器・対象・省略文を一度だけ適用する。古い仕様APIだけの正常出力で、限定構文の表示プログラム・実要求・返却・stdout全体が一致した仕様返却部分を原文参照に置換する。リテラル見出し、モデルの操作、メタデータ、混合出力、最新応答、原文アーカイブ、Pythonの変数等を保持する。両条件のシステム通知は同じ。以後の新しい出力は通常通り追加し、動的に削除しない。

## ２．共通の通常制御

P40の予算通知とP41の残量出力枠を両条件へ適用する。通知には元課題のAPI使用量を含む残量、継続のモデル回数・論理入力＋出力token、残時間のスナップショットを入れる。追加モデルによる制御・予測や課題別の助言はない。通知は各回直前だけに付け、保存会話へ累積しない。

旧通知は最大出力枠を予約すると記述していたため、そのまま流用しない。新しい共通通知は、通知込みの全入力を数えた後で`min(4096, 残token−全入力token)`を出力上限にする実処理を説明する。１出力tokenも入らない場合、または入力と選んだ出力枠が65,536文脈上限を超える場合は拒否する。通常の残量制御であり、新規性はない。

| 項目 | 各条件の固定値 |
|---|---|
| モデル | 同じMiniMax M3 IQ4_XS、同じ固定重み・llama.cpp・KV設定 |
| 初回推論キャッシュ | `cache_prompt=false`、終端実測`cache_n=0`かつ`prompt_n=全入力`を照合 |
| ２回目以降 | `cache_prompt=true`、論理入力と再処理・再利用を別集計 |
| seed | 元の42＋境界８＝50、以後のagent呼出しごとに＋１ |
| 継続上限 | 16生成、論理入力＋出力120,000 token、480秒 |
| API上限 | P29の課題別上限、共通前半の使用量を含む |
| 出力上限／文脈 | 4,096／65,536、残量に応じ出力枠だけを小さくする |
| 復元／評価 | 復元600秒以内、独立評価180秒以内、生成から分離して計上 |

表示構築、通知、入力計数、生成、道具使用は継続時間へ含める。通常の全表示は選択認識器を呼ばず、選択表示だけに必要な認識費用もその条件で計上する。保存処理を含む全実行時間、環境とPython状態の復元、モデルロードも別に開示する。初回の実通知は復元後の経過時間を含むため、事前計数の残時間480秒とは異なり得る。実際の入力を毎回再計数し、初回入力の同一性は通知前のハッシュで照合する。

## ３．実行と停止

全実装・条件・検査をコミットしCI通過後、固定作業木で実行する。P44の全８保存入力と変更監査、P33の固定境界の復元証拠、P39のキャッシュ校正を再照合する。全８通知付き入力を各１回計数（計数期限300秒、１要求30秒）、ハッシュと実装を固定してから生成を開始する。事前計数だけで復元を済ませたことにせず、各分岐で公開観測とDB、記録応答によるPython状態を再照合する。

モデルサーバーの寿命は14,400秒に固定する。これは８条件の復元・継続・評価・後始末の保守上限10,560秒を収容する管理枠で、各課題の予算増額ではない。モデル・ツールを並列実行せず、同一の空きスロットを確認する。終了／停止時はこのサーバーを正常停止する。

使用量不明、API効果不明、復元不一致、初回キャッシュ違反、実行・後始末・評価器の故障、ユーザー停止でバッチを打ち切る。未実行・実行済み未評価・評価済みを分け、未知tokenを０扱いしない。通常の課題失敗や既知予算の上限は評価してから次の固定条件へ進む。停止した条件を再実行したり、予算を延長して同じ結果を上書きしたりしない。

## ４．主要な観測と採否

全８件で独立した公式最終成功を判定し、成功失敗を問わず継続の全入力＋出力tokenを合算する。課題ごとの成功の入替え、実API、原文再読、実再処理／再利用、通知文字数、表示処理と計数の時間、復元費用も残す。単に早く失敗した安さを成功の効率としない。

次の設計へ進む開発基準は、**全８件が使用量既知で完了し監査を通過、全表示で成功した課題の喪失０、選択表示の継続総tokenが全表示より小さい**こと。成功件数だけの一致では通過させない。他の費用の悪化も開示し、token差だけで全費用削減を断定しない。１seedの既知４課題なので統計的非劣性・一般的品質維持の基準にはしない。基準不通過ならこの形の選択表示を採用せず、失敗と全費用を保存して次の原因を検討する。

P33/P40とは通知・出力枠・初回推論状態などが異なるため、過去の値を今回の因果対照として差し引かない。P42の生成見送り、P44の入力計数の限界を変更しない。単一作業役の比較であり、複数担当の通信費・動的再編の有効性や独自機構を示したものにはしない。
