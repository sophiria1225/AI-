# P123: 単発要約と繰返し要約の仕事全体比較

2026-10-25の継続指示に基づく次の比較仕様である. この仕様の作成時点ではP122の固定24条件が実行中で、P123の実課題生成は未開始. P122の途中の成否や費用は設計に使用していない. P122全枠と所有serverの閉鎖、全件監査と結果の確認後に、閉鎖記録と本実装を結び付けた実行計画を別途固定する. 現在はその実行計画を作成していない. 固定計画、同じ完全headのpushとpull_request両workflowと両job成功、事前計数を満たすまで開始できない.

## 問いと根拠

目的は、成功を維持しながら要約を含む全仕事の入力＋出力トークンを減らすこと. P120は単発の別呼出し要約4/4成功に対し、単発の同時要約3/4で、採用基準未達だった. 同時要約CSVでは要約後の入力が11,110から25,687 tokenへ再び増えた. これは繰返し圧縮を試す根拠であり、CSV失敗の原因や改善量の証明ではない. [終了済み全８条件の診断](../../reports/rolling_checkpoint_core_preparation_20261025.json).

履歴を状態へ集約し、必要に応じて更新する考え自体は通常対照である. 既存のMEM1等との重なりを含む[先行範囲](../rolling_checkpoint_candidate_20261025.md)を維持し、本比較を新規手法の成立とは呼ばない. ３方式は指示、schema、要約時点、出力配分、後続行動も変わり得るため、差を要約専用入力だけへ帰属させない.

## ３方式と固定範囲

| 条件 | 要約生成 | 機会上限 |
|---|---|---:|
| `single_checkpoint` | P120と同じ単発の別呼出し要約. 既存推論部品を変更せず使う | 1 |
| `rolling_separate` | 独立した要約要求で状態を更新 | 3 |
| `rolling_inline` | 次の行動と同じ応答の必須欄で状態を更新 | 3 |

既知の写真、精算、返金、CSVの全４課題を全３方式で１回ずつ、計12条件実行する. 過去の成功例の流用や欠測の穴埋めはしない. 順番は写真が上表順、精算が別呼出し反復→同時反復→単発、返金が同時反復→単発→別呼出し反復、CSVが上表順. world seed42、model seed57＋役割内呼出し番号、行動温度1.0、別要約温度0.7. seed選別や閾値探索をしない.

反復方式の共通条件は、実際に提示中の履歴がnative入力16,384 token以上で、前の機会を閉じてから少なくとも３回の新しい行動と結果が完結していること. 初回も完結３回以上を必要とする. 元のシステム指示と依頼、直近２回を残し、同時要約では現在の行動と結果も残す. ２回目以降は以前の要約と新たに古くなった部分をまとめる. 保存原本は削除しない. 未知、未完了、曖昧な情報は要約欄で区別するよう要求するが、意味の正しさは形式検査では保証しない.

要約はcompleted、usable_state、remaining、uncertaintiesの４欄. 既存の32項目、各文字列2,048文字、全体8,192文字上限を維持する. 同時要約はrun_python欄に限定し、tool_choiceはautoのまま. 保存する原応答と、metadataを取り除いた実行用コードとspan IDを結び付け、同じコードを１回だけ実行する. まだ得ていない同じ呼出しの結果は要約させない.

次の要求を作る際に、従来表示と新しい要約表示の両方を同じ共有残予算表示でnative計数し、後者が厳密に短い場合だけ採用する. 不正、欠落、途中切断、非短縮でもその機会を消費し、次の機会には新しい完結３回を必要とする. 同じ要約の修復再試行、別要約への救済、意味判定用モデルは加えない.

## 有限予算と停止

１条件は全役割合計80モデル呼出し、450,000入力＋出力トークン、1,800作業秒. 追加要約も同じ予算に含め、再要約で残量をリセットしない. 出力4,096、context65,536、１要求600秒を残作業時間で制限する. 写真160 API、その他80 API. 準備120秒、後始末180秒、idle回復60秒、独立評価180秒. 12条件の上限は960モデル要求、5,400,000 token、1,200 API、12評価で、最大16の別要約要求を内包する. 同時要約は最大12機会で行動要求に内包する. 所有serverは32,400秒の有限lease. 予算予約量を実費とはしない.

別要約の開始前には、要約と次の行動の２要求分が共有呼出し枠に残り、要約入力＋現在の行動入力＋２出力上限が共有トークン枠に収まり、要約contextが収まるか確認する. 満たさなければ要約は送らず、従来表示で行動の通常の予算判定へ進む. 未送信の要約をモデル要求や無料の応答として計上しない.

使用量不明はその条件の生成と行動を停止し、未知値を補完しない. API効果と後始末が確認できる場合だけ１回の独立評価を行い、固定した次条件へ進む. API効果不明、初期状態不一致、cache混入、runtime、後始末、評価、server同一性の異常は全体停止. 失敗、未評価、未実行も12枠に残す. ユーザーの停止指示に従う.
