# P120終了後の全件表示と費用分解

P120の固定８条件の成否を見ずに集計を準備する. 保存した公開監査結果とsession集計を入力にし、モデル、生成Python、API、tokenizer、評価は追加実行しない. 原稿と未見12課題は保留する.

## 制御が実際に働いたか

今回の同時出力方式は、１回の適格な `run_python` 要求で `checkpoint` を必須欄にする. `tool_choice=auto` は維持しているため、必須欄の指定は、要約の生成や履歴置換の証拠にはならない. 要求が送信された回数と、実際に短い入力へ置き換えた回数を分けて出す. 各条件の図にも履歴置換の有無を記す.

要約が未出力、無効、短縮しない、次の推論がなく未判定の各場合は、監査済みの制御判断をそのまま残す. 未実行や会計できない枠を「置換なし、費用０」の試行へ読み替えない. 形式が妥当でも、要約内容の意味的な正しさや十分性は保証しない.

## 全８条件の図

４課題それぞれで別呼出し方式と必須欄の同時出力方式を並べる. 実行役の入力と出力、別呼出し要約の入力と出力を積み上げ、成功、失敗、役割別呼出し数、履歴置換の有無を示す. 必須欄を指定する指示、schema、要約本文は実行役の費用に含む. キャッシュ済み入力も論理入力に含める.

使用量不明は既知小計に網掛けと `+ ?` を付け、未実行の枠も表示する. 私有領域の合成previewで表示を確認し、実データのPNGは全閉鎖後に別途目視する.

## 全４対の照合

P119で固定した純粋集計関数を再利用し、各課題の全費用差を照合する.

`同時出力方式 − 別呼出し方式の全費用 = 実行役の費用差 − 別呼出し要約の費用`

全費用が不明なら正確な全差をnullのまま残す. 別呼出し要約の入力だけを節約実績にしない. 直後の入力短縮も全仕事の削減とは分ける. 成功した部分集合だけで、他の課題の失敗を除外した採用判断をしない.

両方式の早い方の最初の介入要求より前で、完全要求ファイルのSHAを順に比較する. 介入がなければ全実行要求を対象にし、片側が先に終わった位置も未対応として残す. 応答ファイルのSHAは行動の同一性ラベルに使わない. 以後の差を要約文や入力長だけの因果効果へ帰属させない.

## 実行条件

この集計の完全headでpushとpull_request両workflow、両検査jobの成功を確認する. 全８枠と所有serverが閉じ、元の実装headによる監査とsession集計の指紋が一致してから、図と全４対の集計を各１回作る. 既存の出力、未知、失敗、未実行枠を上書きしない. 実行中のP120のソース、条件、順序、予算は変えない.

P119の任意欄で置換０回だった結果を保持する. 必須欄への変更、同時出力、集計のいずれも、それだけで新規性、一般的品質維持、採択可能性の証明にはしない.
