# P143：最終結果と初稿への反映

**実験は2026年10月28日12:22 JSTに全8条件を閉鎖した。目的である「課題成功を維持し、全仕事のトークン数を減らす」は達成していない。** 通常の再帰要約TRは3/4成功、差分保持TDOは2/4成功で、写真課題の成功を1件失った。使用量不明が1呼出しあり、固定した全体比較の削減率は確定できない。原稿はこの評価結果を記録する初稿であり、技術の有効性や投稿採択の根拠が揃ったという扱いにはしない。

## 実際に観測できたこと

1. **精算は両方式で成功したが、TDOの費用は35,578トークン増えた。** 内訳はactor +35,630、focus −52であり、focusの小さな減少を後続actorの増加が上回った。呼出し回数や経路も変わるため、増分すべてを保持表現の文字数だけの効果とは扱わない。
2. **CSVの84,040トークン減は、両方式が失敗した実行同士の差である。** 両者とも環境API上限80で停止した。成功を保つ節約の根拠にはならない。
3. **写真課題では、TDOの第二要約を採用した記録がない。** 第二object focusは既知14,651トークン（入力10,555、出力4,096）を消費し、finish reasonはlengthだった。delta採用・差分付きactorは0。公開metadataだけから正確な不採用理由は断定しない。その後のactor呼出し中に作業期限へ達し、使用量不明1件と公式失敗が残った。
4. **返金課題には第二差分処置が届いていない。** 成功・費用の一致を差分保持の効果例へ数えない。

変更promptの既知focus送信は3/4課題、採用された差分を含む既知actor入力は2/4課題（精算・CSV）で観測された。第二機会のある3対はtransport参照を正規化したprefixが一致し、strict prefixは一致しない。正規化による一致は内部状態の同一性を保証するものではない。

## 固定判定と研究上の結論

`observed_utility_criteria_met=false`、`comparison_gate_met=false`、`development_gate_met=false`を維持する。固定の全体差・全体削減率・共通成功差はいずれもnull。精算・返金の既知の個別差は示せるが、元の固定common判定を事後の別定義で置き換えない。

本条件での所見は、差分の作動や次入力を短くする採用検査だけでは、全仕事の節約・最終成功を判断できないという点である。差分保持一般の無効性は示していない。保持・object出力指示・ホスト結合を合わせた実装の限定比較であり、要素単独の因果効果や新規性をこの結果だけから確立しない。

全8条件は既知4課題、再使用seed157、共通閾値8,192、作業1,200秒で実行した。P142の非発動を観測後に選んだ開発条件であり、閾値と作業時間が同時に変わるためP142との差を閾値単独の効果にしない。以前の失敗やP141の1課題の小さな削減を、この全体比較へ混ぜて置き換えない。
