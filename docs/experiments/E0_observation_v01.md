# E0 初回観察仕様 v0.1

2026年10月13日、モデルによる実問題実行前に記載。目的は最終品質・全呼び出し費用・環境故障を測れるか、分担時にどんな調整が起きるかの導入確認。1開発課題×2方式×1回では品質維持、非劣性、削減効果を結論しない。

## 入力と環境

`django__django-15957`の公開要求文と、固定された公式イメージ内のリポジトリ全体を渡す。参照パッチ、追加評価テスト、評価スクリプト、正解ラベル、ホストの研究フォルダは渡さない。画像のCPUはamd64、Macでは専用VM内の互換実行。評価器の判定処理は公式SWE-bench、コンテナ生成だけは共通のネットワーク無効・マウント無し・capability除去・資源上限へ変更する。公式の既定環境そのままとは表記しない。

単一担当は調査・変更・可視テストを行える。固定分担は実装担当と検証担当の2つの会話状態を交互に実行する。同じ作業ツリーと基本ツールを使い、両担当に全資料の読取と修正を許す。検証担当も必要なら修正できる。新しい担当の自動生成や引き継ぎ選択は実装しない。

各担当のツール結果を相手へ共有する。相手の内部推論文は共有しない。相手の受信履歴に追加された情報も入力トークンとして計上する。外部メモを作業ディレクトリに残せる。固定分担が弱くならないよう、担当範囲を理由に参照権限を制限しない。

## 予算と停止

設定は`configs/E0_pilot_v01.json`。各方式20呼び出し、総入力＋出力150,000トークン、15分以内。一呼び出し120秒、生成1,536トークン、ツール45秒、表示結果10,000文字。ローカルモデルのみで最大40呼び出し。これは初回の有限な調査予算で、本実験の必要回数ではない。

モデルは接続確認を通過した既存モデル、温度0、seed7、thinking low。P0はthinking無効だったため同一設定ではない。思考有りのコード実行を今回初めて確認する。最良の設定を探索済みとは扱わない。

次の呼び出し前に入力UTF-8バイト数とテンプレート余裕4,096トークン、最大生成長を使った保守的な見積もりで上限を確認する。モデル固有トークナイザーによる厳密な事前保証ではないため、実測値でも検査し、超過した実行は予算内成功から除外する。入力不足時に履歴を黙って切らない。費用欠落・API失敗・実行タイムアウトも記録し、欠落費用を0としない。

単一担当の提出、固定分担の両担当の提出、予算または時間上限、実行不能で止める。提出時点のパッチを保存し、ハッシュを確定してから別コンテナの最終評価へ渡す。最終評価を見て同じ提出物を修正しない。初回は順序を単一→固定分担に固定し、キャッシュとロードの順序効果があるため実時間の優劣を結論しない。

## 比較としての限界と次の判断

この自作の最小実行器は、既存の強力なコーディングエージェントの完全再現ではない。既存実装を導入する前に、費用計測と隔離が動くか確認するために使う。上位の比較で強い単一方式が必要という要件は残る。全方式の失敗から集約が必要とは結論しない。費用記録に欠陥があれば、方式比較に進む前に計測を修正する。
