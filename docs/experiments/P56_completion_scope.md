# P56：保存した作業状態と完了通知の影響を分ける

P55全12条件の終了・監査後に選んだ、既知１課題の事後診断。写真F/Dでは非supervisorアプリの保存ファイルが全て一致するが、完了通知と公式成否が異なった。この差を実作業の改善と誤読しないために、終了手続きだけを介入する。新方式の有効性評価や未知課題での確認ではない。

| 再現する元状態 | 最後の操作 | 位置づけ |
|---|---|---|
| P55写真F | なし | 元の未達の再現対照 |
| P55写真F | 既存Dと同じ空引数の完了APIを１回 | 完了通知の局所介入 |
| P55写真B | なし | 元の未達の再現対照 |
| P55写真B | 同じ完了APIを１回 | 未完了のファイル操作を通知だけで成功にしない負の対照 |

順序も表のとおり固定。元の前半・継続で送信済みの公開APIだけを新しい模擬環境で再実行し、全返却と公開APIの出現を照合する。介入前の全保存DBが元状態と一致してから先へ進む。記録したモデル生成コードを実行せず、隠れたテスト・正解を読んで操作を組み立てない。元のDは既に観測した完了APIの引数を固定する参照であり、新しい回答の生成や探索には使わない。

各条件120 API、実行600秒、片付け45秒、独立評価180秒、全体3,600秒、最大480 API。LLM生成・token計数・未閲覧群閲覧は０。全４件の再現・介入・評価のAPI数と時間を別記し、成功・失敗を見て延長しない。実装、計画、参照監査のハッシュと同一headのpush/PR CIを固定してから実行する。使う版は既存AppWorldと公開ブリッジの固定版で、ground truthをロードしない。

元状態を再現できない、返却・DB・公開スキーマが違う、API作用や片付けが不明、評価が失敗、期限超過、ユーザーの停止指示があれば全体を止める。再実行や別の引数へ置き換えず、未実行も記録する。元P55の成果物と評価は変更しない。

介入後も非supervisorの保存DBが不変で、なし対照の成否が元と一致し、完了APIを加えた同じ元状態だけで成否が変われば、この保存状態における完了操作の影響を限定して示せる。Bはファイル状態が異なる負例として残す。結果が想定と異なっても同じ４件を報告する。P55の成功数を書き換える、未知費用を補う、無料の完了操作を仮定して費用改善を主張する、自律的な完了判断器として採用する、という解釈はしない。

これは一般的な完了APIの診断であり新規性の中核ではない。モデル反復を増やす前に原稿の主張を正しく限定するための確認とし、[P55の全件結果](../P55_findings.md)と[最終研究目的](../research_objective_20261022.md)へ接続する。
