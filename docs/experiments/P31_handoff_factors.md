# P31：会話と実行状態を分けた一回の引き継ぎ

2026-10-22 02時台の準備仕様。未実行。P29全４件の監査とP30再生確認の後に開始条件を固定する。これは適応的な再編アルゴリズムでも、新規性が確認された方式でもない。

問いは、**同じ環境状態で、会話履歴の削減の影響がPython作業状態の有無によって変わるか**。従来のP11〜P14は履歴、P27〜P29はコード実行の違いを扱っており、この組合せを同じ途中状態から比較していない。

全４既知開発課題の４回目のモデル応答後を使い、全履歴／直近１完全ターンと、変数保持／一回初期化を交差する。途中の成否・失敗箇所や最終成功を見て状態を選ばない。該当地点が完了済み・復元不一致なら、代わりの時点へ変えず開始前に停止する。各課題で条件順を循環して固定する。

後続は全条件で状態付きPython、同じモデル・道具・公開スキーマ・原資料参照・seed列。初期化した条件にも、その事実を正確に伝える。したがって「知らせずに変数だけ消す」介入ではなく、実際の引き継ぎ契約の比較である。履歴を削っても過去API記録へのread_span/span_idsアクセスは共通に保つ。新たな圧縮要約は生成しない。

各分岐は最大16生成・120,000トークン・480秒。APIは元の課題別上限から共通前半の消費を引く。時間切れ・トークン切れ・未完了を除外しない。16分岐の最大継続時間128分に、復元・評価が加わる。朝の資料前に終了するための探索的予算であり、十分な検出力や一般性能を保証しない。前半と環境の再実行費用、Python再生費用、後続費用を分けて記録する。再生費用を無視した運用効率は主張しない。

Pythonは保存API返却だけで再生するため、過去の操作を元環境へ再送しない。環境は新しい模擬世界で元API列を再実行し、各公開返却・スキーマ集合・保存DB13件のbyte hashを照合する。RNG・任意のheap・未印字変数の将来の同一性は保証しない。これは完全なプロセスforkではない。

主な記述量は各セルの最終成功と生成／API費用。効果差の差は探索的に示せるが４課題１seedの有意差検定で一般化しない。成功の集約とは別に、NameError、同じ引数の再取得、過去記録参照、実行済み操作の再送を調べる。見かけの費用削減を成功率低下と切り離さない。

固定４回を選ぶ理由は、全課題で同じ実行可能な規則を使い、完了軌跡を見た中間点選択を避けるため。より後の境界は情報量が増える一方、短い課題が脱落する。半分の時点は将来の呼出し数を必要とする。失敗課題だけの比較と、未閲覧群の先行利用も採らない。４回時点がまだ浅すぎる可能性は、この探索実験の限界として残す。

先行研究との重なり：CaveAgentの永続Pythonと意味履歴／実行状態、Agents Learn Their Runtimeの状態有無、What Does Context Compression Cost an Agent?の記憶・予算介入、Same Simulation, Different Evidenceの固定継続を確認済み。二要因を交差しただけで新規性が成立するとはしない。ここで再編利益の候補が残れば、初めて保有状態に応じた引き継ぎ選択を別データで検証する。
