# P46：既公開API契約を拒否時に返す処理と、全P45記録との対応

2026年10月22日。P45終了後の実装検査。写真と返金では送信前拒否の後、既にPythonへ渡されている `api_schemas` の再表示を行っていた。これを見て選んだ処理であり、未観測データによる仮説検証とはしない。全８条件を残し、使用量不明の最終条件も除外しない。

## 固定する規則

対象は、未送信が確認でき、APIがその時点で公開済みで、エラーが未知の引数名に一致する場合だけ。元の公開契約をそのまま返す処理、許される引数名だけを返す通常対照、元の一般的な拒否を区別する。16,000文字を超える契約は引数名へ戻し、それも収まらなければ元の拒否を維持する。原契約にない必須指定を足さない。

引数の値・認証値を返信へ写さず、誤った引数の改名・推測・自動再実行をしない。未発見API、送信済み・効果不明、実行時エラー、予算停止には適用しない。基底の実行器が送信・権限・予算を判定する順序は変えない。既に行ったAPIの作用は元の記録に残す。

## 今回の範囲

全P45の保存入力・RPC要求・受領記録から、その時点の公開契約と拒否を照合する。契約のハッシュと文字数、直後のプログラムが同じ契約を参照し実APIを送らなかったかを集計する。後続AI呼出しの費用を削減できた値とは数えない。プログラム・API・モデル・計数・独立評価の実行は全て０、ファイル分析は120秒まで。新しいモデル比較はこの検査と別に条件を固定する。

## 近い通常方式と投稿上の位置づけ

[jsonschema公式ドキュメントのValidationError](https://python-jsonschema.readthedocs.io/en/stable/errors/)は、失敗した制約、対応するスキーマやパスを取得できる。詳しい契約をエラーへ返すという処理自体は既存である。今回読んだ範囲は属性説明と例で、ライブラリ全体の性能再現ではない。

[TSCG v1](https://arxiv.org/html/2605.04107v1)は決定的なツール仕様の表現変換を扱う。今回は要旨・導入の確認にとどめ、８演算子の完全再実装とはしない。一般的な仕様圧縮や詳細エラーを新規な主提案へ改称しない。

今回の実装は、入力省略の後に公開済み仕様を取り直すためのAI呼出しが必要か、強い通常の拒否処理を備えた条件でも同じ失敗が残るかを調べるための部品。10月23日の主張・主要結果を選ぶ際には、引数名だけで足りる場合と完全な契約が必要な場合、全実行の品質・費用を対応づける。検査件数や文字数の減少だけで、レターの中核が成立したとはしない。
