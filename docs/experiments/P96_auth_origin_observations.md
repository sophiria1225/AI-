# P96：全８条件で認証由来と通常対照を分ける

P95を閉じた後の開発用診断。全８条件の成否、399要求・150モデル境界、P89–P95の公開集計、公開認証実装を見て設計した。未見評価ではない。新しい由来比較の実記録への実行は、固定計画・同一headの両workflow/job成功後に一度だけ行う。

対象はP95と同じ32ファイル、全399送信と全150モデル境界。全行をP95の要求hash・call・返却状態へ対応させる。Spotifyの既存読取６ APIを分類し、認証引数の比較を変えるのは曲一覧、アルバム一覧、プレイリスト一覧、プレイリスト詳細の４ APIに限る。残りの要求も全行保存し、都合のよい成功例や再要求だけに絞らない。

全引数一致、認証引数の単純除外、過去の成功した同一login要求に基づく由来群、の３つを比較する。後二者は実際の送信や観測文面を変えるものではない。認証値・資格情報・返答本文は公開せず、由来群は各記録内の連番で表す。以前の比較対象はそのキーの直前要求とし、例外やサイズ上限を間に挟んだ正常返答だけの飛越し比較はしない。

候補境界は、少なくとも１件の対象読取があり、全ての返答が**以前のモデル境界**に同じキーで返った値と一致し、その他の送信が同じlogin要求の再成功だけで、不明作用がない場合とする。同じ生成内だけの反復を条件へ数えない。API０件、別の操作、例外、不明、最初のlogin、新しい読取結果は連続数を切る。候補境界が２回続いた時点を一度の通知候補とし、結果から閾値を探索しない。連続が３回以上でも同じ連続区間へ何度も候補を発行しない。

これは、ローカル計算や推論に新しい進捗がなかったことを示さない。通知やAPI省略は一切行わず、最終成否との因果関係、除去できる生成数、token削減、認証の有効性、状態の同一性を主張しない。認証引数を除く通常対照と候補が同じなら、由来管理の独自の便益としては数えない。

上限は１回120秒、８条件、１入力16 MiB、各4,000イベント・80モデル境界、各索引512件、値64 KiB。全件の元の成否と既知1,689,160論理token＋不明１生成を保持する。新しいモデル生成、API送信、コード実行、DB読取、評価器、保留課題閲覧は全て０。失敗時は完了済み行と未実行対象を保存し、自動補充しない。

既知群で追加候補がなければ、この方向の大きなモデル比較は行わない。候補があっても次の介入は別計画とし、完全一致、単純な認証引数除外、由来群、同じ費用の一般的な回復通知を対照に含める必要がある。[先行研究と実装の範囲](../auth_origin_repeat_scope_20261024.md)。
