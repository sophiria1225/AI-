# P44：表示処理に対応する仕様返却だけを区別する通常の対照

P43で仕様API返却の文字列との一致箇所が分かったが、文字列一致だけでは出力の由来を認定しない。P44は保存Pythonの限定した表示処理と、対応する実要求・API返却・stdout全体を照合する。これは通常の選択的省略を比較できるようにする基準実装で、独自方式とは呼ばない。

対象は同じP29全４課題・８応答境界。元のコードは実行せず、構文木の小さい許可範囲だけを認識する。直接のprint、変数への代入、リテラル配列の有限ループ、仕様APIの実記録、json.dumps、リテラルに由来する見出し文字列を扱う。各要求のAPI・引数・順序、表示全文が元記録に一致しない場合は停止する。

名前空間が継続するため、対象プログラムだけでなく、それ以前の全保存プログラムも確認する。固定workerの初期名前空間とJSON返却を前提に、print・json等の再定義、別名、反射、動的呼出し、未知import、関数定義、属性の変更を含む履歴は採用しない。限定範囲外は元の出力を保持する。一般のPythonについての完全な出自認定ではない。

既存P42と同じ古い正常出力候補23件を全て確認する。仕様APIだけの要求群に限り、認識した仕様返却の表示を参照標識へ変え、見出し・空白・区切り・元の操作・成否・エラー・最新応答・混合出力・Python状態・原記録を残す。原文には既存read_spanからアクセスできる。変換後の方が長ければ保持する。原文が残ることは、AIが必要なときに正しく読み戻せる保証ではない。

まず全履歴／仕様返却の表示だけを省略、全４課題×２入力の８計数に限定する。モデル生成・実API・環境再生・評価器０。１要求30秒・全体300秒・同じモデルと形式・cache_prompt=false。保存したP42全履歴と最後の入力を照合し、失敗は上書き・差替えしない。全検査と固定headのCI後に計数する。

２課題以上で初回入力1,000 token以上を減らせる場合に限り、次の生成比較を設計する。この基準はP44の開発上の計算配分で、P42の判定変更ではない。十分な入力差がなければこの対照の生成を見送る。入力が短いことから品質や総費用を推定しない。次の比較には残量出力制御を共通の通常処理として含め、全４課題、初回cacheなし、同じ上限、原状態の一致、最終品質と継続総費用を固定する必要がある。

## 既存方式との重複と今回の範囲

[The Complexity Trapの原著者による説明](https://kairos.jetbrains.com/research/articles/the-complexity-trap)のObservation Masking節を再確認した。古い観測を標識へ変え、推論・操作を残すことは既存の基準方式である。P33で既に一律stdout省略を比較した。今回も、省略の仕組み自体を新規性としない。

[HD-Gistの公式PDF](https://aclanthology.org/2024.findings-eacl.143.pdf)の要旨・導入を再確認した。API仕様を引数・値ごとに圧縮し必要時に参照する発想にも先行研究がある。原論文の学習・モデル内部制御と今回の記録に基づく外側の表示処理は異なるが、その違いだけで新しい研究貢献とはしない。両論文の性能再現は今回行っていない。
