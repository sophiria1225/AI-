# P100：閉じたP97の不明使用量を条件付き区間で扱う

2026-10-24. P97全12条件・223生成試行の保存記録を一度だけ読む事後感度分析. 不明２生成を補完せず、元の採用基準・最終評価・既知費用を変更しない. P99の途中成否、未見12課題、課題DB、生成された推論の内容は調べない.

## 固定する計算

全12条件、全223試行、全４課題×３方式を保持する. 元監査でhashを固定したusage.jsonと全request.jsonだけから、数値使用量・事前入力計数・出力上限を取り出す. 要求本文は公開せず意味内容を読まない. 正常221生成について入力計数と最終使用量、出力上限を全件照合する. １件でも整合しなければ停止し、不整合を除いて分析しない.

正常生成の区間は既知費用の一点. 不明生成の条件付き区間は `[0, 事前入力計数＋要求出力上限]`. 下端０はサーバ受領を断定できないための下限で、０使用量の代入ではない. 残予算からの出力上限とcontext上限を再計算する. 別にcontext上限のみの緩い区間も保存する. P97の出力上限4096とcontext65536を別々に足して上限とせず、受理済み要求の入力＋出力予約がcontext内であることを照合する.

この区間には、記録された入力計数が実要求に適用され、サーバが出力／context制約を守り、定義した論理費用に未記録の再試行がないという仮定がある. 正常生成での整合は、欠測生成での上限遵守の証明にはならない. サーバの内部処理量・消費電力・GPU時間の上限へも読み替えない. cached inputを含む入力＋出力という元の費用定義を保つ.

差の区間は `[左下限−右上限, 左上限−右下限]`. 全３方式対の全仕事差と全12課題対を出力し、成功／未達の寄与も残す. 下端が正なら仮定下で正、上端が負なら仮定下で負、両端０なら既知の差０、それ以外は符号不明とする. 独立標本の推測や有意差検定は行わない. 元の `terminal_usage_recorded` はタイムアウトのエラー行が保存された場合もtrueであり、使用量既知とは扱わない.

## 有限の実行と採否

最大180秒、１ファイル16 MiB、各条件80生成. 追加モデル生成・API・評価・保存コード実行はすべて０. 同じ完全SHAのpush/PR workflowとaccounting-and-syntaxの成功後、専用作業木で１回実行する. 出力または失敗記録が存在すれば再実行しない. 元監査を再実行せず、その公開hashに照合する.

区間が大小関係を識別してもしなくても全結果を保存する. これは通常の区間演算を用いる事後解析で、新規手法・費用削減・一般品質維持の主張ではない. 既知結果を見て計画したこと、P97途中集計の出力逸脱があったことは消さない. P99の実行条件や採用基準へ反映しない.

CI確認コードは既存P98の手順を利用し、解析本体は外部通信・モデル・実験workerをimportしない. 検査は欠測を０に変えないこと、上限矛盾での停止、欠落・重複・再試行の拒否、全課題・全方式の保持を対象とする.
