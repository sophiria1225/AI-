# P58：残時間通知１か所の生成感度を固定４回で確認する

P55返金D/Bは一覧の差がなく、最初の実送信要求・ID以外の生成内容も同一だった。第２要求は配送IDを除くと残時間335／336秒の１か所だけ異なった。この一致と分岐は事後に見つけたもので、１秒の差が元の結果を起こしたという因果主張はしていない。

この確認では、保存したDの第２要求を基礎に、通知の数値だけを335／336へ切り替える。４呼出しの順序は335、336、336、335。seed 51、温度1.0、top-p 0.95、元の全会話・ツール・出力上限4,096を共通にする。元のB要求との照合は配送IDだけを正規化するが、新しい４要求の中ではDのIDを全て共通に保つ。

全４回とも `cache_prompt=false` とし、入力15,588 token、実測cache０を確認する。元P55第２要求はwarmだったため、これは元実行の完全再現ではない。同一のcold条件にそろえた局所的な感度確認とする。出力上限や既存履歴の内容は、結果を見て変更しない。

## 有限予算と停止

モデル生成４、全入力＋出力100,000 token、入力計数２、各生成240秒、計数各30秒、実行1,200秒。推論器は最大1,800秒、準備待ち300秒、実行子プロセス1,260秒、片付け45秒。固定版とそのpush/PR CIの両方を確認してから専用の推論器を起動する。

生成されたコード・ツール要求は保存するだけで実行しない。模擬環境API、独立評価器、未閲覧群は０。元P55記録を変更しない。未知使用量、実測cache不一致、非待機slot、版・推論器の不一致、上限、停止指示で打ち切り、代替試行はしない。全４予定行を保存し、未実行や不明を０成功・０費用へ埋めない。所有する推論器だけを終了し、ロード・常駐・標本RSS・swapを別記する。

## 出力の比較と解釈

生成メッセージ全体を、配送用tool-call IDだけを除いて比較する。推論文、コード、順序、リテラル等は保持したハッシュで照合する。同じ335の２回、同じ336の２回がそれぞれ一致するかを先に調べる。いずれかに揺れがあれば、１項目の差だけによる決定的な帰属をしない。両組が一致して値の間だけ違う場合は、この入力・seed・cold条件で通知１項目への感度が観測されたと記録する。

２回ずつは独立課題数でも分散推定でもない。元のwarm条件の分岐原因、写真の成否、総費用削減、時計を隠す新方式の有効性へ広げない。差が出なくても全４結果を残す。比較の信頼性を整える確認であり、新提案手法の成立を示す実験ではない。
