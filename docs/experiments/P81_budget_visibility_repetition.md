# P81：残時間表示の同一seed反復

2026-10-24。P80の最初の３対が終了し、書出しの２条件は未確定の時点で準備を開始した。P80で同じ品質と費用差が１回観測されても、安定した改善とは判断できない。この不足を調べる有限の反復である。新規の方式、パラメータ探索、独立した追加24課題とは扱わない。

## 問いと固定する条件

主問は、同じseedと初期状態でも、残時間表示の有無によってモデルの入出力列と全仕事費用がどの程度変わるかである。P80の全８条件を第１反復とし、全８条件の第２・第３反復を新たな記録先へ各１回行う。対象は同じ既知４課題、表示Mと非表示Hの２条件。好成績の課題だけを選ばず、未閲覧12課題は開かない。

モデルseed57＋呼出し番号、環境seed42、全推論保持、型付きAPI返却、通常Python例外、持続Python、公開スキーマ、通信参照の正規化、初回coldと後続prefix cache、実期限と全予算をP80と同一にする。第２反復は課題順にH/M、M/H、H/M、M/H、第３反復はM/H、H/M、M/H、H/M。全16新条件の順序を先に固定する。

非表示はハーネスの現在の残時間欄だけの操作である。Pythonコードからの独自の時刻参照を禁止した実験や、あらゆる時間情報を除去した条件とは表現しない。

P80の全８件の評価と監査、所有推論器の停止確認を実行開始の前提とする。P80の採用基準の成否で反復対象を選ばず、既知部分と使用量不明も元のまま残す。反復後にP80の結果を置き換えない。

## 有限予算と停止

各条件80生成、450,000論理入出力token、作業1,800秒、写真API160・他80、出力最大4,096 token、文脈65,536。準備120秒、後片付け180秒、評価180秒、idle復帰60秒。新16条件の予約上限は1,280生成・7,200,000 token、推論器の有限寿命43,200秒であり、予測使用量ではない。新規事前計数は初期入力の固有８条件だけで、生成ではない。

使用量不明の応答は実行せず、再試行しない。作用・後片付け・同一推論器の復帰が確認できた場合だけ、次の固定条件へ進む。API作用不明、初期状態・cache・runtimeの不一致、後片付け・評価失敗では後続を停止する。使用量の不明を０で埋めず、期限後に届いた既知費用も計上する。利用者の停止に直ちに従い、`.runtime/P81.stop` も各workerで確認する。

## 事前の集計規則

全24行を残し、そのうち新規実行は16行と区別する。各課題・各条件の３回について、全tokenの列と最小・最大・範囲、成否の列を示す。欠測があれば３回の確定範囲を出さない。P80の開発基準を各反復へ同じように適用し、全３反復で満たすかを記すが、統計的な非劣性や母集団の平均改善の推定とはしない。

P80終了時点で書出しHの１生成の使用量が不明であり、第１反復の基準は未達である。このため「全３反復で基準達成」は追加結果によらず不成立となる。P81の目的は成否・費用・入出力列の安定性を確認することであり、元の未達を解消するための再実行ではない。[固定設定](../../configs/P81_budget_visibility_repetition_v01.json)には閉じたP80の全件監査・停止確認・出典記録を固定した。

同じ課題・条件の３回を全３対ずつ照合し、計24対のモデル入力、公開出力、IDを除いた返却messageのhashを比較する。opaqueな推論文字列はhash照合だけに用い、意味を解釈・公開しない。最初の入力差と公開出力差を記録し、現在の残時間通知だけをそろえると入力が一致するかを機械的に判定する。この事後照合を実際に同一の入力を与えた実験と読み替えない。

通信JSONの差と再構成tokenの差、モデル入出力列の一致と環境状態の一致も分ける。これらの24対は独立した24標本ではない。生成数や出力打切り、実際の期限・API上限による停止、環境返却の違い、cache入力、出力、各時間の内訳を併記する。論理tokenを金額や計算量へ直接換算しない。

P80/P81の結果は通常設定と限定した実証原稿の判断材料である。独自手法や一般的品質維持、採録に足る新規性が確立したとはしない。結果が逆転・欠測しても隠さず、追加seedや都合のよい予算で同じ計画をやり直さない。
