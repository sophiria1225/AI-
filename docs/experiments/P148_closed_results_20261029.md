## 固定した方式・実行条件

TRは通常の反復要約、UPDATE_INDEXEDは既存状態の各項目にkeep/update/deleteのいずれか一つを指定する方式である。ホストがモデル出力を従来の更新形式へ決定的に変換し、既存の厳格な検査を再適用する。項目追加も可能だが、旧項目の完全な対応、項目数、文字数の制限は緩めない。

変更対象は2回目の更新用プロンプト、構造化出力の表現、推論上限2,048トークンであり、この組合せを一つの固定候補として比較した。行動生成、最初の専用要約、TRの処理は共通である。プロンプト・表現・推論上限それぞれの単独効果を分離した実験ではない。

| 条件 | 設定 |
|---|---|
| モデル | MiniMax-M3、IQ4_XS量子化 |
| 実行基盤 | llama.cpp b11669、コンテキスト65,536、K/Vキャッシュq8_0 |
| モデルseed基点／環境seed | 357／42 |
| sampling | actor温度1.0、focus温度0.7、top-p 0.95、top-k 0、min-p 0、repeat penalty 1.0 |
| 1実行の共通上限 | 80モデル呼出し、450,000総トークン、1,800秒 |
| 1生成の出力上限 | 4,096トークン |
| API要求上限 | 写真操作160、精算・返金・CSV処理は各80 |
| 要約条件 | 入力長8,192トークン、要約機会上限2、新規完了ターン条件3 |
| 要約時の保持・上限 | 直近2ターンを原文保持、要約8,192文字以下 |
| 推論上限 | actor・最初のfocus・TRは−1、2回目UPDATEのみ2,048 |

モデルseedは各役割の基点であり、その役割の既実行呼出し数を加えた値を各生成に用いる。表の「要約機会上限」は採用回数ではない。課題順は写真・精算・返金・CSV、方式順は奇数課題でTR→UPDATE、偶数課題でUPDATE→TRと固定した。実行後に条件、課題、seedを選び直していない。

固定ソースは `fe8945c1a448feafb09af04d006403161d98c35f`、固定計画は [P148_indexed_update_v01.json](../../configs/P148_indexed_update_v01.json) である。計画時の台帳は219件・3,118結合であり、その後の原稿公開などで増加する現在の台帳へ読み替えていない。モデルrevision、実行基盤commit、正確な設定と証跡ハッシュは機械可読資料に保存した。
