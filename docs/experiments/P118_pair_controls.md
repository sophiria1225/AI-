# P118終了後の公開集計による費用分解と要求照合

８条件の成否・要約本文を読む前に、この追加集計の対象を固定する. 新しいモデル実験、token再計数、保存コード実行、API、独立評価は行わない. 同一headの両workflowと両job成功後、全８枠とserverが閉鎖し監査・sessionが確定した公開JSONだけを読む. 全４課題を残し、既存の採用基準を変更しない.

各課題について、全仕事token差を「実行役のtoken差＋要約役のtoken」に分ける. 要約を不採用にした場合もその生成費用を含める. 未知使用量があれば正確な全差を出さず、既知小計と未知を分ける. 未実行は費用０の対照へしない. 要約前後の直後入力差は別欄に残し、全仕事の削減額に置き換えない.

要約生成より前の実行役要求について、公開監査にある要求ファイルSHAを課題内の同じ順番で照合する. 一致・不一致・未対応を全て残す. 要約を送信しなかった場合は実現した全実行役要求を照合する. 返答ファイルは時刻や計数等も含み得るため、そのSHA差を生成本文や行動の差として使わない. この対応は保存要求の同一性であり、全実行状態の同一性、圧縮の因果効果、未知課題での品質維持を証明しない.

この集計は結果を説明する補助で、新手法の確認ではない. 私有履歴や要約本文、評価の正解は読まず、P111の採用基準未達と未知２件も変更しない. 原稿と未見12課題は保留する.
