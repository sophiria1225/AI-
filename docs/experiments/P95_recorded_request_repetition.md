# P95：全８条件の再要求と、以前に得た値の範囲を分ける

対象は閉じたP88全８条件・全399 API要求。P89の全件公開集計から、CSV２条件には各10回のログインと一覧の複数取得があると分かった。ここではAPI名の回数から不要処理を推定せず、引数まで一致する再要求と、以前の返答の一致、間に入った別操作を区別する。既知の成否と集計を見た事後の開発用診断であり、独立な未見評価ではない。

要求はAPI名と全引数をJSON構造で照合する。辞書のキー順だけをそろえ、配列順、型、認証tokenを保持する。直前の同一要求との返答比較は、返却された公開payloadそのものとJSONを復号した値を分ける。例外・不明結果・返答の変化も残す。異なるログインtokenを同一人物のものと推測して結び付けない。

別に、従来のSpotify読取６ APIの範囲内で、同一要求の成功返答が**現在の要求より前**にあるかを点検する。それ以外の送信は引き続き全て区切りとなり、ログインやartist取得に新しい例外を設けない。不明作用はその後も不明とし、同一範囲の値の矛盾や失敗後には以前の成功を再利用可能扱いしない。１範囲512要求、１値64 KiBを上限とする。後の返答一致から、過去の時点に利用許可があったことへ逆算しない。

全150モデル境界も残し、API送信０の境界を「全要求が重複」と数えない。同じ要求だけの境界にも新しいローカル計算や推論があり得るため、生成の削除可能性やtoken削減を主張しない。同じ返答が観測されたことと、APIを省略しても同じ仕事になることは別である。

上限は１回120秒、８条件、各4,000イベント・80モデル境界、１入力16 MiB。元の要約・使用量・イベント・spanの32ファイルと公開実装のhashを固定する。新しいモデル生成・API送信・保存コード実行・DB読取・評価・保留課題の閲覧は０。全件結果・失敗・不明を残し、再試行や都合のよい部分への差し替えは行わない。

要求の一致は通常の照合であり、新しいキャッシュ方式ではない。結果から候補が見つかっても、状態の根拠、通常の完全応答キャッシュとの比較、制御費を含む全仕事の評価を固定するまではオンラインの省略へ進めない。全８条件の元の成否・既知token・不明１生成を保持する。
