# P67：書出しから退会までの公開証拠を点検する

P66の写真終了制御の実行中から、別の既知要求文型へ通常検査を広げられるか準備した。対象は同じCSV書出し課題 `6104387_1` のP18元基準、P25一般案内基準、P29持続Python基準の全３記録。過去の欠落71行／成功72行／未書出しという診断、公開要求、返却形状、最後の３生成の内容を確認した後の事後選択である。未知課題の確認評価ではない。

この段階は読取専用。全体120秒、各4,000イベント・80生成境界、512対象ID、CSV内容1,048,576文字まで。追加生成・API・評価・DB内容・保留群の読取は０。実行用コントローラーへ接続せず、元の成否も変更しない。[固定設定](../../configs/P67_public_export_scope_v01.json)。

## 支持する条件

分析者が記述した厳密な既知文型から、書出し先と「バックアップ後に退会」の順序を得る。任意の自然言語要求を自動で理解したとはしない。

1. 曲・アルバム・プレイリストの公開一覧を、同じSpotify認証範囲・一定page_limit・page 0から終端の空ページまで確認する。短い非空ページだけで完全としない。公開／非公開による絞込み、途中の状態変更や一覧の不一致は不明にする。
2. 観測した曲IDの和集合を取り、書出し前の公開タイトル・アーティスト情報を照合する。IDに対応するTitle/Artistsの組が衝突する場合は解釈が曖昧として不明。72件を条件へ埋め込まない。
3. 指定先への成功した作成返却と、送信内容のCSVを照合する。ヘッダー、重複、欠落、範囲外、アーティストの `|` 区切りを検査する。同じ行数だけで支持しない。公開create_fileの意味に依存する書込証拠であり、再読と同じものとは呼ばない。
4. 検査を満たすバックアップ作成の**後**に、同じ認証範囲の成功した退会返却を要求する。後から得たメタデータで、退会時点に不足していた根拠をさかのぼって補完しない。退会を実行・許可する部品ではなく、すでに行われた記録の点検である。
5. 未対応の作用、後のファイル変更、不確定なAPI作用、異なるパス・資格情報では支持しない。最初の成功した単一書込という狭い正規化範囲とし、複数書込は不明に残す。内容不一致が観測できても、後の未対応変更があれば現在の状態を断定しない。

各生成応答の全実行後に支持／矛盾／不明を記録する。最初に支持された境界があれば、後続の生成数・既知token・使用量不明数を報告するが、実測節約額へは変換しない。元の評価器は呼ばず、公開済み監査の元の公式成否をそのまま併記する。

## 採否と限界

通常の取得情報保持・CSV照合・手続き順序でどこまで説明できるかの適用点検であり、新しい集合アルゴリズムや自然言語解釈器ではない。P18/P25/P29ではインターフェースや案内・実行条件も異なるため、この３記録を方式の因果比較にしない。元の集計器や原記録を結果に合わせて変更しない。

検査が支持しても、逐次終了による実際の成否・全費用は別の有限実行が必要。書出しだけで退会を省く、既知の72行に合わせる、成功した記録だけを使う案は採らない。12件の合成反例で、ページ不足、別名ID衝突、同数の誤った行、順序違い、未来の情報、後の変更、不明作用を確認する。
