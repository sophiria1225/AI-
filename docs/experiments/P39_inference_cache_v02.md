# P39 v02：呼出しごとに再利用の有無を明示する

v01は12:31、最初のslot消去APIがHTTP 501となり、生成０回で停止した。元の[結果](../../reports/P39_inference_cache.json)・設定・実行木を保存。公式READMEの消去API記述だけで利用可能と判断した準備が不十分だった。

[固定版server-context.cpp](https://raw.githubusercontent.com/ggml-org/llama.cpp/620d2225cc436ab0b001e3200e590e3b286ef9ab/tools/server/server-context.cpp)のpost_slots実装は`slot_save_path`が空なら全slot操作を拒否する。現在の起動引数にはその指定がない。同じ実装では、`cache_prompt`が有効な場合に既存入力との接頭辞を再利用する。これを受け、v02はサーバーを再起動せず、その呼出しの再利用設定を明示して校正する。

元のP38入力・seed50・最大256生成tokenを維持。順序は再利用無効１、再利用有効１、有効２、無効２、有効３、無効３。記録ラベルのcold/warmは前版と対応するが、v02ではRAM全体を消去した意味ではない。無効時は`cache_prompt=false`、有効時は`true`。この１設定以外の要求本文は同じ。前回と同じ入力なので、有効時には直前の入力が保持されていることを実測cache_nで確認する。

全６生成・10万token・1,560秒・１呼出し240秒、状態不一致・不明使用量では停止する。要求されたツールは実行しない。正解・最終評価器・未閲覧課題は使わない。今回も、入力全処理／保持済み接頭辞の利用をcache_nとprompt_nで確認し、テキストと引数等の一致を記述的に比較する。

終了後にslot消去APIは呼ばず、キャッシュが残ることを記録する。次の研究実行は初回の再利用方針を明示し、無条件に未使用のスロットとみなさない。v01を成功例で上書きせず、サーバー再起動、モデルやseed変更、成功するまでの追加生成は行わない。これは比較基盤の校正で、新しい効率化方式の実証ではない。
