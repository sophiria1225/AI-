# P141：費用規則と主張可能範囲

2026-10-28、source固定後・P141成果読取前の補足。先行調査の最初の記録は起動前、追加確認と本整理は起動後に行った。事前登録された先行調査とは扱わず、実験条件・判定を変更しない。原稿本文ではなく、根拠と限界をまとめた資料である。対象sourceは `5cab33a2e239f3e6d90e63e32c54ba0764b1c594`、実験範囲は[固定した既知Task4の3条件診断](P141_object_timing_diagnostic_20261028.md)に限る。

`E ≥ C` は**既に観測した履歴だけを使う発火heuristic**である。既知の有料actor入力について、実入力のnative token数を `W_i`、同じtools・budget stateで新eligible rawだけを除いた計数専用入力を `U_i` とする。既存summary・system/task・直近2turnは残し、直前known-paid focus以後の `E = Σ max(0, W_i − U_i)` を累積する。`C` は直前known-paid focusの実入力＋出力であり、採用済みsummaryに限定しない。invalid/nonshrinkingでも有料ならCを更新しEをreset、未送信は不変、unknownは停止する。初回16,384、fresh3、keep2、最大2機会等の条件は別に満たす必要がある。[費用台帳](../../scripts/checkpoint_prefix_exposure.py)・[反復規則とview](../../scripts/checkpoint_representation_p139.py)・[P141への対応](../../scripts/checkpoint_object_timing_p141.py)が定義を与える。「過去のみを使う」ことは因果効果の識別を意味しない。

全体費用は全actor・focusのlogical入力＋出力で、cached inputも控除しない。共通履歴の後をA＝今focusする経路、B＝対照経路とし、`F_p`を全focus入力＋出力、`I_p`と`O_p`を全actor入力と出力の総和とすると、

`T_A − T_B = (F_A − F_B) − (I_B − I_A) + (O_A − O_B)`

削減には `I_B − I_A > (F_A − F_B) + (O_A − O_B)` が必要十分で、等号が損益分岐になる。追加・省略callや対照側の後続focusも含める。過去Eと共通の前focus費用は既支出であり、未来差への削減額には加算できない。unknownを含む厳密差は未確定のまま残す。計数の実時間は共有wall budgetに入り、logical tokensとは別に扱う。

**未測定の仮想反例。** 合法的な反復発火境界でAだけが新focus費用Fを払い、Bは追加focusを行わず、両経路ともその後actorが同じく1回だけ動いて終了すると仮定する。Aの採用後入力がBより `s` tokens短くても、`0 < s < F` なら、出力長・最終品質が同じという仮定の下で全費用は `F − s` 増える。これは実payloadを生成・計数した例ではない。したがって局所的な全view shorter検査もE≥Cも償却を保証しない。将来m回の再利用、各回の実現入力削減下限s、出力増・追加actor費用の上限H、focus純増上限F_maxをそれぞれ別途保証できれば、`m s > F_max + H` は十分条件となる。過去Eからこれらの境界は得られず、品質維持はさらに別の条件である。旧summary同bytes保持も、その記述の正確さ・現在性を保証しない。
