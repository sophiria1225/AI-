# P112: P111の実軌跡に沿った表示差の入力計数

P111の全件成否を読む前に固定する診断の準備. P111の規則や予算は変更しない. 全12条件と所有モデルサーバーの閉鎖、元の監査の終了後にだけ、実際に保存された全要求を対象として入力を計数する. 未見課題と原稿は開かない.

## 問いと対象

履歴を省いた入力差と、別の生成列による仕事全体の費用差を区別する. 全P111条件の全生成試行を対象にし、成否や削減量で抽出しない. 生成しなかった最終予約停止の表示は件数を残すが、モデル使用量に加えない.

保存済み応答とAPI実行記録から、当時の全原文履歴を順番に再構成する. 実行記録はその時点以前のものだけを用いる. P110で固定したfull、recent、execution_gatedを、各実軌跡の各要求時点へ適用する. 実際の方針で再構成した完全messagesが保存要求と一致することを要求する.

３つの仮想入力は、その時点で実際に通知した残予算と、実際のdecoder設定を共通に保持する. 次の手順の予算へ仮想差を伝播しない. 実際の方針の再計数は、その要求の実測input tokenと一致しなければならない. fullが実際の方針でなかった要求に、fullの計数一致を要求する誤りを避ける.

## 区別する値

実軌跡pについて、同じ応答列のままfull表示を仮定した各入力と、実際の表示入力との差を合計し、D_pとする. D_pは実現した経路での表示省略量であり、別方式の生成を予測した削減量ではない.

実測総費用C_pと、新しく測ったfull条件の実測総費用C_fullがともに既知なら、差を次の恒等式で整理する.

`C_p - C_full = -D_p + (C_p + D_p - C_full)`

括弧内は表示差を足し戻した残差であり、推論の悪化、再試行、出力長など特定の原因の因果効果とは呼ばない. 仮想full入力でも同じ応答が得られる保証はなく、残予算への収まり方も変わり得る. 仮想費用を別方式の実測や成功実績へ転記しない. 使用量不明があれば総費用差と残差はnullに保つ. 入力だけ数えられても、元の不明な出力使用量は復元できない.

全12条件、全試行、元の成否、欠測、未実行を保持する. 成功損失や開発上の採用判断はP111の固定基準で行い、この診断から基準を緩めない. 隣接仮想入力の共通prefixは実測KV cache使用量ではない.

## 二段階の固定と有限実行

先に[範囲](../../configs/P112_realized_history_scope_v01.json)、再構成・計数コード、検査を固定し、同じ完全headのpush/PR両workflowと両job成功を確認する. この段階ではP111の途中成否を読まない.

P111閉鎖後、`measure_realized_history_inputs.py bind` が全12条件の監査とsessionを要求し、存在する全要求と応答、制御記録、使用量、公開task、環境設定の指紋を保存する. 元の監査が欠測とした要求は追加せず、不在を記録する. bindは入力計数や再生成を行わない. 生成した完全計画を公開して同じheadの両CI成功を確認した後、`count` を一度だけ行う.

最大12条件×80試行×３表示=2,880計数、全体900秒、条件ごとのrenderer120秒、renderer RSS 2 GiB、単一ファイル16 MiB、元の私有入力512 MiB. 既存のP110 vocabulary-only rendererと同じモデル語彙、runtime版、実効chat templateを照合する. 推論context生成、decode、API、生成Python、評価器、task DB、未見課題の読取は０. rendererの停止と全枠の未完了状態を保存し、失敗時の自動再試行はしない.

`.runtime/P112.stop`とユーザー停止に従う. 全体実行中のP111へ負荷を加えず、その所有サーバーが閉じてから実施する. 終了したP110の計数を再実行しない.
