# P93：P84の公開出力・操作形式・Python構文を分ける

P84の固定した６入力×３反復の全18出力を対象にする。元の公開出力hashの一致判定を保持したまま、文章、ツール名列、JSON引数、Python ASTの差を別に報告する。結果を見た後の説明用点検であり、新しいモデル実験や独立な有効性確認ではない。

## 読み取る範囲と上限

元の全件監査でhashを保持した18要求と18解析済み応答だけを読む。raw応答を再解析する元監査は再実行しない。公開メッセージの本文・function欄だけを分類し、非公開の推論を意味的に読まない。新規モデル生成、実API、保存コード実行、評価器、DB、保留12課題の閲覧は０。

120秒、１ファイル16 MiB、公開本文・引数各65,536文字、１応答16ツールまで。Pythonは20,000文字・5,000 ASTノード、JSONは5,000値ノード・深さ64、入力は512メッセージ・512通信参照まで。上限外・不明・不正は切り詰めたり有効な空操作に直したりしない。実行・失敗の出力先が既にあれば停止して保持する。

準備前にP84の元の集計、終了理由、出力tokenと一致数は確認済み。準備中に18要求のツール引数schemaが現在の固定インターフェースと一致することも確認した。今回の分類を結果未知の検証とは呼ばない。

## 区別する比較

| 比較 | 揃えるもの | 残すもの・限界 |
|---|---|---|
| 元の公開出力 | 既存と同じ本文・function・終了理由 | 元の判定を変更しない |
| 公開本文のみ | 本文の型と文字列 | 操作が同じでも本文は違い得る |
| ツール名の順序 | function名の列 | 引数や実行意味の一致ではない |
| JSONの操作形式 | 引数のJSONオブジェクトのキー順・空白 | 値の型、配列順、操作順は保持。重複キー・非有限数は不適合 |
| Python構文 | 行・列情報を除いたAST | 変数名、値、文順、span参照を保持。意味的な等価性を証明しない |

`run_python` と `read_span` の引数形式は、保存要求に宣言された同じschemaと実行器の形に照合する。span参照の実在、文書発見、実行時の値、権限、全てのPythonライブラリの動作や最終成功は検査していない。動的実行・名前空間アクセスがある場合も構文上の注意として残す。

ツールを提出していない２出力を「同じ有効な操作」と数えない。操作形式・構文の比較は比較不能として残し、ツールなしの組数を別に示す。全15群間比較と全６群内比較を保持する。９対は同じ３反復を共有するため、独立な９標本ではない。

入力の構造化された通信IDが、公開本文またはJSON引数の文字列値に部分文字列として現れるかも数える。ID値を公開したり、出力を書き換えたりしない。未対応引数があれば走査の不完全さを示す。文字の一致は参照としての正当性を意味せず、０件でも全ての意味的影響を否定しない。

## 採否への使い方

書式だけの差なら、その範囲へ元の解釈を絞る。JSONやASTでも差が残っても、異なる実行結果や品質差へ広げない。正規化後の出力が文章だけでも、それを生成コードの成功や作業完了と数えない。P84の元判定、P82の全件未達の採用基準、P88の全件結果は変更しない。点検後も新規手法・実課題改善を自動的に成立させない。
