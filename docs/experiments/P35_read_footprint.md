# P35：API返却とコードの参照範囲を、記録再生で照合する

2026年10月22日、P33全件の分析後に定める測定仕様。新しい省略方式の実験ではない。対象はP33の全４既知課題×３条件。良い結果の軌跡だけを選ばず、８応答の共通前半と各後続を再生する。12確認シナリオは読まない。

## 目的と選定理由

P33では最初の入力を減らしても継続全体の費用が増えた。次は、取得・引渡しを細かく制御できる単位があるかを調べる。APIが返した構造化情報のどこをコードが参照し、どこで丸ごとの印字や別処理への引渡しが起きるかを区別する。

同一要求のキャッシュは、異なる要求に含まれる情報の重複や、過去出力の再入力を直接解決しない。一律省略の強化や同じ条件の反復を先行させない。現在のPython接続はAPI返却をすべてモデルへ渡しておらず、コードが印字した出力と参照IDを渡す。そのため**APIの未参照フィールド量を、そのまま削減可能トークン量に換算しない**。

## 実装する範囲

- 値は元の組込み型のまま保持し、生成コードの構文木へ読み取り記録を挿入する。辞書・リストの代理型は、型判定やライブラリの挙動を変えやすいため最初の方式にしない。
- APIから返った辞書・リストを、返却時のフィールド経路に対応づける。添字・辞書のget・反復、印字・直列化への引渡しを記録する。値、キー、引数、コードは公開しない。
- 任意関数への引渡し、変更、動的exec/eval、型や名前空間の内省等は未対応・不確実として残す。現在のスカラー値をIDだけで追跡しない。Pythonの値の共有・再利用が誤った対応を作るため。
- APIスキーマ、以前の観測を別に読み込んだコピー、外部ライブラリ内部などは完全な追跡対象ではない。参照の未観測を不要性・欠落・省略可能性としない。

## 比較と判定

元の記録との一致を、①通常の記録再生、②参照計測付きの記録再生の両方で確認する。両方ともネットワークのない既存の隔離Python内で動かし、固定順の要求に対して保存済み返却だけを返す。書込み要求も実際には送信しない。

要求列・JSON引数・標準出力・切詰めフラグ・例外・完了状態・利用可能状態を照合する。不一致が起きた軌跡はその地点で止め、次の軌跡は試す。未対応状態・元から再生できない状態も全件表へ残す。再生できた一部だけの比率を全体へ一般化しない。

一覧追加条件では元の一覧測定も順序に含める。ただし観測用の補助操作自体はコード参照量へ含めず、状態を変えなかったことを確認する。元のファイル・履歴は変更しない。

出力は全12件の照合結果、元のAPI返却数、読取を観測したフィールド数、丸ごとの引渡しと未対応・変更の件数、再生と計測時間。フィールド数・JSON量をトークンや実現可能な節約量とは呼ばない。これは１本の固定コード列に対する計測で、情報を減らした後のAIの挙動や最終品質を検証したものではない。

モデル呼出し０、実API０、最終評価器０。次の制御へ進むには、この測定で残る余地、必要情報を守る具体的規則、既存手法との違い、追加費用を別途検討する。
