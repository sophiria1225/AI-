# P77：閉じた全８条件の公開実行経路を読む

P76の結果を見た後の事後診断である。モデル・方式・成功例を追加する実験ではない。対象はP76全８条件、43生成試行、40公開Pythonプログラム。写真だけやAPI０の生成だけを選び直さない。生成不明２回を再試行しない。

## 問いと固定した読取範囲

再取得、ローカルの計算・状態点検、例外、未実行の生成中断を分ける。読むのは元監査と同じhashを持つ各条件の `events.json`・`spans.json`・`usage.json` だけ。公開コードをASTとして読むが実行しない。推論本文・モデル要求／応答・個別評価・DB内容・保留12課題は読まない。

- 43生成を、既知使用量かつAPI送信あり／既知使用量かつ送信なし／使用量不明かつ未実行へ分ける。後者を必要ない処理と解釈しない。
- 全40プログラムの構文、状態、stdoutの長さ、例外の型、APIへの対応を保存する。文字列定数、stdout本文、API引数値、応答本文は公開しない。動的呼出しや構文解析失敗も残す。構文の不在を実行作用の不在と同一視しない。
- 全送信APIの同一名・同一引数をhashで対応させ、前の返却と同じか、その間に何のAPIを送ったかを数える。同じ返却でも時刻・外部変化・読取の作用を一般に否定できず、安全なcacheや省略の証明にはしない。
- 元監査の全生成数・既知費用・不明数・API数・プログラム状態・反復数へ照合する。失敗・元成否・欠測・採用基準は変更しない。

読取120秒、各ファイル4 MiB、各コード20,000字・AST5,000ノード。入力hash・対応・費用に不一致があれば停止し、途中の結果と停止理由を保存する。結果ファイルは存在時に上書きしない。全検査と固定HEADのpush/PR両CI・job成功後、清浄な固定作業木から１回読む。追加の生成・入力計数・API・評価・DB読取・保存コード実行は全て０。

出力は `reports/P77_public_path_scope.json`。全８条件の表と公開構文の要約を資料へ返す。費用内訳は節約可能額ではない。通常方式との差、公開の判定根拠、元の必要情報・作用・例外を保つ条件が具体化しなければ、新しい制御やモデル比較へ進めない。新手法・一般的品質維持・採録に足る中心貢献は未確立のままである。
