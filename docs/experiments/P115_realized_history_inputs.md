# P115: P114の非再入力対照での実軌跡入力差

P114の全件成否を読む前に固定する、生成を伴わない診断. P111、P112、P113の結果は既知である. P114の方式、順序、予算は変えない. 全４条件と所有serverが閉じ、元の監査が完了してから一度だけ実施する.

## 問いと範囲

P114では過去の推論欄をすべて次回入力から外す. この直接的な入力差と、異なる行動列で生じた実際の全仕事費用差を区別する. 全４条件の全生成試行を対象にし、成功や削減量で選ばない. 使用量不明、欠測、未実行を残す. 未送信の最終停止表示は件数を残すが、生成費用へ加えない.

保存済み応答と実行記録から、その時点までの完全履歴を順番に復元する. full、recent、execution_gated、public_onlyの４表示を適用し、残予算通知とdecoder設定は各時点の実際の値を共通に使う. public_onlyの完全要求が実記録と一致し、既知の実入力token数が再計数と一致することを要求する. P110の選別規則とP114の全省略規則を変更しない. 保存コード、API、評価器は再実行しない.

## 会計と比較の限界

各要求の仮想full入力と実際のpublic_only入力との差の合計をDとする. Dは同じ実軌跡での表示省略量であり、別方式で得た全仕事の削減量ではない. P114には新しいfull実行がないため、比較費用は過去P111のfull条件から取る. 全12過去条件を出典付きで保持し、新規費用へ加えない.

`C_public - C_historical_full = -D + (C_public + D - C_historical_full)`

括弧内は会計上の残差であり、行動変化、再試行、推論品質などの因果効果ではない. 両側の全使用量が既知の場合だけ実測差を出し、Dも計数できた場合だけ残差を出す. 入力計数から元の不明使用量は埋めない. 同じ応答が別表示でも出るとは仮定せず、仮想費用を実測や成功実績へ転記しない.

各仮想入力に出力予約4,096を加えてcontext65,536に収まるかも記録する. contextに収まっても、実際の全仕事予算でその要求を送信できた保証はない. 仮想差を後続の残予算通知へ伝播しない. 共通prefixの長さは実測cacheではない.

先に範囲、再構成・計数・報告コード、合成検査を固定し、同じ完全headのpushとpull_requestの両workflow・両job成功を確認する. ここまではP114の中間成否を読まない. 閉鎖後のbindは全４条件の全保存要求、応答、使用量、実行記録、予算通知、公開taskとruntimeの指紋および欠測を固定するだけで、再生成や入力計数はしない. この完全計画についても両CI成功を確認した後にcountを一度だけ行う.
