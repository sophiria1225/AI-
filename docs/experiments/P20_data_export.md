# P20：同じ取得済み情報からの直接書出と計算コード

2026年10月21日、P18全件終了・診断後に設定。１つの既知の開発失敗を用いる、事後的な原因候補の切分けである。独立した確認実験や新方式の評価ではない。P19は整合版台帳の未設定枠として残し、この比較はP20と呼ぶ。

## なぜこの比較をするか

P18課題04で、必要な曲の情報を取得済みなのに１件をCSVへ出力しない例を確認した。直接文字列を生成する方式と、データを変数で扱う通常の計算とを比べずに、追加の台帳や検証器が必要だとは言えない。[CodeAct（ICML 2024）](https://proceedings.mlr.press/v235/wang24h.html)のデータ・制御フローは既存原理であり、その導入を新規性としない。

## 入力と２条件

元の実行で最初にファイルを作る直前までの、曲・アルバム・プレイリスト一覧と曲詳細の公開返却を用いる。同じ要求と66観測を、両方式で完全に同じJSON文字列として渡す。選択したAPI名と切断規則はコードへ固定する。過去のCSV、欠落項目、正解件数、モデルの説明、認証情報、独立評価、保留12課題は入力へ含めない。

| 条件 | モデルが生成するもの | 実行器がすること |
|---|---|---|
| literal_csv | 完成したCSV文字列 | 文字列を保存する |
| data_program | 同じ観測を変数で処理するコード | 制限付きデータ処理言語として解釈し、CSV文字列を作る |

両方とも新しい環境APIは使わない。コードにはモデルへ見せたものと同一の観測だけを渡す。行の選択・集合の作成・重複除去・列の抽出はモデルが書く。`csv_text`は渡された行の引用符や区切りを処理する汎用書式化のみで、対象集合や正解条件を知っていない。

共通の構造化入力に整理するため、元のP18の会話そのものとは異なる。P18の失敗と新コード条件だけを比べて効果とせず、新しい直接書出条件を必ず実行する。情報取得・アカウント終了・最終環境状態の評価もこの比較には含まれない。

## コード実行の範囲

一般のPythonプログラムをホストで`exec`する実装は使わない。ASTを解釈し、JSONデータ、有限のfor、if、内包表記、基本演算、許可したデータメソッド、CSV書式化だけを扱う。import、ファイル、ネットワーク、プロセス、eval/exec、クラス、任意の属性は機能として提供しない。最大10,000要素、100,000処理ステップ、20,000コード文字、1 MiB出力を固定する。範囲外の生成は失敗として数え、後付けで機能を追加して救済しない。

これは**一般のPythonやCodeAct実装と等価ではない**。この範囲の通常計算で成功すれば、転記を避ける既知の手段で足りる証拠になる。一方、範囲外コードが失敗しても、一般のコード実行では解決できない根拠にはしない。

代案としてmacOSのsandbox-execによる別プロセスも動作確認したが、制限設定で既知のimport確認が終了コード134となった。モデル生成コードは一度も渡していない。ホストの権限を広げて続行せず、この限定診断には不要な一般実行機能を持たせない方を選んだ。この実行器は新規技術として主張しない。

## 固定する生成条件

MiniMax M3 IQ4_XS・64K・thinking有効・temperature 1.0、P18と同じモデルとサーバー設定。２条件×seed51/52/53＝６生成。各seedでは両条件を実行し、条件の順を交互にする。各出力4,096トークン、全６生成25万トークン、5,400秒上限。制御生成・修正生成は行わず、失敗の無償再試行も行わない。使用量不明なら停止して記録する。

依存ソース、入力、モデル、計画、順序を生成前に固定。コード本文・CSVの意味判定は全６生成が終わってから行う。生成中は形式と使用量だけを進捗へ出す。

## 評価と判断

分析側で、公開返却のIDの和集合とタイトル・アーティストを照合する。CSVの見出し・形式・重複・欠落・余分な行、完全一致、生成費用を全件報告する。行順とアーティスト順は要求が指定していないため比較上は無視する。区切りの曖昧さや同一書出値を持つ別IDがあれば、判定を止めて報告する。

この照合式は分析者が課題に合わせて記述したもので、自律的な仕様生成や検証器の実績ではない。６生成は１局面の反復であり、６独立課題ではない。少数結果から一般優越や品質同等を主張しない。

- コード側だけが安定して完全書出できた場合：通常計算で解消できる現象として整理し、独自の検証器を付ける理由にしない。
- 両方できた場合：元の１失敗の再現性と共通の入力整理の影響を留保する。新機構の追加価値は示せない。
- 両方失敗した場合：データ選択、集合処理、コード範囲、書式、予算を分けて確認する。直ちに新方式の根拠とはしない。
