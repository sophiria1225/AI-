# P84：保存した参照ID差と次の生成の局所診断

2026-10-24、準備。P82は別の固定実行として継続する。P84はその終了と所有推論器の停止を確認した後、実行の必要性を判断する。新しい推論器の割当て、入力計数、生成はまだ行わない。

## 目的と選定

P83は、P80とP81第２反復のCSV課題の14生成目で、文章化された呼出しIDの差が実際の文章・token列まで届くことを確認した。表示前の参照統一では２入力が一致した。一方、P83は生成を行っておらず、次のモデル出力への影響は未検証である。

P84ではP83が保存した全６入力を使う。元の一対は既知４課題の完了した第２反復全８条件を調べた後、最初の文章化ID差から選ばれた事後の診断対象である。新しい無作為課題や独立した６課題とは扱わず、選び直さない。

|---|---|---:|
| P80元入力 | 元のIDを持つ保存要求 | 22,669 |

保存要求のmessages、tools、seed 70、temperature 1、出力上限4,096を保持し、`cache_prompt`だけを全条件でFalseにする。過去のwarm状態や元の応答を再現したとは主張しない。現在のサーバで全６入力を各１回計数し、P83の計数と一致しなければ停止する。６入力の３反復で計18生成。生成コード、API呼出し、課題評価は実行しない。

## 有限予算と順序

１生成の上限は4,096出力token、480秒。18生成の入力＋最大出力の予約は481,671論理token、全体の上限は500,000 token、生成段階は10,800秒、所有推論器は12,600秒。初期計数は最大300秒、各生成後のidle確認は60秒。実際の費用は計数、推論器起動、全生成、失敗、idle待ちを含め、重なった時間を二重に加算しない。

上表を0〜5とした固定順は、反復１が0,1,2,3,4,5、反復２が5,4,3,2,1,0、反復３が2,5,0,3,1,4。seed、上限、順序、入力を結果に合わせて変更しない。同一プロセス内で入力cacheを毎回無効化する比較であり、毎回サーバやGPU内部状態を初期化する実験ではない。終端のcache計数０を全件で確認する。

P82の終了・所有推論器停止・記録したプロセスの不在、固定HEAD、push/PR両CIを実行前に要求する。未知使用量やHTTP失敗はそのまま保存して停止し、差替えや再試行を行わない。出力上限で切れた既知応答は費用に含め、完全な次出力としては採用しない。ユーザー停止は最優先とする。

## 事前に固定する解析

各入力内の３対、６入力間の全15組×９対を公開する。対数を独立標本数や有意差の根拠にしない。公開内容・関数名・引数のfingerprintと、返された推論を含む不透明なmessage全体のfingerprintを別に比較する。生成された参照IDは照合用fingerprintから除き、推論内容を意味的に読まない。

全18件の終端使用量が既知で、全６入力の３回が完全かつ非空の公開出力として安定し、統一入力２組およびnative参照対照が一致したときに限り、元のID一対で公開出力が異なるかを判定する。一致、差、途中切れ、揺れ、欠測のすべてを報告する。内容変更対照は入力の相違が確認された対照であって、出力まで必ず変わるとは仮定しない。

この診断で判定できるのは、選んだ保存文脈における次の生成への影響までである。課題成功、継続後の実行経路、CSVの完成、仕事全体の削減は測らない。新規手法の採用基準に置き換えず、P82の条件・閾値・採否も変更しない。
