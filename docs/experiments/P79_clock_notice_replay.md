# P79：保存入力の残時間通知と単発生成の感度

P78では返金と書出しの第６回入力に、実API例外が起こる前から差があった。対応する通信IDをそろえると差は残時間通知１秒だけで、公開出力も異なった。これは１秒差の因果効果を特定した結果ではない。新しい有限診断では、保存入力の同一条件内の再現性と、通知だけを１秒変えた条件間の出力を分けて測る。

## 対象と変更

選定規則は、閉じたP78全４対のうち「最初の内容差が現時点の残時間だけ」「差の時点まで実API例外なし」をともに満たす全対。該当する既知２課題の第６回入力だけを用い、成功や費用の有利さでは選ばない。各課題の文字列通知側の元要求を土台に、最終予算通知の残時間だけを、元値／元値＋１秒へ変える。通信ID、履歴、推論フィールド、ツール定義、サンプリング、seed56、4,096出力上限は共通とする。元記録は書き換えない。

全12要求を `cache_prompt=false` として送信し、実測cache_n=0、入力計数、単一の同じ推論器を確認する。[P39](../P39_findings.md)でキャッシュ方針により出力が変わったため、今回もそれを固定する。元P78の継続はキャッシュありだったので、本診断は元の推論状態・出力・全タスクの再現ではない。保存入力中の残時間は刺激として固定する数値で、診断の実時間予算とは別にする。

各課題の２通知×３回を固定順で送る。返金は元／＋１／＋１／元／元／＋１、書出しは＋１／元／元／＋１／＋１／元。途中結果による追加・置換・seed変更はしない。全API応答を含む保存履歴は機械的に読み、内部推論の内容を意味解析せず、生成したプログラムも実行しない。

## 予算と停止

[固定計画](../../configs/P79_clock_notice_replay_v01.json)で12生成、論理入出力合計150,000 token、各要求480秒、全生成段階7,200秒、推論器9,000秒を上限とする。事前に４種類の全入力を計数し、入力＋最大出力の12回分が上限内であることを確かめる。初期計数は最大300秒。所有推論器だけを起動・終了する。

使用量不明、入力・版・キャッシュ条件の不一致、予算不足、停止指示で全体を止める。途中までの全要求・失敗・欠測を残し、補充しない。各生成後のidle確認と所有プロセスの終了を記録する。AppWorld初期化、環境API、評価器、保留12課題の閲覧は０。

## 出力の分析と次の判断

主な出力指標は、生成された公開文・関数名・引数・終了理由をそのまま比較した一致／不一致である。通信上の生成IDだけを除く。推論を含むメッセージ全体も内容を公開せずハッシュで照合し、出力上限到達、公開行動の有無、論理入出力、実処理入力、キャッシュ入力、実時間を全12条件に残す。

同じ通知の３回が一致するかを先に報告し、２通知間の全９組も併記する。組合せを独立標本に数えず、p値や一般的再現率は求めない。上限打切りや空の公開出力を同じ行動の再現とみなさない。未完了の群には確定した同一性判定を与えない。

同条件内でも公開出力が異なれば、１秒差だけで説明せず推論実行の変動を残す。同条件内が一致し条件間が異なれば、この固定した再利用なし入力で通知感度が観測されたと記述する。両方同じでも、元のキャッシュあり実行で影響がないとは結論しない。いずれの場合も、新手法、API失敗通知の効果、タスク成功、全仕事費用の削減、一般品質維持の証拠へは転記しない。

この診断の目的は、次の通常対照で固定すべき入力と、反復を要する変動を具体化すること。P78の不採用、既知課題の成否、未閲覧群は維持する。研究の最終目標である品質を保った仕事全体費用の削減に対して、本診断だけで新しい削減機構が成立したとはしない。
