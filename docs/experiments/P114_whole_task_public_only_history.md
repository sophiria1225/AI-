# P114: 内部推論を再入力しない通常対照

2026年10月25日. P111〜P113の全結果を確認後に固定する、既知４課題だけの探索的校正. 新手法の検証や独立確認とは呼ばない. 原稿は保留する.

## 問いと変更箇所

持続PythonとP99のauto経路で、過去の内部推論を一切再入力しない通常方式の費用と最終品質を、課題の初期状態から確認する. P76は８応答後の継続、P25はnative tool方式であり、この条件を満たす対照ではなかった.

各要求を完全保存履歴から組み立て、全ての過去assistantメッセージの`reasoning_content`欄を削除する. 直前の推論や失敗時の推論も例外なく対象にする. コード、公開文章、引数、返却観測、指示、状態を削除しない. 生成側の推論予算は−1、出力枠は4,096のまま. 推論生成を無料や０とみなさず、今回返った出力は全額計上する.

P111と同じ実行記録の検査・保存を共通の計測処理として残すが、その適格性で省略対象を選ばない. 追加の選別LLMは使わない. 保持したPython変数、通常の即時API呼出し、型付きエラー、公開仕様のフィードバック、数値の残token/API予算、壁時間非表示、参照識別子正規化は共通. ReadViewや完全応答キャッシュは有効にしない.

## 失敗、閉鎖、全件保存

使用量不明のモデル試行は実行・再試行せず、その条件を終了する. APIの副作用とcleanupが確定していれば、同じ所有サーバーのidleを60秒以内で確認し、最終評価を１回行って固定順の次条件へ進む. 未知のAPI副作用、初回cache不一致、初期化・runtime・cleanup・評価失敗、サーバー変更や不足した残leaseではbatchを止める. 同じ条件をやり直さない.

全４予定枠、全試行、失敗、使用量不明、未実行、未評価、生成直前に予算停止した未送信表示も保存する. 各要求を完全履歴から再構成し、計数入力と送信入力、公開情報の保持、使用量とAPI台帳を照合する. 所有サーバー閉鎖後にまとめて結果を読み、最終評価の情報を実行中のモデルへ戻さない.

## 比較と判断の限界

全４新条件を、既に公開されたP111の全12条件と出典を分けて並べる. P111を再実行・置換せず、元の採用基準未達と使用量不明２件を変更しない. P111の結果を見て追加した対照であり、同時実行対照、因果効果、一般的品質維持、採録可能性を示す実験ではない.

主要費用は課題開始からの全論理input＋output. 制御、失敗、回復を含め、cached/noncached入力、出力、生成回数、API、setup/work/cleanup/評価/load/server時間も別記する. 包含する時間を重複加算しない. token、時間、金額を同一視しない.

各過去方式との記述条件は、全８評価・使用量既知、監査正常、各課題で成功を失わず、両成功が１課題以上あり、全課題合計と両成功課題合計が両方低いこと. これは新手法の採用gateではなく、普通の対照で費用が変わるかを判断する補助である. 安い失敗だけの削減を成果にしない. 不明使用量があれば正確な差はnullとし、非負性による上下界を表示する場合はその意味を明記する. 未実行枠から上下界を作らない. 成功部分の集計は全件比較の代わりにしない.
