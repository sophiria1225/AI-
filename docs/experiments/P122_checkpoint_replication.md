# P122: 同時要約の費用差と成功を固定３設定で反復する

2026年10月25日. ユーザーから「誤差なのか、特定のパターンだけなのかを確かめ、実行を続ける」と指示があった. 続く確認に対して、P120全体では別要約4/4対同時出力3/4成功であり、性能維持は写真１課題に限ると説明した. 今回はP120/P121での区切り後に、新たな反復確認を行う. 過去の固定計画、結果、原稿は変更しない. 本文書は新しい生成を開始する前の規則である.

## 問いと限界

P120写真の7.50%減少は、全モデル要求の実測input＋outputに基づく１実行対の差だった. この値の計数一致と、生成される行動の違いによる費用のばらつきは異なる. 同じ設定での再現と、固定した別seedでの変化を調べる. CSVの成功損失、精算と返金の未起動も含め、全４課題を残す.

３設定は有限の予備確認であり、未見課題を代表する標本ではない. 統計的有意差や品質の非劣性を判定する検出力を保証せず、信頼区間は算出しない. 同じseedでの再現１組を含み、同じ既知４課題での12対を独立12課題とは数えない. 別の写真課題への一般化はこの比較では未確認のままとする.

P120の別呼出し要約と、要約欄を必須指定する同時出力をそのまま使う. 写真 `34d9492_1`、精算 `3c13f5a_1`、返金 `60d0b5b_1`、CSV `6104387_1` の順に、各課題を初期状態から両方式で１回ずつ実行する. これを下表の３設定で行う.

|---|---:|---|---|
| 1 | 57 | 別呼出し、同時出力 | 同時出力、別呼出し |
| 2 | 157 | 同時出力、別呼出し | 別呼出し、同時出力 |
| 3 | 257 | 別呼出し、同時出力 | 同時出力、別呼出し |

world seed42、モデルと量子化、実行役温度1.0、別要約温度0.7、各方式内の呼出し番号によるseed更新規則、system指示、入力と出力の上限を維持する. seedを結果に合わせて選び直したり、良い反復だけを採用したりしない. 以前のP120は開発結果として別に残し、今回の主集計へ追加しない. 反復1と以前の同じseedとの費用、成否、要求数の差は参考表へ分離する.

要約は通常入力16,384 token以上、完結したやり取り３回以上の最初の機会に１回だけ要求する. 古い完結履歴だけを対象とし、元指示と課題、直近２回、現在のコードと実際の結果を保持する. 四つの要約欄、形式・長さの検査、厳密な次入力短縮時のみの採用、metadataの再入力除外はP120と同じ. 不正、欠落、打切り時に要約用の再生成や別方式への切替をしない. tool_choiceはauto. 共有出力枠4,096にはコードと要約が含まれる.

## 予算、停止、実行前の照合

各条件は全役を合わせて80モデル要求、450,000論理token、1,800仕事秒まで. 写真160 API、他80 API. 準備120秒、後処理180秒、idle回復60秒、独立評価180秒. １要求600秒、context65,536、出力4,096は残予算にも従う. 初回cache無効と実測再利用０を確認し、その後は通常のcacheを使う.

全24枠の予約は1,920モデル要求、10,800,000 token、2,400 API、24評価. 別要約は最大12要求で、全要求予算の内数. 所有serverの上限は64,800秒（18時間）とし、全件完了または停止時に閉じる. これは最悪時の有限上限であり実績費用ではない. P120と同程度の経路なら全体で約５時間が目安だが、別seedの行動と停止理由によって変わる.

全24枠、順序、seed、解析規則を生成前に固定する. 同じ完全headのpush・pull_request両workflowと両accounting-and-syntax job成功後、専用固定木から一度だけ起動する. 24初回入力と、別要約１・合成同時要約関連３入力の計28入力を語彙だけで確認する. 各課題・反復の両方式で初回の完全要求一致を確認する. この事前確認では生成、API、評価を行わない.

使用量不明の応答は実行せず、元の不明を保持する. API効果と後処理が確認できた場合は、同じserverのidleを待って１回評価し、次の固定条件へ進む. API効果不明、初期状態、cache、実行環境、後処理、評価の故障では全体を停止し、未実行枠を残す. 障害による枠の補充、再試行、途中結果に応じた追加反復はしない. ユーザー停止を優先する.

## 全件終了後の解析

全24枠と所有serverの閉鎖後に初めて成否と費用を読む. 各反復、各課題の差を `同時出力 − 別呼出し` とし、総tokenと別呼出しを分母とした割合を出す. 全３対が既知の場合だけ平均、中央値、最小、最大、標本標準偏差を示す. 一部が不明なら既知分の一覧は残すが、全３対の統計量は未確定にする. 対応する差の平均と標準偏差の定義は[NISTの対応観測の説明](https://www.itl.nist.gov/div898/handbook/prc/section3/prc311.htm)に従う. この記述統計を推測統計上の有意差と呼ばない.

各対に両方式の成否、成功損失、要約の採用を併記する. 失敗を含む費用差は同じ成果の費用削減ではない. 成功課題だけの小計は別欄に置き、全件の代用にしない. 精算と返金で要約が起動しなければ、その成功を要約の性能維持例へ数えない. 異なるseedで起動した場合もそのまま記録する.

写真の再現判定は、今回の全３対で両方式が成功し、費用が既知、同時要約が採用され、同時出力の総tokenが少ないこと. 全体の採用には、これに加えて全24件評価済み・使用量既知・監査不一致０、各反復で課題ごとの成功損失なし、両側成功１件以上、全４課題と共通成功課題の両方で費用減少、実際の同時要約採用１件以上を要求する. 全体が未達でも写真の限定的な再現結果は区別して報告する.

元のP111不明２要求、P118不明１要求、P119の要約不発動、P120の成功損失と採用基準未達を変えない. 未見12課題は使わず、自動的な追加評価も予定しない. モデルの学習、要約の保持規則、指示の探索、新規手法の主張は含めない. 原稿はまとまった結果の後に別版へ反映する.
