# P69：CSVの取得済み情報とAPI応答全体の範囲を点検する

2026年10月23日、P68全２条件の終了・監査・結果反映後に固定した読取点検。P68は両条件とも80 APIで未達、最終境界で72件の必要メタデータがそろっても書出し・退会に進めなかった。終了判断以外の費用を具体化するため、取得時点で既に持っていた情報を調べる。

## 固定範囲

[設定](../../configs/P69_export_acquisition_scope_v01.json)。既知CSV１課題 `6104387_1` のP18_04_ROLES、P25_04_GUIDED、P29_04_CODE、P68_01_EXPORT_NATIVE、P68_02_EXPORT_CONTROLLEDの全５記録。P67の全３記録にP68の両条件を加える。選定は事後であり、各方式の条件・案内・履歴・予算の差を制御効果へ帰属しない。過去の成否・欠測・監査を変更しない。

120秒、各4,000イベント・80生成境界・512曲ID・ファイル16MiBまで。読み取るファイル名とSHA256を設定に固定する。モデル生成、環境API、評価器、DB内容、保留12シナリオの読取は全て０。APIの実装はP67と同じ公開コードのハッシュを照合する。

## 分けて記録するもの

1. `show_song`要求の直前に、そのIDのTitle/Artistsが公開返却に含まれていたか。既知CSV文型の出力列だけを対象とし、全てのAPI利用目的に十分とはしない。
2. 同じ名前・同じ引数の成功した要求が既にあり、応答全体を保持していたか。後の実応答との一致・不一致も残す。
3. 一覧や他の公開返却から得た同じIDのオブジェクトが、後の実応答全体とも一致したか。これは返却後の照合であり、未来の実応答を見たオンライン判断ではない。列だけの一致と分ける。
4. １生成内に新規情報を必要とする要求や他の操作が混ざるか。全要求の必要列が既知でも、生成全体を省けると断定しない。tokenを任意のAPIへ按分せず、元の生成費用をそのまま記録する。

時系列外の情報は使わない。未対応のSpotify操作、作用不明、ID不一致、同じIDの内容矛盾は、先の再利用候補を無条件に有効としない。未対応や不明を「不要」に置換しない。過去に取得した情報が更新後も有効かは公開記録と宣言したAPI意味の範囲に限る。

## この点検から進める条件

読み取りだけの候補数は実測節約額ではない。手書きの必要列照合、通常の同一要求キャッシュ、集合の差分取得そのものを新手法とはしない。全５記録・全該当要求と反例検査を残し、必要列は既知でも応答全体を代替できない例を隠さない。

次のモデル実験へ進むには、実行時に利用できる根拠、完全なAPI応答契約との整合、単純な既存対照、必要作業・最終品質を保つ判定、制御費用を含む有限比較を別途固定する。成立しなければ通常の取得制御以上の追加提案へ進めない。P68を成功するまでやり直す用途にはしない。
