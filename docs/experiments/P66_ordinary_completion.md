# P66：公開記録による通常の逐次終了制御

2026年10月23日、P64/P65の終了後に固定する有限の開発比較。**既知写真文型の手書き検査を通常対照として実行し、自動完了の成否と仕事全体費用を測る。新提案手法ではない。**

## 削減対象と必要処理

P64の写真２条件は、P65の宣言済み検査条件が支持された後も各２生成・39,323／39,431 token、４回の公開ディレクトリ確認・１回の完了通知を使った。それを節約可能額と仮定せず、実際の逐次制御で確かめる。元集合・元日時・公開時計・全移動・名前保持の根拠は残し、判定と完了通知も費用に含める。

分析者が解釈した既知の１要求文型、平坦で完全な初期集合、全移動前の情報、同じ認証範囲、公開時計、成功した移動先と返却先の一致、上書きなしが前提。P62/P65の正規化と集合検査は変更しない。追加の保守的な入口検査として、時系列外・重複・不確定なイベント、未対応の他アプリ作用、すでに行われた完了通知を支持しない。根拠が不明・矛盾・未対応なら追加ヒントもAPIも送らず通常継続する。

## 条件と判断時点

- 既知 `34d9492_1` の文書取得必須／公開名アクセスをこの順で各１回。`P66_01_PHOTO_DOCUMENTED`、`P66_02_PHOTO_NAMED`。両方が同じ写真課題であり、独立２課題ではない。
- 新しいAppWorldの開始状態から解く。公開課題と初期13 DBハッシュをP29/P64と照合し、前回の解答・未来の応答・評価器の結果は入力しない。
- モデル、サンプリング、seed42＋生成番号、状態保持Python、可視スキーマ、能力案内、固定予算通知は対応するP64と同じ。最初の生成はcold、以降cached inputも全入力費用へ含める。
- **生成応答に含まれる全プログラム・APIの実行後、次の生成前**に、その時点の公開記録だけを点検する。同じ生成内の途中の移動完了では割り込まない。
- 支持がそろい、予算と時間が残っていれば、通常の `supervisor.complete_task(status='success')` をanswerなしで１回送る。既存ApiChannelの名前・引数・予算・時間・完了・不確定作用の制約を通す。モデル応答を捏造せず、別の `controller_api` イベントにする。
- 完了が実応答で確認されたら生成を終える。通知が拒否・不明・非完了なら残り条件も停止し、再試行しない。先にモデルが完了した場合は追加通知しない。

## 有限配分と停止

各条件80生成・450,000全入力＋全出力token・1,800秒、160 API（制御の完了通知を含む）。生成出力4,096、ctx65,536。各生成境界１回、最大80回の判定、各4,000公開イベントまで。判定・digest・保存・通知は条件の実経過時間に含む。純粋な判定＋digest時間も別記する。

全体最大160生成・900,000 token・320 API・２評価。初期化120秒、評価180秒、idle待ち60秒。所有worker4,800秒、所有推論器5,280秒、ready待ち300秒。停止ファイル `.runtime/P66.stop` とシグナルに従う。

課題予算・使用量不明／利用不能モデル応答による終了は、既知の世界を評価して固定順の次へ進む。不確定API作用、開始・実行・片付け・評価の失敗、制御による完了通知の失敗、出典・モデル変化、明示停止・所有プロセス期限は残りを停止する。失敗・不明・未実行を保持し、結果を見た再試行・条件置換・上限変更はしない。未確認使用量を０に補完しない。

## 比較と採否

対応するP64全体実行を、閉じた通常対照として使う。新生成が前回と同じになるとは仮定しない。全条件終了後に、実行した全生成の要求・モデルメッセージ、公開イベント・応答が元の同じ前半と完全一致したかを照合する。不一致の位置と種類も報告し、基準を緩めて一致扱いしない。最後の13 DBと非supervisorの保存ハッシュも比べる。DB内容・非公開個別テストは読まない。

全条件の公式成否、全入力＋全出力、API、生成、判定時間、初期化・片付け込み時間、推論器ロード・資源・停止を報告する。使用量が確定し両方の公式成否を保ち、全体tokenが対応する通常対照より減った場合に限り、この既知条件での局所的な削減として記録する。一方が悪化・失敗なら選択して一般採用しない。前半が一致しなければ、差全体を終了制御だけの効果にしない。前半一致でも各１回の後から選んだ既知課題であり、平均因果効果や一般的品質保証は主張しない。

通常の保持・集合検査・完了通知で十分かを確認する対照で、汎用の自然言語解釈や新しい証明方式ではない。保留12シナリオの閲覧０。最終目標は必要な仕事と品質を残した総費用削減であり、独自機構・採録に足る中心貢献は別に判断する。
