# P143: 共通8,192 token閾値での最終カバレッジ比較

2026-10-28、P142終了後、P143のモデル実行前に固定する開発計画。最終締切は本日15:00 JST。
P142の全8条件は両方式3/4成功、各572,405 tokensで一致し、第2機会の差分処置は作動しなかった。
これは処置の有効性を確認した結果ではない。作動範囲を調べるため、初回・反復の共通閾値を
16,384から8,192へ一度変更する。結果観測後の閾値選定であり、事前独立確認とは扱わない。

## 比較と対象

通常の再帰置換TRと、前回要約を保持し新規情報をobjectとして生成・ホスト併合するTDOを比較する。
両方式の発動閾値・初回要約・機会数・直近履歴・各種予算は一致する。第2機会の表現と
プロンプトの組の効果を評価し、個々の構成要素を分離した因果効果とは呼ばない。
旧controllerを変更せず、新しい派生controllerと独立trace検査がともに8,192閾値を使用する。

元の既知4課題をすべて使用し、seed157とworld seed42を再使用する。
奇数課題TR→TDO、偶数課題TDO→TRの固定順。順序・ホスト効果は除外できない。
未使用予約課題は読まず、全8条件を新しいP143名前空間で実行する。
P142を含む旧結果は置換・併合しない。閾値と作業時間の両方を変更するため、
P142との数値差を閾値変更だけの効果と解釈しない。

## 固定予算と締切

各条件actor/focus合算80呼出し、論理input+output 450,000 tokens、作業1,200秒。
環境API上限は課題順に160/80/80/80。拒否込み要約最大2機会、前回機会後3新規完了turn以上、
直近2turn保持。要約生成上限4,096 tokens、結合8,192文字、各フィールド32要素、
各要素2,048文字の制限を維持する。setup60、cleanup60、idle30、評価60秒。

8条件の最大予約11,280秒、batch11,400秒、readiness300秒、native preflight120秒、
activation30秒、server lease12,000秒。外側pipeline watchdog12,600秒は絶対期限を延長しない。
native preflightは初期8、focus4、要約後actor2の14件、生成なし。
最新起動10:55 JST、モデル絶対終了14:15 JST、集計・TeX/PDF完成期限15:00 JST。
全予算が入らない場合は起動せず、条件を黙って削らない。途中の科学的結果を見て条件を変更せず、
自動再試行・追加seed・追加閾値・P143後の追加実験を行わない。未完了・不明も8枠に残す。

## 集計と判定

主費用はactor/focus/失敗を含む論理input+output。cached inputも含める。
使用量不明は0で埋めず、完全合計はnull。主品質はactorへ戻さない独立公式最終評価。
全8条件の評価・使用量が揃い、audit errorなし、TR成功課題の成功喪失なし、
全4対と共通成功対の両方で総費用が減ることを開発上の有用性条件とする。
処置の採用判定にはさらに契約・会計の完全性、共通成功課題での実差分利用、
作動した比較のcanonical prefix一致を必要とする。strict prefixは別記する。
canonical一致は隠れ状態の同一性ではない。非作動例を処置効果として数えない。

既知4課題・単一seed・結果後に選定した条件での開発結果に限る。
一般的な精度維持、未使用課題への汎化、各構成要素の独立新規性、採択を保証しない。
結果が条件を満たさなければ原稿にもその限界を明記し、成功したように数値や結論を変更しない。
