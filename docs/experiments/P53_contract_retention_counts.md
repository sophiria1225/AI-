# P53：契約保持候補と単純対照の16入力だけを計数する

**終了：** 全16計数・86監査不一致０。使用履歴による２候補は配分基準未達で継続生成を見送る。一覧だけを残す単純対照は基準を満たしたが、品質・総費用は未検証。[全結果](../P53_findings.md)。

P52は文字数だけの点検だったため、トークンと削減余地を混同しないよう、全４既知境界で次の４入力を各１回計数する。全履歴、API・アプリ一覧を残して詳細だけ省く単純対照、使用後の詳細を省くP52候補、全引数名の観測も必要とするP52候補である。[固定設定](../../configs/P53_contract_retention_counts_v01.json)。

P29の全４課題・８応答後、P44と同じモデル・テンプレート・コードツール・元入力を使用する。全履歴の計数はP44の値と照合する。P52の２入力は保存したハッシュと一致するものだけを使う。一覧だけを残す単純対照は、同じ出自照合から詳細APIの区間を選び、使用履歴や後続成績を参照しない。

計16要求、180秒以内、所有サーバーの稼働上限600秒。生成・実API・コード再実行・評価器・保留群閲覧０。失敗時は再計数せず、その後を停止して全予定を記録する。計数後は所有サーバーを終了し、準備・待機も別費用として残す。

計算配分にはP44と同じ「２課題以上で初回入力を1,000 token削減」を用いる。基準未達で閾値を下げて主要比較へ進めない。達成しても総費用・品質・新規性の証拠ではなく、生成開始の自動許可でもない。標識と保持条件のメタデータも計数に含む。課題継続は行わないため、入力間の表現差を因果的な品質差として解釈しない。
