# P51：生成途中の使用量記録を合成入力で校正する

**終了：** v01は生成前の初期化失敗、v02は合成３生成を完了。既知554 token＋意図した切断の不明１回。52監査不一致０、所有サーバーは正常停止。[全結果](../P51_findings.md)。以下の固定条件は変更しない。

P47等では生成中の時間上限で最後の使用量が不明となった。今後の比較の測定を改善するため、既存の非ストリーム実装を変更せず、途中の計数と終端使用量を分ける受信器を追加する。これは計測基盤であり、新しい省費用方式ではない。[固定設定](../../configs/P51_stream_receipts_v01.json)。

**v01は初期化で終了、生成０回。** 検証関数の返却に含まれるPathを初期状態のJSONへ直接渡した実装ミスで、入力計数・モデル呼出しの前に停止した。サーバーは41.11秒稼働し正常停止した。原版・記録を残し、再実行しない。[失敗記録](../../reports/P51_stream_receipts_v01_failure.json)。修正版[v02設定](../../configs/P51_stream_receipts_v02.json)と[実行器](../../scripts/probe_stream_receipts_v02.py)は、出典をJSON可能な固定項目へ変換し、初期化失敗も保存する。３ケース全体・初期化失敗・生成後失敗の停止を結合検査した。生成結果はまだ観測しておらず、入力・モデル・順序・予算は変更しない。

固定モデル・推論器で、同じ合成入力を非ストリーム完了、ストリーム完了、途中切断の順に各１回だけ生成する。３生成、１入力2,048 token以下、出力枠128、論理token予約合計8,192以下、300秒。各回cache_prompt=false、seed 73、文脈65,536、KV q8を共通にする。生成内容の一致を仮定せず、差があっても反復しない。課題文や過去の修復結果を入力に使わない。

途中切断はサーバーの累積出力計数が４以上になった時点で行う。最後に受け取った計数は下限であり、切断後に生成された未受信tokenを含む終端使用量ではない。終端usageだけ受信してDONEを失った場合は、確定した費用を残し、メッセージを実行へ返さない。部分的なツール引数は実行しない。

固定版llama.cppの`prompt_n`は実処理入力で、論理入力全体ではない。`t_max_predict_ms`は生成段階かつ改行時の判定なので、タスク全体の厳密な時間上限に転用しない。`n_predict`の予約値を実測使用量へ置き換えることもしない。[原典と実装範囲](../stream_receipt_measurement_20261022.md)。

実API・生成ツールの実行・評価器・保留群閲覧０。予期しない失敗は以後を停止し、再試行や欠測埋めを行わない。最後の意図した切断後は単一slotの停止を30秒まで確認し、今回所有する推論サーバーを終了する。サーバー起動・待機・停止・メモリ費用も別に保存する。過去の不明使用量や停止規則は変更しない。
