# E0 初回観察仕様 v0.2への変更

2026年10月13日、v0.1単一実行の停止後、最終評価を見る前に変更した。v0.1の記録は保持し、今回の2方式比較と混ぜない。研究全体の開発費用には含める。

観測ID：`20261013_141028_single_4ba765`。11呼び出し、77,194トークン、約153秒で停止。最後の実測入力は13,770トークンだが、次の入力をJSON全体のUTF-8バイト数で70,179と見積もり、65,536のコンテキスト上限で停止した。修正パッチは空。入力長の過大推定によって、まだ使える実行枠を消した可能性が高い。最終成功やモデルの能力をこの結果から評価しない。

変更点は次の2つ。

1. 同じ担当が前回実際に入力した、変更されていないメッセージ列については実測入力トークン数を使う。追加メッセージだけをUTF-8バイト数とテンプレート余裕4,096で保守的に見積もる。前のメッセージ列が変わっていないことをハッシュで確認する。実測値での超過確認も続ける。厳密なトークナイザー等価性の保証ではない。
2. 各方式の総トークン上限を300,000へ変更する。11回時点ですでに77,194を消費し、入力が増え続けることが分かったため、20呼び出しの挙動を観察しやすくする。20呼び出し・15分・モデル・その他条件は変えない。

コード変更後、単一と固定分担を両方とも初期状態から実行する。途中の単一実行だけに条件を緩めた成績を比較しない。対になる固定分担の初回実行もこのv0.2で行う。

代替案の「上限検査を全廃」は採用しない。「ローカルtokenizerから厳密な事前計測」は有望だが、Ollamaの実際のチャット整形と一致するか別途照合が必要なため後続項目とする。「モデルを削除・入れ替える」は今回の停止原因に対処しないため保留する。
