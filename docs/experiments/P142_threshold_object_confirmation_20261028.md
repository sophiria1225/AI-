## 問いと比較

入力長閾値で要約する通常の再帰方式TRと、同じ閾値で差分を明示的な単一オブジェクトとして
生成し、前回の要約をホスト側で保持するTDOを比較する。両者はP141の実装を変更せず使用する。
第2要約の表現とプロンプトの組を比較し、個々の構成要素の独立効果とは呼ばない。
発動時機の比較、seed探索、閾値探索、新規課題の読み出しは行わない。

元の既知4課題を順番どおり使う。本P142の結果を観測する前にモデルseedを157に一度固定し、
world seedは42を維持する。seed157は過去の別cohortでも使用しているため、
未使用seedによる独立確認とは扱わない。奇数課題はTR→TDO、偶数課題はTDO→TRの順。
順序の無作為化やホスト・キャッシュ効果の排除は主張しない。
全8条件を新規実行し、P123/P139/P140/P141とは混ぜず、過去の失敗も置き換えない。

## 予算と締切

各条件はactor/focus合算80呼出し、論理input+output合算450,000 tokens、作業1,800秒。
環境API上限は課題順に160/80/80/80。要約は拒否も含め最大2機会、初回・反復閾値16,384、
前回機会後の新規完了turnは3以上、直近2turn保持。差分併合後8,192文字、
各フィールド合計32要素、各要素2,048文字の既存制限を維持する。

期限に合わせ両方式ともsetup60秒、cleanup60秒、idle30秒、独立evaluation60秒へ固定する。
作業時間は短縮しない。cleanupは実際の残時間に従って所有プロセスを閉じる。
8条件の予約上限は16,080秒。batch上限16,200秒、server lease18,000秒。
pipeline watchdog18,600秒は異常時の外側上限であり、モデル実行の絶対期限を延ばさない。
readiness900秒、native preflight480秒、activation60秒を予約する。
native preflightは初期8、focus4、要約後actor2の計14件で、生成は行わない。

最新起動時刻09:15 JST、モデル実行の絶対終了14:15 JST、集計とTeX改訂の期限15:00 JST。
期限超過を理由とした追加実験・自動再試行・途中の条件選別はしない。

## 判定と解釈

主費用はactor・focus・失敗・既知の拒否費用を含む仕事全体の論理input+output。
cached inputを引かない。使用量不明は0や推定値に置き換えず、完全な比較合計をnullにする。
主品質はactorに戻さない独立した公式最終評価。成功数だけでなく課題ごとの成功喪失を確認する。

開発上の採用条件は、全8条件が評価済みかつ使用量既知、audit errorなし、
TR成功課題の成功喪失なし、共通成功課題あり、全4対と共通成功対の両方で総費用減少。
さらに契約・会計が完全で、共通成功課題上で既知のobject focusと差分利用actorが存在し、
発動した比較のcanonical prefixが一致することを必要とする。
strict prefixも別に報告する。transport IDを正規化した一致は意味的・隠れ状態の同一性ではない。

これは既知課題での開発上の再現性確認に限る。一般的な品質保証、未使用課題への汎化、
新規手法の成立、レター採択をこの判定だけで宣言しない。
通常の閾値要約、差分更新、キャッシュを考慮した圧縮には既存研究・実装があるため、
先行研究との差異と研究意義は実験結果とは別に限定して記述する。
