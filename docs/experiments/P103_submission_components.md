# P103: 保存提出のコード構文と参照指定を分ける

## 問いと位置付け

P98の `syntax_actions_sha256` は、各run_pythonのコードを位置情報を除いたASTへ置換し、ツール名・順序・span_ids等の他引数を保持した提出列全体のhashである. Python ASTだけのhashではない. 現行稿の「構文が異なる」という表現をPythonコード自体の差と解釈すると範囲を広げるおそれがあるため、既知の全記録で内訳を確認する.

これは既存指標の内訳に対する事後解析であり、新方式、意味同値性判定、最終品質、費用削減の実験ではない. 元P98の値・採用基準・失敗・欠測を変更しない. P101の途中出力・使用量は読まない.

## 固定する対象と処理

元P98の全24実行・426生成枠、全60実行組・1,132対応位置を保持する. 元の33位置（提出構造が異なり、非空の実API列が一致）と37生成は、内訳を確認する既存の集合としてそのまま残す. 改善例の再選択や別反復での補充はしない.

各既知の保存応答を元P98のhashで読み、公開出力の構造のみを点検する. 既存の全提出hashと公開出力hashを再照合した上で、次を別々に保存する.

1. ツール名の順序付き列.
2. run_pythonコードのPython ASTだけの順序付き列. ASTの位置情報以外は除かず、変数名・定数・演算・文順を保つ. Python提出がない場合は比較可能な空コードとはせず、比較不可とする.
3. 各ツールのコード以外の引数の順序付き列. span_ids、read_spanの指定などを保持する.

コードと非コード引数の一致は別指標であり、コードの意味同値性や全状態同一性を意味しない. 他ツールを挟む位置の違いはツール名列・引数列へ残す. 不明応答、無提出、不正JSON、不適合インタフェース、構文不正を補完しない.

全対応位置で元指標との整合を確認し、元33位置をPython AST列が異なる、Python AST列が同じで他要素が異なる、Python AST列が比較不可に分類する. 各群について重複を除いた生成数・実行数・既知課題数と、元のAPI前史一致の範囲を併記する. 組数を独立標本数としない.

## 上限と停止

読取専用で１回、180秒、ファイルごと16 MiB、応答426枠以内. 新規モデル生成・API・保存コード実行・評価器・課題DB参照・予約評価群の参照は全て０. 元の応答hashまたは構造集計との不一致で停止し、失敗記録を保存する. 生のコード、認証値、完全履歴、内部推論の意味内容を公開しない. 公開成果はhash、件数、各比較位置の指標とその定義である.

P103実施前には、37生成を「Python AST自体が異なる37生成」と断定しない. 現行稿の記録は保持し、内訳に応じて次の版で表現と件数を正す. この確認の結果が中心主張を弱める場合も残す.
