# P68：CSVの通常終了と公開証拠による終了制御をそろえて比較する

2026年10月23日、P67の全３記録の読取点検後に固定する。必要な作業と最終品質を保ち、終了までの全体費用を減らすという研究目標に対する、写真以外の既知１文型の通常制御の点検である。独立確認、新しい要求解釈器、証拠付き終了の新方式とはしない。

## 対象と介入

同じ既知課題 `6104387_1` を初期状態から２回、新しい通常native実行／同じnative＋外部終了制御の順に各１回実行する。モデル、seed42からの連番、一般案内、静的予算通知、公開スキーマと発見手順、履歴ページサイズ、入力計数、出力予約、最初のcold cache条件をそろえる。

P25の初期公開要求・13保存ファイルのハッシュだけを初期同一性の参照にする。未来の応答、過去の解法・CSV内容、件数72、評価器の判定をモデルや制御の入力へ渡さない。通常対照の結果を見て２番目を変更しない。P25の古い動的通知を再現する比較ではなく、P68内の同じ静的通知を比べる。P25の後続41,702 tokenを実測節約額として扱わない。

制御あり条件のみ、各モデル応答に含まれる**全native呼出しの実行後**に、現在までの公開記録を変更せずP67検査器へ渡す。全ページ、元IDの和集合、メタデータとCSV内容、正しい書出しの後の退会が支持される場合に限り、既存ApiChannelから `supervisor.complete_task(status="success")` を１回送る。answerは省略する。退会を含む要求作業は全てモデルが行い、制御は退会の代行・許可をしない。

不明・矛盾・未対応の場合は追加案内なしで通常継続する。支持があるだけでAPI予算や時間を越えず、完了返却を確認してから終了する。不確定な完了作用・失敗は再試行せず、その条件と残りの予定を止める。モデルが先に完了した場合には制御を実行しない。通常対照には監視処理も追加しない。

## 有限予算と全件保持

各80生成、全入力＋全出力450,000 token、1,800秒、80 API（制御の完了通知も含む）、出力上限4,096、context65,536。２条件合計で最大160生成・900,000 token・160 API・２評価。準備120秒、評価180秒、idle60秒、worker4,800秒、所有推論器5,280秒、ready300秒。制御は各80境界・4,000イベントまで。元のP67容量・文型・意味は変更しない。

使用量はSSEの終端記録と事前計数を照合し、cached inputも主費用に含む。未知使用量や利用不能な応答は実行せず、再試行しない。既知の予算終了・利用不能生成で作用と片付けが確定していれば１回評価して次の固定条件へ進む。設定、初期状態、推論器、API作用、実行・片付け・評価の不一致は全体を停止する。未実行・失敗・未知費用を置換や補完しない。

同じseedでも要求・モデル応答全文の一致は仮定しない。全要求・応答、実API前半、最終13ファイルを照合し、不一致と呼出しIDだけの差も保存する。全文一致を事後に正規化して合格へ変更しない。P66で既にID差があったため、P68の下記の局所採用基準に全文一致は含めず、反復された因果効果とは呼ばない。

## 事前の局所採用条件

両方が評価済みかつ公式成功、全使用量既知、監査不一致０、最終13保存ファイルが全て同一で、制御ありの全体論理tokenが通常対照より小さい場合に限り、この既知文型の通常対照部品として採用する。条件を満たさない場合も全結果を報告する。公式成否・ファイル一致は観測範囲の指標で、外界の真実・一般的品質の保証とはしない。

制御の判定・digest・保存・完了通知も全時間に含め、判定部分の時間を別記する。API、setup、評価、推論器ロード・常駐・最大観測RSSを別記する。成功率の一般化、未閲覧12シナリオの選定、P55主表への合算はしない。

## 実装と検証

[固定設定](../../configs/P68_export_completion_v01.json)。`export_completion_control.py`はP67の変更していない検査器を包み、既知使用量・連続した境界・未完了を要求する。`run_export_completion.py`は通常native呼出しと明示的controllerイベントを分ける。監査は各時点の履歴・公開ツール・判定を再構成し、未来の情報で判断していないことを照合する。

合成検査で、書出しだけでは終わらないこと、退会後でも同じ応答内の後続変更があれば終わらないこと、API予算、失敗・不明作用の無再試行、通常対照への監視混入、未来のスキーマ・判断の混入、未知費用・失敗・状態差の採用拒否を確認する。全検査、固定コミットのpushとPRのworkflow／job成功後にだけ、別作業木で実行する。
