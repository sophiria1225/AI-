# P33：実行の手掛かりを残して、長い出力だけを省く

2026年10月22日。P31/P32の全結果と[費用内訳](../cost_profile_20261022.md)を見た後に設計する開発比較であり、確認用実験とはしない。12保留シナリオは使わない。

目的は、入力削減のために会話ターン全体を消す必要があるか、また状態の可視化を加えると再取得や追加生成を減らせるかを調べること。最終性能を維持した総費用削減という目的に直接対応させる。通常の観測省略と状態一覧を独自技術とは呼ばない。

| 条件 | 操作・コード | 古い標準出力 | Python | 一覧の追加 |
|---|---|---|---|---|
| full_keep | 全て保持 | 全て保持 | 保持 | なし |
| stdout_mask_keep | 全て保持 | 対象を明示して本文だけ省略 | 保持 | なし |
| stdout_mask_index_keep | 全て保持 | 同上 | 保持 | 変数名・型・件数・既取得API名 |

元の４課題の８応答後から全12分岐を各１回実行。３条件を課題ごとに巡回して順序を変える。全履歴対照も同じ実装・説明で新しく実行し、過去の最もよい試行を対照として選ばない。seedは元の42＋境界８を起点とする。

対象は最後の１ターンより古い、成功した`run_python`の長い標準出力。置換で長くなる短い返却はそのまま残す。エラー・未知の作用・完了宣言がある返却を対象にしない。コード、返却の状態、エラー、切り詰め情報、API記録のIDは残す。省略を空出力・未実行・正しい完了へ読み替えない。原記録は全条件に同じ再読手段を残し、変更しない。

これは一度だけの省略であり、その後の出力を毎回削る方式ではない。固定地点で入力情報の構成を切り分けるためである。一覧は境界での利用可能性を表すだけで、重要な変数・正しい値・後続でも有効な状態だという判定ではない。一覧の作成は隔離した実行環境で値を出力せず行う。

後続は16生成・12万総トークン・480秒。API上限は写真160、その他80で共通前半を含む。一覧作成と入力整形の時間も後続480秒に入れ、追加入力も計上する。復元のAPI・時間は実験準備として別記。新たな要約LLM、モデル変更、API結果キャッシュは加えない。

実行前に全４前半の公開返却・DB・Python再生と、３条件の入力構成を照合する。対象や地点が不適格なら勝てそうな別地点へ置換しない。独立評価は終了後に実施し、生成器へ返さない。途中の成績による上限増額・試行追加はしない。

主に全履歴対照と省略、次に省略と一覧付き省略を比較する。全４課題の成否、総入力＋出力、キャッシュ、新規入力処理、呼出し、API、再読、作成費用を残す。全履歴で成功した課題を落とす、または総トークンが減らない場合は品質維持を満たす削減候補として進めない。使用量不明があれば厳密な削減率を確定しない。この条件を満たしても、４件各１回から非劣性・一般化・新規性を証明したとはしない。

一律の直近ターン化では操作の手掛かりも消えるため、次の対照には採らなかった。意味要約は追加生成費用が必要で、まず安価な出力省略を試す。変数一覧は既存の強い対照を作るためであり、準備済みコードがあったから研究の中心に選んだわけではない。結果から通常方式で足りない具体的条件を絞り、その条件に対応する選択制御を検討する。
