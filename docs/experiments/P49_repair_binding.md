# P49：修復の変更境界の実装と、既知拒否への適用点検

2026年10月22日。P48で名前変更・型変換・未公開APIを区別した結果を受け、[値を保持する部品](../request_repair_binding.md)を合成例で検査し、同じ全12予定条件の10拒否へ適用できる範囲を点検する。既知の失敗後に選んだ開発作業であり、新規性・効果の確認実験ではない。[固定設定](../../configs/P49_repair_binding_v01.json)。

元の拒否、その時点で公開済みの原契約、元の要求だけを使い、後続の要求から修復案を逆算しない。全条件と全拒否を残し、未公開・未送信と確認できないもの・未対応制約も集計する。引数値・原コード・認証値は出力しない。生成入力の構成と型制約上の対応可能性だけを測り、API・Pythonは実行しない。

合成検査では、既存の公開引数の保持、衝突・省略・型変換・API変更・古い要求や契約の拒否、ローカル同時提案の１回制限を確認する。実記録では入力文字数、適用・拒否理由、空契約の正規化候補、完全な名前対応の有無を全件記録する。型上の候補を意味的に正しい修復とせず、入力文字数をtoken節約へ換算しない。

実記録点検は120秒以内、追加生成・実API・コード再実行・評価器・計数・保留群閲覧０。新しいモデル実験を自動開始しない。適用範囲が狭い場合はそれを明示し、実装を先に複雑な再開器へ拡大しない。
