# P21補助評価：生成コードが入力を扱っているか

2026年10月21日、P21の全６生成が終わる前に設計。途中の生成本文・コード・CSVは未閲覧。主実験の入力、指示、生成順、上限、判定方法は変更しない。

## 目的と位置づけ

１つの観測パケットで正しいCSVを作れた場合にも、入力への依存が正しいとは限らない。たとえば、対象IDを選別せず全メタデータを集めるコードは、今回の元データ上では偶然正解になり得る。その区別を付けるため、全生成終了後、提出されたコードを４種類の入力変換で再実行する。

これは分析者が課題に合わせて定義した補助検査である。メタモルフィックテスト、自律的な仕様生成、新しいハーネス方式の発明を主張しない。[ARMeta著者原稿](https://arxiv.org/html/2605.28321v1)のIII-A〜B節も、入力変換と出力関係を使ったAPIの検査を扱う。今回はモデルに関係を生成させず、保存データだけを変換する。実APIや実環境の状態は変更しない。

## 事前に固定する４条件

| 変換 | 期待する結果 | 主な確認対象 |
|---|---|---|
| 観測順・一覧順・参照ID順を逆にする | 行順を除いた内容が同じ | 観測位置への依存 |
| 同一の観測パケットを２回並べる | 行数・内容が同じ | 重複の除去 |
| どの取得元一覧にも属さない曲の詳細を１件追加 | 出力に加わらない | 対象範囲の選別 |
| 固定規則で選んだ対象IDの曲名を、全観測で一貫して変更 | その１行だけが変更される | 固定文字列の出力との区別 |

対象IDの選択は型名とJSON表現の辞書順先頭とする。P18で欠落した行やP21の出力内容では選ばない。元データ中に同じIDの異なる曲名・アーティスト情報があれば、静的データという前提を満たさず、この検査は適用しない。対象が空、出力項目が衝突、未観測メタデータがある場合も適用しない。

## 実施・集計規則

- 全６生成の完了と主評価の監査後に実施する。主評価に合格したコードだけを選ばず、形式に適合して提出された全コードを対象にする。
- 新たなLLM呼び出し、コード修正、再提出は行わない。変換ごとの失敗と実行費用を全件残す。
- CSV文字列の提出方式は入力を再実行するプログラムではないため適用外。これを失敗扱いしてコード方式と成功率を比較しない。
- 未提出・打切り・形式不適合も母数に残し、補助評価の対象外である理由を記す。元入力での主評価結果を上書きしない。
- 人工的な変換４件は４つの独立した実課題ではない。合格しても一般的な正しさや未知領域への転用を証明しない。

## 採らない案と理由

生成結果を見てから苦手な変換だけを追加することはしない。主評価の途中で失敗情報をモデルに返すと、生成予算の比較が変わるため行わない。コード方式だけへ正解の集合や対象件数を渡す案も採らない。検査コードを実行器へ接続しただけで新規性が得られるとは扱わず、既存方式との機能差は別に検証する。
