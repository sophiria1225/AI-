# P39：比較時の推論状態を校正する

P38の閉鎖後、同じ初回入力・seedでも生成が異なり、入力の実処理量も違ったため行う。新しい研究方式やP38の再試行ではなく、今後の比較条件を整える検査。元の実験成否を変更しない。

固定版[llama.cpp公式README](https://raw.githubusercontent.com/ggml-org/llama.cpp/620d2225cc436ab0b001e3200e590e3b286ef9ab/tools/server/README.md)の`cache_prompt`と`/slots/{id_slot}?action=erase`を確認。接頭辞の再利用時には実処理が変わり、バックエンドやバッチサイズによって数値的に同一の出力を保証しない旨がある。これを今回の原因の証明とはせず、実機条件を確認する。

P38の初回要求を一つ固定し、最大生成長だけ256 tokenへ変更する。全６呼出しの要求本文・モデル・seed50・サンプリング・`cache_prompt=true`は同じ。順序は空１、保持１、保持２、空２、保持３、空３。空条件の直前に非稼働スロット０のキャッシュを消去する。保持条件は直前の同じ入力の呼出し後、そのまま実行する。重み・入力・量子化を変えない。

状態の実測確認は、空条件の`cache_n=0`・入力全体の実処理、保持条件の`cache_n>=入力数-1`とする。確認できなければ固定条件が成立しなかった結果として止め、消去方法や順序を途中で変えて再試行しない。モデルが生成したツール操作は実行しない。AppWorld・最終評価器・未閲覧群を使わない。

上限は６生成、計10万token、１呼出し240秒、全体1,560秒。入出力・使用量・timingを保存し、不明使用量を０にしない。試行の前にモデルの固定版、非稼働１スロット、サーバーの残り稼働期間を確認。終了時にスロットが非稼働なら消去し、次の実験へ保持状態を残さない。外部ジョブを停止・再起動する処理は入れない。

生成テキスト・引数・推論出力の一致をハッシュで比較し、転送用tool-call IDだけを除外する。同じ群の３回、群間９組を記述的に示す。長い課題の性能・普遍的再現性・数値差の詳細な原因は、この短い検査から結論しない。各呼出しのキャッシュ実測値と全費用を合わせて公開する。

再試行して都合のよい出力を選ぶ、生成差を新規性とする、全課題を再実行してから原因を調べる案は採らない。今後は、各分岐の開始前に同じ推論状態を設定し、分岐内のキャッシュ再利用を共通化する方針を候補とする。検査結果に応じた規則は、既存の結果と区別して版を付ける。
