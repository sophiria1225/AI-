# E0 生成上限の適合確認 v0.3

2026年10月13日、v0.2の公開実行ログを根拠として、最終評価前に設定変更を決めた。新しい手法の性能調整ではなく、同じモデルを比較可能な状態で動かすための開発確認。

観測：固定分担の15呼び出し時点で、7・8・11・13・15回目は`done_reason=length`、出力1,536、ツール呼び出し無しだった。思考とツール要求を含む一回の生成枠が不足し、実際の操作へ進めないケースがある。単一も20回で編集のAssertionErrorから回復できず、パッチは空だった。現時点で、これを分担固有の害やモデル一般の限界と判定しない。

変更する実行設定は、`num_predict`を1,536から4,096にすることだけ。両方式のモデル、温度、seed、コンテキスト、総トークン300,000、20呼び出し、15分、1呼び出し120秒、ツール45秒、タスクを維持する。条件ファイルを明示して実行できるようCLIに`--config`を追加するが、戦略やプロンプトは変えない。

追加は単一1回・固定分担1回まで。両方を初期状態から始め、ローカルモデルを順に呼ぶ。旧試行を削除しない。設定版ごとに成否と費用を示し、全開発費用には旧試行も含める。この追加でもうまくいかなくても、同じ課題を成功するまで無制限に繰り返さない。

代替案：thinking無効化は、推論設定も変えてしまうため今回は選ばない。モデル交換は、まず既存モデルが生成枠で止められている問題を分離してから考える。呼び出し数・総予算の増加も同時には行わず、変更理由を一つに限定する。

この課題・設定はすべて開発用。最終評価を見て調整した未調整テスト性能としては扱わない。公開ベンチマークである以上、モデルの学習由来の既知性を排除した評価とも言えない。
