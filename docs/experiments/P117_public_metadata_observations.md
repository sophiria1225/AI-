# P117: 再送観測と固定公開API仕様の全件照合

2026年10月25日. P116の結果を知った後に固定する有限診断. 精算の非再入力条件で18,446文字の観測が18回表示されたため、ハーネスの公開API仕様を表示し直したものかを調べる. この１件だけに絞らず、P116全16条件・283要求・263観測出現を保持する. 成功・未達・未知使用量２件の扱いは変えない.

新しい読取対象は各条件のevents/spansと全保存request、合計315私有ファイル. P116の固定指紋から選び、内容を変更しない. 公開API仕様は既存AppWorld配布物のfunction_calling/standardから読み、元の公開ファイル指紋へ照合する. task DB、評価器の内容、未見12課題には触れない.

各tool messageと原spanの観測が一致することを確認する. ページ表示、不一致、解析不能を残す. stdout全体を最大65,536文字、20,000 AST node・深さ24など既存の有限literal認識器で検査し、完全なJSONまたはPython literalだけを扱う. 部分文字列を取り出さない. 値が完全な公開関数仕様、その名前付き辞書、または完全な仕様のリストに全要素一致する場合だけを数える. 変更された説明や課題データを含む混合物は一致にしない.

公開仕様の表示済み範囲は、原記録の初期公開名とnew_toolsから復元し、当該プログラム終了時までに露出していたかを別記する. 生成コードは構文としてapi_schemas名のLoadと直接print構文の存在だけを数え、実行せず、rawコードも公開しない. 同名変数を読み込む構文は実際のデータフローの証明ではない. 値が公開仕様と一致しても、由来・意味的不要性・安全な省略は認定しない.

全再送回数はP116のmessage指紋・入力内出現番号・初回位置と照合する. 文字数とnative tokenを区別する. stdoutを空にした際のcompact JSON文字差は、原記録自体が同じcompact形式である場合に限り表示上の内訳へ使う. 実際の要求や記録を書き換えず、生成にも使わない.

上限180秒、１ファイル16 MiB、私有入力合計512 MiB、１要求1,024 messages、自動再試行０. 全16条件・283要求・263観測の枠を先に保存し、未処理・失敗も残す. ソースと入力指紋をcommitし、同一headのpushとpull_request両workflow・両accounting-and-syntax job成功後に一度だけ処理する. モデル生成・API・生成Python実行・評価・tokenizerは０. 出力先が存在したら再実行しない.

新方式の採用や一般的品質維持の実験ではない. 既存P34/P55/P71/P106と近接研究を引き継ぎ、単なる仕様照合や文書省略を新規性へ数えない. 原稿保留と未見群の分離を維持し、この計画から次のモデル生成を開始しない.
