# P75：通常対照の推論履歴を保存記録で確認する

2026年10月23日、読取点検前の固定範囲。必要な情報・処理と最終品質を保ち、仕事全体費用を減らすという研究目的に対し、現在の「全履歴」の範囲を明確にする。モデル比較を追加する前の通常対照の点検であり、新提案手法ではない。

## 既存条件と確認する理由

[P10の計画](P10_native_history.md)は、公開されたassistant content・呼出し・観測を保持し、`reasoning_content` を再投入しないと明記していた。`NativeConversation.append` はその条件を実装している。P71も同じ会話部品を使う。従って、発見した不具合として過去の結果を修正するものではない。「全履歴」は全ての私的な推論まで保持した対照を意味しない。

一方、固定されたlocal adapterは `reasoning_content` の送受信を扱い、P73で保存した実際のM3テンプレートは、与えられた各assistant turnの同フィールドを描画する。生成時にthinkingを有効にすることと、過去の出力を次の入力へ保持することは別の条件である。`preserve_reasoning` という設定名だけでは実際の履歴内容を証明できない。

原典の範囲も分ける。MiniMaxの[2025年M2の記事](https://www.minimax.io/news/why-is-interleaved-thinking-important-for-m2)は推論の持越しを推奨し、M2の比較値を示す。現在の[関数呼出しガイド](https://platform.minimax.io/docs/guides/text-m3-function-call)は完全な応答の保持を推奨するが、本文の対象はM3.1-Flashである。旧M2のURLからこのページへ転送されたことも確認した。これらを今回の量子化M3の効果量や必須条件の直接証明にしない。[M3のモデルカード](https://huggingface.co/MiniMaxAI/MiniMax-M3)のthinking modeの説明も、履歴保持による品質改善の実測ではない。今回の直接の根拠は固定されたローカル実装と保存入力である。

## 全件の固定範囲

[計画JSON](../../configs/P75_reasoning_history_v01.json)の16群を順番どおり読む。

- P29の既知４課題から、P71が共通前半として使った最初の８回ずつ、計32回。
- P71の全12条件・継続73回。うち終端使用量不明２回も除外しない。
- 計105回の保存requestと解析済みresponseだけを対象とする。原usageは一覧とhashを確認する。P29の９回目以降は対象外。

各入力のassistant列を、それ以前に実際に得られた同条件の応答へ順序付きで対応させる。P71の入力には同課題のP29最初の８応答だけを前置する。content・呼出しの公開値が一致するかを確認し、推論フィールドの有無・非空・文字数とinline tokenの有無を集計する。意味内容は分析せず、私的な文章・ツール引数・観測は公開reportへ含めない。不明使用量の応答を空の正常応答として数えない。

既存の入力に推論フィールドがなければ、対応する過去応答から同フィールドだけを付けた場合の文字数を検算する。この構成物はモデルへ送信・保存しない。文字数はtoken数でも節約額でもなく、累積入力の文字数には同じ過去応答の再掲が含まれる。

## 別部品の実装と検査

`ReasoningConversation` は従来部品とは別の任意選択の通常対照である。返却された文字列・空文字・null・欠落を区別して保持し、生成・選別・要約は行わない。不正引数の文章への代替表示にも同じ推論フィールドを保持する。型不正や観測対応の不備では履歴を途中まで追加しない。公開観測の成否を変えず、推論を実行済みの証拠に使わない。

過去の部品・実験config・結果は変更しない。合成検査で、既存動作、失敗記録、ページング、非公開文字列の非出力、誤対応、未来応答の混入につながる個数不一致を確認する。対応の一致は未来情報を使っていないことの十分条件ではないため、読取器は固定された時系列からしか前半を構成しない。

## 予算・停止・判断

固定commitのpushとPRの両CI/job成功後、清浄な別作業木で１回だけ実施する。上限120秒・１ファイル8 MiB。モデル生成・tokenizer・環境API・評価器・保存コード実行・DB内容・保留12課題の読取は全て０。

元ファイルのhash・型・時系列対応の不一致、期限超過では部分結果を保存して停止し、再試行や対象除外で合わせない。全105回をreportへ対応させる。過去の全成否・費用・不明２回は維持する。

非空の過去推論が保存入力から除かれていると確認できれば、保持する通常対照が未検証であるという制約を明示する。これは品質低下の原因や、保持すれば改善することの証明ではない。新たなモデル比較を行う場合は、別計画で全条件・順番・有限予算・費用・品質・欠測基準を固定する。今回の部品を追加しただけでは、その比較を開始しない。
