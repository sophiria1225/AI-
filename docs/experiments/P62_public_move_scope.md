# P62：公開の移動記録で終了条件のどこまでを確認できるか

P55写真整理のF/D/B全３条件を対象とする読取専用の事後点検。P57の「最後の書込後」という会計上の境界を、そのまま安全な終了条件にできない理由を、具体的な公開の要求へ対応させる。P61終了後に選び、実装前に公開要求とAPI回数・作成日時の年別件数を点検した。事前登録された独立検証ではない。

分析者が、既知の一つの要求文型を対象集合・元の作成日時・今年の２月／３月・その他の行先・元ファイル名の保持へ分解する。契約の解釈をモデルが自律生成したことにはしない。対象は平坦な元ディレクトリ内の全ファイルを扱えるこの既知例だけで、任意の自然言語や混在ディレクトリの一般的な完了判定ではない。

公開の `show_directory` は未絞込み・再帰ありの完全列挙として、`show_file` は移動前のID・パス・作成日時として、成功した `move_file` は元パス・先パス・返却先パスとして読む。同じ資格情報の範囲、全元集合、重複、上書き、ファイル名、月と年による振り分けを区別する。API実装による列挙・作用の意味と、記録アダプタが正しいことを前提とした通常の照合であり、外界の真実を証明するものではない。

現在年は実際に送信され成功した公開の時刻APIだけから得る。モデルが書いた年、ホスト時刻、最新ファイルの年、成功した移動先からの逆算、公式成否は代用しない。元の作成日時の各年と「それ以外」の年で振り分けの一致を条件付きに計算しても、一致した年を観測済みに昇格させない。APIが移動後の日時を変更し得るため、元の条件に使う日時は移動前に固定する。

元監査で固定された公開要求・イベント・返却・使用量・出典のSHAを照合し、全生成境界を順番に点検する。送信しなかった形式拒否は実行に数えず、作用不明や記録不一致があれば停止する。元のP55成否、不明費用、P56介入結果は変更しない。

上限60秒、３既知条件、モデル生成・入力計数・環境API・評価器・DB読取・保留群閲覧０。生成プログラムや保存コマンドを実行しない。現在年を新たに取得する、完了APIを追加する、再実行で成功を探す、という処理は含まない。公開する結果は件数・支持の範囲・元の成否・出典ハッシュだけで、資格情報・ファイル内容・具体的な個人パスは含めない。

不明が残れば、新しい自動完了器として接続しない。通常の契約・証拠検査との重なりを維持し、検査器ができたことや既知の結果を説明できたことだけでは新手法・節約効果の成立と判断しない。
