# P17：台帳インターフェース修正の校正

2026年10月21日。P16終了・内容判定・不適合監査の後、新しい生成の前に固定する。基準実装の修正確認であり、新規方式の性能実験ではない。原稿目標はユーザー訂正後の２段組４ページ、10月31日投稿。

## 修正の理由と比較

P14/P16では、モデルに空出典を許した定義を渡す一方、受取側は拒否していた。要求文の出典IDも未登録だった。[全監査](../memory_contract_correction_20261021.md)。この不整合を残して台帳の有効性を判断しない。

- `legacy`：P16と同じメッセージ・ツール定義・受取検査。
- `aligned`：出典最低１件、利用可能IDの列挙、空でないキーを宣言し、同じ出典集合で検査。要求文を`task`として登録し、要求は操作実施の証拠ではないと明記。追加の正解情報・操作・検証LLMは与えない。

両者の前半の課題情報、操作履歴、API仕様は同じ。整合版は対処をまとめた修正であり、個々の変更の因果寄与を分離した実験ではない。元の定義を後から変更せず、旧成果物を不変で保持する。

## 固定する範囲

P16で使用済みの記録通りの４入力を全て使う。拒否の人工条件や表示分離は今回扱わない。課題を入れ替えず、４入力×２版×新しいseed 47・48＝16生成。入力ごと・seedごとに先行する版を交互にする。seed一致による完全再現は保証しない。

M3 IQ4_XS、64K、KV q8_0、単一推論スロット、温度1、出力上限4,096。総予算50万トークン、３時間、16呼出し。入力計数でコンテキストと総費用の上限を確認してから開始する。使用量不明、モデル・ソースの変化、実行環境の期限不足では停止し、同じ試行を成功まで再送しない。

測るものは、台帳全体の形式適合、空・未登録出典、定義外状態、全生成費用。全16出力終了後に内容を確認する。要求IDが付いたから完了の証拠があるとは判断しない。既存のP16判定を変更したり、形式適合したものだけを成績の分母にしたりしない。

## 次へ進む条件

整合版で形式適合が得られ、要求と観測を取り違える完了項目が増えていないことを確認してから、全タスク実行の基準候補へ採用する。４課題・２seedで一般優位を主張しない。新たな自然な失敗があればその原記録から次の仮説を立て、修正で消える問題を新規性にしない。

空出典へ既存spanを自動で付け足す、無条件に受理する、旧結果を修正後の結果として書き換える案は採らない。個別の出典補完には意味判断が必要であり、形式を通すだけでは根拠を増やせないため。
