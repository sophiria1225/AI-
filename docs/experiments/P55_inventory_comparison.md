# P55：API一覧と詳細を分けた表示比較

2026年10月23日。P47・P53・P54の全結果を見た後の開発比較。新しい制御アルゴリズムの実証ではなく、金曜の主張を絞るための一度の比較とする。独自の中核と品質を保った総費用削減は未確立。

## 問いと３条件

P47ではAPI説明を省くと写真の成功を失い、後からの公開契約返信でも回復しなかった。原因がAPI一覧の省略か、詳細の省略か、その他の行動変化かはまだ分からない。P53では一覧を残す通常対照だけが初回削減の配分基準を満たした。ここから「一覧は必要、引数詳細は省ける」と結論せず、全４既知課題を同時期の３条件で比べる。

| 条件 | 古い引数詳細 | 古いアプリ／API一覧・説明 | 共通条件 |
|---|---|---|---|
| F：全表示 | 保持 | 保持 | Python状態、原アーカイブ、公開契約返信、予算通知を保持 |
| D：詳細を省略 | 出典を照合できた部分だけ省略 | 保持 | 同上 |
| B：詳細と一覧を省略 | Dと同じ返却を省略 | 出典を照合できた部分だけ省略 | 同上 |

認識器はP44の固定実装を使う。操作、タスク要求、リテラル、混合／不確かな出力、最新の完全な応答、api_docs・supervisor自身の詳細は保持する。D/Bの省略印とメタデータの規則を共通化し、入力に条件名を加えない。短縮判定の影響で省いた詳細の集合がD/Bで異なる場合は、生成前に停止する。情報はPythonとアーカイブに残るため、「情報が存在しないこと」の検証ではない。

生成前の全４境界の照合で、詳細の省略対象は写真７・電気代２・返金３・書出７返却となり、D/Bで一致した。一覧の省略対象は各１・１・０・３返却。返金には追加で省ける一覧がなく、D/Bの基礎入力が同一となる負の対照である。ここで行動差が出ても一覧の効果とは解釈しない。時間通知、数値計算、実行順の残る揺らぎを含めて記録する。

## 固定する対象・予算・停止

- 元のP29全４課題、８応答後。写真・電気代・返金・書出の各３条件。すべて既知の開発対象で、未閲覧12課題は開かない。
- 順番は FDB / DBF / BFD / FBD、各１回。元と同じモデル、seed=元seed+8から応答ごとに加算。初回cache_prompt=false、既知応答でcache_n=0を確認。後続はtrue。
- 各条件：16生成、120,000継続総token、480継続秒、最大4,096出力、65,536 context。残りtokenから全入力を引き出力枠を制限する。APIは前半を含め写真160・他80。状態復元600秒、評価180秒。全12条件で最大192生成、予約枠1,440,000 token。予約を実消費とは呼ばない。
- 全12入力を再計数し、Dの初回削減が２課題以上1,000 tokenを満たす場合だけ生成。P53よりモデル表示用メタデータを統一したため、新しい数を保存する。共通の予算通知も計数に含む。
- 各実行は独立した子プロセス。復元＋継続＋片付けの上限を親からも監視し、超過ならその実験を停止する。最大６時間の専用モデルサーバーは全段階を囲むfinallyで停止する。

### 使用量不明と最終状態の評価

P47は生成の使用量が不明になった時点で全体を止め、当該状態の評価も行わなかった。P55は事前に次を区別する。モデルの使用量不明なら、その条件の生成を終了し、再試行しない。API効果が全て既知で片付けが成功した場合だけ、同一サーバーが60秒以内にアイドルへ戻ることを確認し、保存した最終状態を一度評価して固定の次条件へ進む。部分応答は実行しない。

不明使用量をゼロ・上限・推定値で埋めず、費用合計は「既知分＋不明件数」。いずれかが不明なら費用の採用基準は未達。API効果不明、復元不一致、既知応答のcache違反、その他の実行／片付け／評価失敗、サーバー版や期限の不一致、ユーザー停止では全体を止める。残りを成功・失敗に補完しない。P47の旧結果をこの規則で評価し直さない。

## 判定と論文に使う範囲

主要比較は D−F と D−B。独立評価器のタスク成否と、共通のP29前半実測token＋継続全入力出力tokenを比較する。継続だけの数も併記し、割合の分母を明記する。API、制御・計数・生成・実行時間、復元、評価、モデルロード・常駐、失敗も記録する。省略時の初回入力だけで総費用を判定しない。

全12件を評価・監査でき、使用量不明０、DがF/Bいずれに対しても対ごとの成功を失わず、仕事全体の合計tokenがFより少なくB以下の場合だけ、既知課題におけるDの採用候補とする。さらに一覧保持の利点を支持するにはD成功／B失敗の対が必要。同数成功は非劣性の証明ではない。４課題×３条件は独立12課題ではなく、反復seedも独立課題に数えない。

既知結果に着想した仮説であり、確認評価や統計的一般化として扱わない。成功すれば通常方式の追加価値の候補、失敗すれば限定仮説の不採用という判断を残す。「圧縮は失敗することもある」だけを新知見としない。表示以外の経路でAPI一覧が参照され得るため、API認知の内面状態や単一の心理的原因まで断定しない。

固定実装は新規の `inventory_display.py`、`run_inventory_branch.py`、`run_inventory_comparison.py`。P47等の実験コードは変更しない。共有実行部品のP47合成コンテナ検査は同一SHAを確認して再利用し、新しい表示・欠測の扱い・全12順番を検査する。
