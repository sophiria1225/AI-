# P52：使用前のAPI契約を残す候補の適用範囲

P47の一律の仕様表示省略は採用しなかった。次の候補として、**APIやアプリの一覧は保ち、詳細契約は観測された使用履歴を条件に省略する**規則を既知記録で点検する。P47の再実行や上限変更ではなく、生成を伴わない入力候補の構築である。

対象は元のP29全４課題・８応答後だけ。P44の23出力候補と出自照合をそのまま用いる。出自が未確定の混合出力、最新応答、リテラルの見出し、作業値、元コード、会話、API・アプリの一覧を残す。仕様の全文は元記録から参照可能なままとする。

２つの候補を先に固定する。第一は、その詳細契約を取得した後に当該APIを送り、公開返却がエラーを含まないJSONだった場合だけ省略対象にする。第二は、第一に加え、公開契約の全引数名がその後の非エラー返却を得た要求に一度以上現れた場合に限る。いずれも取得後に拒否・不明な試行があれば残す。新しく取得した詳細は古い使用履歴だけで省略せず、完了・プロトコル用APIの契約も保持する。

これは**使用履歴の観測規則**である。返却が非エラーであっても意図に沿った操作とは限らず、一度使った引数の説明が次回も不要とは限らない。型・意味の正しさや将来の不要性を証明しない。全引数を過去に観測したことを、未使用のenum・値・組合せを理解したことにも置き換えない。

120秒以内、追加生成・入力計数・実API・コード再実行・評価器・保留群閲覧０。全４件・全23候補を出し、成功した課題やP47の後続呼出しを選択条件に使わない。文字数と実トークン数を区別する。少しでも変えられたというだけで主要比較へ進まず、適用範囲、通常の再利用・重複除去との違い、全文保持の必要性と制御費用を見て次の判断を記録する。

既存の仕様圧縮・段階的取得・状態表示と重なる部分がある。この点検だけで新規性や品質を保った総費用削減は確立しない。新しい生成比較は別途、強い対照と有限予算を固定する必要がある。[固定設定](../../configs/P52_contract_use_retention_v01.json)。
