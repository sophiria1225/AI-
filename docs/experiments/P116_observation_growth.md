# P116: 全16条件の観測再送とAPI再取得の点検

2026年10月25日. P111/P114/P115の結果を知った後の診断計画であり、未見性能実験ではない. P115では局所的な推論非再入力だけでは全仕事費用差を説明できなかった. 次の制御対象を選ぶため、公開観測が何回入力へ含まれたかと、同じ引数の実API要求がどこへ発生したかを分ける.

対象はP111の12条件とP114の４条件すべて. 全283モデル要求、820 API、既知3,026,706 token、未知使用量２件を保持する. 成功、失敗、APIのない呼出し、出力が不明な要求も除かない. 全要求・返答とusage/events/spansを既存のP113/P115指紋へ照合し、新しい計画へ固定する. 生の推論は意味解釈せず、実行コードを再実行しない.

入力のsystem、user、公開assistant、reasoning_content、関数名、関数引数、tool本文を分け、Unicode文字数を数える. 文字数をnative tokenへ換算しない. 同一tool messageは全messageの指紋と入力内出現番号を用いて追跡し、初めて入力に現れた本文と、その後の再送本文を加算する. 別の通信ID、変更された本文、同じ入力内の複数出現を勝手に統合しない. 予約停止による未送信入力を追加しない.

全実APIは、公開API名と認証を含む全引数の指紋を比較する. 同一要求、前回同一要求の返答一致、元の６読取操作に限定した保守的区間内の再取得を区別する. 既存の `field_read_contract.READ_ONLY_APIS` 以外の操作、返却失敗、未知作用で区間を切る. この区間は実状態の同値証明ではなく、通常キャッシュ候補の所在を狭めるための記録である. 返答内容や引数は公開しない. 後で同じ値が返ったことは事前の置換許可ではない.

上限は180秒、各条件80要求・4,000 event、各ファイル16 MiB、私有入力合計512 MiB. 自動再試行０. 保存先が存在すれば実行しない. 条件・ソース・私有入力の指紋をcommitし、同一headのpushとpull_request両workflow、両accounting-and-syntax job成功後に一度だけ処理する. 全16条件・283要求の未処理枠を先に保持し、失敗・timeout・停止も保存する.

モデル生成、実API、生成Python、評価、task DB、未見12課題、tokenizer呼出しは０. 局所文字数や同一要求の件数を、費用削減、意味的な不要性、品質維持、因果効果、新規性へ置き換えない. 原稿は保留し、結果を見てから具体的な介入と通常対照を定める. 次のモデル実験をこの計画で開始しない.
