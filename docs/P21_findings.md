# P21：提出できた３件は正しく、コード方式の優位性は示せない

2026年10月21日19:08〜19:58 JST。固定した６生成を全て終えてから、主評価と事前に固定した補助検査を実施した。**直接CSVは2/3、計算コードは1/3が完全な書出。残り３件は8,192出力の上限で未提出**だった。コードの実行エラーや、提出されたCSVの行欠落は観測しなかった。

これは、P18の既知の１開発状態で、取得済み公開情報から書出だけを比較した診断である。３seedは３独立課題ではない。CodeActの完全再現、自律的な検証方式、新規手法の効果、検索から完了までの成功率向上は主張しない。

## 何を調べたか

P18では必要な72対象の情報を取得していたが、元のCSVに１行の欠落があった。追加の機構を作る前に、普通の文字列生成や計算コードで正しく書き出せるかを確かめた。P20では両方式とも全６件が4,096出力で未提出となったため、同じ公開要求、66観測、モデル、指示、seed、順序を使い、両方式の出力上限だけを8,192に増やした。

原CSV、欠落行、正解件数、隠し評価は入力しない。ユーザーメッセージの要求と観測文字列は両方式で同じだが、出力関数とコード言語の説明は方式ごとに異なる。その入力費用も含める。これは元の長い会話をそのまま継続したものではなく、共通の観測パケットを与える比較である。P18からの改善をコード方式の因果効果とはしない。

固定した[計画](experiments/P21_export_budget.md)と[ソース記録](../reports/P21_execution_controls_v01.json)に従い、６件の終了まで生成内容を読まず、評価規則を変更しなかった。公開観測のライブラリ集合と対象メタデータから分析者が定義した72行の集合と照合した。これは信頼された課題別評価であり、モデルが検証仕様を自律的に導出した実績ではない。

## 補助検査

生成内容の閲覧前に、順序反転、観測重複、対象外メタデータ追加、対象の曲名変更を[別途固定](experiments/P21_supplementary_robustness.md)した。適合したコードは１件だけで、その１件は４条件全てで正しい集合を書き出した。元条件6,110ステップ、各変換6,110／10,470／6,164／6,110ステップ。追加モデル呼出し０、実環境操作０。

これは４つの分析者定義の検査に適合したという結果であり、任意の入力や仕様への正しさを証明しない。固定されたCSV文字列には再実行するコードがないため適用外とし、CSV方式の不合格に数えない。既存のメタモルフィックテストの利用を新規性としない。[補助結果](../reports/P21_supplementary_summary.json)。

## 解釈と次の判断

この観測では、通常のコード計算で完全な書出ができる場合があり、直接CSVでも完全な書出ができた。一方、同じ予算内でのコード方式の優位性は示せなかった。小標本なので、一般に直接CSVが優れるという結論にも使わない。残る３失敗は提出前の上限停止であり、制限付き言語による実行失敗ではない。

したがって、**この１件を根拠に新しい完了ゲートや集約方式の必要性を主張しない**。次は以前から予約した６開発シナリオを、P11・P18と同じ全履歴基準、モデル、１課題予算で実行する。対象の条件付き更新、集合選別、集計、複数種類の削除、書庫作成後の削除、最大値の判断を含む。全結果を残し、通常構成で解ける範囲と残る失敗を調べる。これは新手法の検証ではなく、機構を選ぶための開発実験である。

採らない案と理由は次の通り。

- 自動的な上限倍増や同じ１件の指示調整：提出が得られ、その全件が正しかった。１状態へ調整を続けても新機構の必要性は示せない。
- 今回のコードを標準Pythonで再評価して元結果を置換：唯一の提出コードは既に実行・補助検査へ適合した。言語制限による失敗がないので追加価値が薄い。[標準Python環境](standard_python_preflight_20261021.md)は将来の比較用に残す。
- thinking設定変更を新手法として扱う：公式モデルの設定であり独自技術ではない。テンプレート対応だけを確認した段階で性能は未検証。今回の提出内容の評価に必要な変更でもない。
- 確認用12シナリオを先に実行：方式を選ぶための開発と、固定後の確認を混ぜない。要求文を未閲覧のまま残す。

通常計算、証拠付き完了、課題契約、入力変換による検査には[近接研究](export_mechanism_review_20261021.md)がある。今回の実験と基盤整備を接続しただけでは、独自アルゴリズムの成立とは扱わない。４ページ原稿へ載せる主張は、追加開発で残った現象、既存対照との差、具体的な更新規則に基づいて絞る。投稿期限は10月31日、主要実験・あらましの目標は10月23日のまま。
