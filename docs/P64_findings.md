# P64：公開名アクセスの通常基準を開始から比較した結果

2026年10月23日。固定した全４条件を終了・独立評価し、2,366項目の監査は不一致０。**両方の通常条件が２課題とも成功したが、公開名条件の合計tokenは減らなかった。** 新提案手法の効果や、受付コードだけの因果効果ではない。

## 比較と全結果

P63で受付差を確認した既知の写真整理 `34d9492_1` と電気代精算 `3c13f5a_1` を事後選択した。同じ初期の公開課題・13 DBハッシュを元P29と照合し、各条件を新しい世界から１回ずつ実行。文書取得必須の従来Pythonと、説明取得前でも正確な登録公開名で呼べるPythonを比べた。能力の案内も合わせて変わるインターフェース全体の比較である。[固定計画](experiments/P64_public_name_comparison.md)。

全76生成、815,724 token、253 API、４評価。使用量不明０。全条件 `agent_declared_complete` で終了。cached inputも主費用に含む。表の時間には別プロセスの評価とモデルロードを含めない。所有推論器は1,983.310秒、ロード10.061秒、最大観測RSS 235,944,624,128 byte、swap０、要求した停止でexit code０。監査数は独立した課題数ではない。

文書取得必須は407,678 token・38生成・127 API、公開名は408,046 token・38生成・126 API。差は公開名が**368 token多い（約0.09％）**。写真では21,225増え、精算では20,857減った。課題ごとに各１回の観測であり、平均効果や分散は推定しない。

４条件とも日時を含む公開時計の成功応答が１件あった。未送信の時計要求は写真の文書必須１／公開名０、精算の文書必須２／公開名０。未送信には受付での拒否等を含み、その全てをコード１箇所の効果へ帰属させない。写真の元集合・日時・移動先の照合は別の[P65](P65_findings.md)に記録した。

## 採否と原稿への意味

正確な公開名アクセスは通常基準の機能として保持する。総費用を下げる独自手法としては採用しない。従来条件も両課題を完了したため、過去P29/P55との差をP63の受付変更だけで説明しない。プロンプト、予算通知、計測、開始地点の違う履歴比較である。

P55/P56の本文・成否・欠測は保持する。その知見は説明取得必須という追加制約の下での局所診断であり、一般のコード実行型エージェントに広げない。今回の２課題をP55の主表へ合算しない。保留12シナリオの閲覧０。

次はP65で確認した公開根拠に基づく通常の終了制御を、実際の逐次実行に接続して試す。後続約3.9万tokenを事前に「節約」と呼ばず、判断処理・完了通知・失敗も数えて元の通常実行と照合する。既知文型の手書き検査を新しい一般手法とはしない。
