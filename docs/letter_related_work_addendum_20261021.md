# レターの関連研究：追加確認

2026年10月21日。[最初の機構比較](letter_mechanism_review_20261021.md)の後に読んだ範囲を記録する。実装再現や採録確認を完了した記録ではない。

**MemTXの５節・付録Gも確認した。** 読み取りの隔離水準を変える比較、正常な操作を阻害しないかの測定、記憶撤回後の影響を扱っている。したがって「用途別に記憶を制限して安全性と実行可能性を測る」という広い説明だけでも差にならない。未送信の要求本文を、圧縮・修復へ渡す境界に限定して何が追加で分かるかを示す必要がある。論文固有の結果を今回の実装で再検証したわけではない。[著者公開原稿](https://arxiv.org/html/2607.23929v1)。

**MemTraceの要旨・１〜３節を確認した。** 原記録を保存し、現在のリポジトリ状態と照合して必要な根拠を復元する方式。原文への参照、状態の有効性、記憶の復元だけを独自機構としない。コード変更に伴う過去の根拠の失効と、送信前に実行されなかった要求の扱いは問題設定が異なるが、その違いだけで提案の有効性は成立しない。[著者公開原稿](https://arxiv.org/html/2610.04838v1)。実験節の全面精読・実装再現・正式採録確認は未実施。

HaluMemはv3の３〜５節も確認した。記憶抽出・更新・回答を分けて評価し、助手が述べてユーザーが確認しない撹乱情報への抵抗を含む。会話由来の事実記憶が対象で、実行器の送信記録を用いた今回の操作完了の判定とは対象が異なる。ただし段階別の幻覚評価や情報を残す／捨てる比較自体を新規性としない。v3の実験節の全面精読は未実施。OpenReviewの匿名ACL投稿版を採録の証拠にしない。[v3本文](https://arxiv.org/html/2511.03506v3)。
