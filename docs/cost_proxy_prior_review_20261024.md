# 費用指標の近接研究を踏まえた主張の限定

2026-10-24。論理tokenが減っても他の費用が増えるという観測だけを、新規性の柱にはしない。全仕事の費用、cache、再取得・失敗、最終成否を併せて測る必要性にも先行研究がある。今回、以下の一次資料を追加確認した。著者原稿の読取であり、こちらで再現実験を行ったものではなく、正式採録は未確認である。

| 一次資料・確認範囲 | 今回の位置づけへの影響 |
|---|---|
| Weinberger・Hozez, [Token Reduction Is Not Cost Reduction, v5](https://arxiv.org/html/2607.12161v5)。初版2026-07-13、v5は08-12。要旨、§2、§5.2–5.4、§7.2–7.3、§14–15。先にv1も読取 | 圧縮と請求費用の方向差、失敗を含む成功当たり費用、cache持越しと使用量の限界を扱う。費用指標の区別や失敗を残す評価を独自の提案とはしない。 |
| Song, [Cache-Aware Prompt Compression, v1](https://arxiv.org/html/2607.15516v1)、2026-07-17。要旨、§6.5、§7.1–7.7 | 圧縮後のprefix再利用を考慮した方式を提示し、環境による費用増減も報告する。cacheと圧縮の相互作用自体は既出。こちらのローカル推論の計数へ、外部APIの請求率や閾値をそのまま移さない。 |
| Lumerら, [Don’t Break the Cache, v2](https://arxiv.org/html/2601.06007v2)。初版2026-01-09、v2は01-31。要旨、§3.1–3.4、§4.1–4.3 | 複数提供元のcache方針を、費用と最初の応答までの時間で比較する。両指標で有利な方針が同じとは限らない。こちらの全作業時間や課題成功とは測定対象を区別する。 |

CAPC本文にある成功件数の一致と差の検定での非有意は、一般的な品質同等性の保証とは扱わない。これは今回の解釈上の注意であり、元論文の結論をそのまま採用したものではない。こちらも既知４課題の成功保持を統計的非劣性へ読み替えない。

今回の主張候補は、固定実期限のもとでの残時間表示、文章化経路の通信参照が実入力へ残る仕組み、それらの局所診断と全仕事比較の対応に限る。これらも一般的な時間通知・ID正規化の発明ではない。小さな既知課題群、単一モデル・環境、事後選定した入力、欠測を持つ実証がレターの貢献として十分かは、依然として未確定である。

P80/P81の全24条件・429生成、不明２生成と条件付き区間、資源別集計は変更しない。金銭費用・GPU計算量・消費電力を測ったことにはせず、実測時間の差も因果的な高速化としない。P82/P84の条件や採否基準はこの文献確認で変更しない。P84の問いを消す根拠でも、18生成を増やす根拠でもない。
