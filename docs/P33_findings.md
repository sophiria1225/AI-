# P33：出力を省いても、今回の総費用は減らなかった

2026年10月22日09:28〜10:23 JST。全12条件を終了し、原記録・状態・初回入力・予算・独立評価の監査不一致は０。４既知課題の同じ８応答後から、Python状態を保持し、全履歴／古い成功出力だけ省略／省略＋変数・API一覧を比較した。条件ごとに１試行で、12独立課題ではない。[固定仕様](experiments/P33_output_views.md)／[全件集計](../reports/P33_comparison.json)／[公開PR #177](https://github.com/sophiria1225/AI-/pull/177)。

目的は、ハーネスで不要な情報処理を減らし、最終品質を維持すること。今回測ったのは、操作コード・状態・原記録を残す通常の出力省略が、その目的にどこまで近づくかである。複数担当の通信削減、新しい関連性判定器の性能は測っていない。

成功したのは全方式で写真整理と返金の同じ２件。成功の入替えはなかった。ただし各１回の開発結果であり、品質維持の一般的な証明ではない。

返金では、全履歴の後続は送金作成と完了の２ APIだった。省略ではAPI説明・相手の探索等を含む８ API、一覧追加では４ APIとなった。これは実行経路の観測であり、取得全てを不要と判定したり、追加呼出しが全て同じ原因だと確定したりはしない。[プログラム診断](../reports/P33_program_diagnostics.json)。

共有・依頼は全方式でトークン予約上限に達した。曲一覧の書出は、全履歴が後続62 APIで課題のAPI上限に達し、他２方式はトークン予約上限で停止した。**全履歴の書出が安いのは成功を安く達成したという意味ではない。** 停止の仕方が違うため、総費用だけから全履歴一般の優越も結論しない。

## 今回の判断と、採らない案

[実行前に定めた採否基準](../reports/P33_development_gate.json)は、対照の成功を落とさず、総費用を減らし、費用不明がないこと。両省略条件は総費用の点で通らなかった。この設定を、品質を維持した費用削減方式として本実験へ広げない。

- 写真整理だけの削減や返金だけの一覧効果を取り出して、全体の改善とはしない。課題別に最良方式を正解を見て選ぶ運用もしない。
- 一律にさらに短縮する、上限を増やす、同じ比較を成功するまで繰り返す案は先行しない。今回の経路差を説明できる削減対象を先に調べる。
- 単純な同一要求のキャッシュだけで解決すると決めない。元の前半との一致、後続内の同一要求、異なる要求で得る情報の重複は別に測る必要がある。要求が同じでも状態更新後の確認などは必要な場合があるため、自動的に不要とは扱わない。
- 全出力と現在の値を照合するP34も対象23出力中１件だけで、その制御への追加モデル実験を見送った。これは形式の限界を含み、他の表現でも値が不在だと証明したわけではない。

[費用差の算術的な分解](../reports/P33_cost_decomposition.json)では、入力長を減らす項が、生成回数・後続入力の増加等の項で打ち消されている。各項を独立した因果効果や実現可能な削減量とは扱わない。[定義と制御検査](continuation_cost_accounting_20261022.md)。

## 次の実装へ進める範囲

次は取得後の出力を一律に隠す追加実験より、**実行コードが実際に参照した情報と、APIが返した情報の対応**を調べる。元の返却だけでコードを再生し、読み取り箇所を記録できるか、元と同じ要求列・出力・例外になるかを確認する。新たなモデル呼出しや実APIを先に増やさない。

狙いは、必要な情報を消して再探索させることを避けながら、取得・引渡しを細かく制御できる条件を探すこと。読まれた記録がないだけでは不要と判定しない。印字・直列化・外部ライブラリ・型判定など、計測で見落とす経路も明示する。対応を確かめられない場合は省略制御へ進まない。具体的な方式と近接研究との差分は、この結果を基に別途判断する。

現時点で独自方式と改善効果は未確立。12確認シナリオは未閲覧のまま。10月23日の主要実験・あらまし目標には、新しい主張を確定できていないという不足が残る。今月の投稿へ、通常の出力省略や今回の負の結果だけを新規性として書き換えない。
