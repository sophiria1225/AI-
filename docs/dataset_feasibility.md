# データ候補の導入確認

初回は、公式の独立評価を使えるコード課題を調べる。候補の優劣は実測前に確定しない。

| 候補 | 今回の位置づけ | 理由と未確認事項 |
|---|---|---|
| SWE-bench Verified | 導入確認の第一候補 | 一課題でamd64互換実行と正負対照の独立評価が動いた。モデルが生成した4試行の成果物は不合格。コアダンプも観測し、他課題・環境の安定性と研究対象としての適合は引き続き未確認。 |
| BrowseComp-Plus | 転用・代替候補 | 調査の分担を扱える。今回はコードの評価環境を先に整え、全文書索引と別評価器を同時には構築しない。性能劣位は未検証。 |
| SWE-bench Pro | 後続比較候補 | 別のコード課題群として残す。版・実行条件の追加調査が必要で、初回の変数を増やさないため保留。 |
| TheAgentCompanyなど業務環境 | 後続候補 | 複数サービスの構築が別の実装課題を増やすため、最初の費用計測の確認では後順位。適性の否定ではない。 |

Verifiedの取得版・サイズ・ハッシュ・公開入力列は`records/sources/verified_download.json`に保存した。原データの500件を、500件の実行指示とは扱わない。

開発候補と選定理由は判断D008を参照。最初に一課題で評価環境を確認し、実時間・保存量を測ってから追加する。
