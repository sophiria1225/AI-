# 残時間を後半だけ表示する通常対照の準備

2026-10-24。P80の終了結果とP81の途中結果を見た後の開発上の選択である。P81の実行条件は変更しない。次の通常対照を準備するため、[時間表示の部品](../scripts/late_time_observation.py)と[適用機会の読取解析](../scripts/inspect_late_clock_opportunity.py)を追加した。新規手法、品質維持、費用削減の成立とは扱わない。

## 固定した部品の規則

モデル呼出し直前に、既存と同じ切捨て整数秒の残時間を得る。元の作業上限をD、現在通知の残時間をrとし、`2*r <= D` のときだけ実測値を表示する。それより前は既存の非表示通知を使う。比較用の常時表示は既存の通知と同じ内容にする。割合は1/2の一つだけであり、複数の閾値を探索していない。

整数秒の切捨てを引き継ぐため、厳密な実時間の中点より最大１秒弱早く切り替わり得る。表示の判断は生成前に一度行う。入力計数中に中点を越えても通知を再作成せず、実際の残時間から送信可否とタイムアウトを判定する。生成の途中へ時間通知を差し込むものではない。

過去の文章・推論・API返却を書き換えない。通信参照IDの通常の正規化と初回cold確認は両条件で共通にする。切替までの生成、API、tokenを全て残す。元の実期限を延ばさず、不明な使用量は不明として停止し再試行しない。追加のモデル判定器は使わない。

## 終了済み全８条件で確認した適用機会

[P80全件の読取結果](../reports/late_clock_feasibility_20261024.json)では、D=1,800秒の半分以下の通知機会は非表示の書出しだけにあった。最初は16生成目、残り741秒であり、その前に196,133 tokenを使っていた。既存記録では16〜20生成目の５通知が該当する。他の７条件は切替対象になる通知がなかった。

これは保存済みの経路における適用機会である。16生成目の入力を変えると後続経路全体が変わり得るため、５回分やその費用を節約できたとは扱わない。元の未達と不明１生成も保持する。全８条件の要求・返却hashと通知・使用量を照合し、生成・API・評価の追加は０だった。

## 実行比較へ進める条件

目的は、前半の細かい時刻差を入力しないことと、終盤に実残時間を知らせることを分けて調べることである。通常の閾値通知を独自方式へ格上げしない。長い１生成が中点から期限までを使い切る場合には、新しい通知の機会自体がない可能性もある。

部品はまだ実タスクworkerへ接続していない。P81を全件終了・監査した後に、必要な比較か判断する。実行する場合は、常時表示と後半表示の新しい対照、全既知４課題、順序、同じseed、有限上限、全費用と欠測の扱いを固定する。P80/P81の古い結果を新しい同時対照へ読み替えず、都合のよい課題だけを選ばない。保留12課題は使わない。

部品の７検査は、境界値、切替前の費用保持、常時表示の既存入力との一致、計数中の経過時間、実期限、送信後欠測、初回cacheの拒否を対象とする。合成検査は実モデルでの品質や節約を示さない。
