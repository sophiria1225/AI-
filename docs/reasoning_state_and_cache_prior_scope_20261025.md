# 推論表示と状態・cacheを分ける追加原典確認

2026年10月25日. P114の通常非再入力対照を実行中に、次の判断で混同しないために確認した. P114の中間成否は読まず、方式と予算、P115の固定診断を変更していない. 原稿の更新ではない.

## 計画の有無を調べる診断と、成功を保つ制御

[Plans Don't Persist v1](https://arxiv.org/html/2606.22953v1)の§3、§7–9を確認した. replay pairingは、計画を含む実行の行動と観測を固定して、計画を除いた側にも与え、隠れ状態の差を測る. 除いた側で新たに出た行動は、その後の軌跡を駆動しない. strict strippingは計画の交換に加え、過去assistantの完全なthinkブロックを除く. 公開された行動等は残す.

これは今回の独立した全仕事実行と異なる. また、報告自身も、長さ・位置・談話構造、片側だけの削除という交絡が残ることと、表現上の測定を行動改善の証拠にしないことを述べる. §8の圧縮ストレス試験では、計画を固定保持する方式とprobeで再表示する方式でも、同じ狭い履歴枠における成績は回復しなかった. 観測と行動の消失が残るという説明は著者の仮説であり、今回のP111の原因として確定しない. 効果量を今回へ移さず、著者コードは再現していない.

今回への判断は、単に推論を除く比較、同じ軌跡での診断、必要そうな計画を戻す発想を独自性にしないこと. P115は追加生成や隠れ状態の測定を行わず、既知実軌跡の入力計数だけを行う. その結果に新たな成否を付与しない.

## 文章の編集とKV状態の直接操作

[Cache Engineering for Agents v1](https://arxiv.org/html/2610.28577v1)は、既存の[費用確認](cost_profile_20261022.md)では要旨・導入まで読んでいた. 今回は§3.3–3.4、§4.1–4.2、付録A.1.4へ範囲を広げた.

dropは論理上のtoken列と残すKVを変えず、以後の注意から選んだKVを外す. reposは鍵の位置符号を変える. このため、同じ残存tokenでも、どの時点でdropしたかにより後続KVは異なり得る. AKVはtoken列に操作履歴も加えて再利用を照合し、欠けた状態を元の操作順に対応する注意計算で復元する.

付録A.1.4の提供性能測定は、各方式自身の保存軌跡から出力量を定め、新しいassistant出力を生成しつつ、tool返答を保存記録から渡す. toolを再実行する全仕事の再評価ではない. この測定では返答のない最終入力を除く規則も記す. 本文の課題性能評価と、この提供性能測定の対象を混同しない. 著者実装・性能再現、採録状況の確認はしていない.

今回のP111/P114は文章としての送信履歴を変え、AKVのdrop/reposは実装していない. P115の語彙だけによる入力計数は、KV状態や処理時間の予測ではない. 新しいKV制御を導入したり、過去の実測cache使用量を書き換えたりしない.
