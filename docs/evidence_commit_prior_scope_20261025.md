# 証拠の十分性と実行許可に関する先行範囲

2026年10月25日. P111〜P113の結果を受け、単なる実行成功より強い証拠を使う案について一次資料を照合した. 以下は読んだ本文の範囲であり、著者コードを再現した比較ではない. P111の対照へ後から追加した成績でもない.

| 一次資料と既読範囲 | 確認した仕組み | この研究での扱い |
|---|---|---|
| [MemTX](https://arxiv.org/html/2607.23929v1), §3.1〜3.6、§4 | 記憶に出典、権限、有効期間、依存関係と段階を持たせ、commit時の検証と不可逆操作のgate、取消後の依存先修復を行う. 強いgateは、操作自身の入力全てではなくsnapshot中のaction-safe記録の存在を条件とする. LLMの主評価と強いgateの評価範囲も区別している. 修復は記録された依存関係に限り、環境全体の巻戻しを保証しない. | 証拠付き記憶を確定してから実行する一般構想や依存先の失効処理を、こちら独自とはしない. 主目的は記憶と行動の安全性で、P111の入力＋出力token削減とは評価目的が異なる. |
| [SafeCommit](https://arxiv.org/html/2608.04289v1), §2.1〜2.4、§3.1〜3.4、§4.6 | 残る候補世界の全てで安全な操作だけを許可し、不十分なら証明を妨げる候補を減らすprobeを選ぶ. 安全性が同じ世界をまとめる圧縮も定義する. 保証は候補集合のcoverageとdomain固有の安全判定に依存し、候補世界の取り落としを別項として扱う. 評価は明示的世界と手作業の安全写像を使う制御simulation. | 行動に必要な証拠だけを残す、証明付きで取得を止める、という一般構想は既出. この保証を自然言語の依頼や後続LLM行動へ、そのまま適用したことにはならない. |
| [Router-Mem](https://arxiv.org/html/2608.01285v1), Method全節、Algorithm 1 | 共有の初期検索を行い、取得証拠が回答に十分かを学習済みrouterで判定する. 不十分なら同じ検索結果を起点に記憶blockの分析を続ける. 推論時の判定は１tokenでも入力処理は必要で、routerの学習には証拠の介入例とteacherの説明を用いる. | 取得済みの証拠に応じて追加処理を省くこと自体は新しくない. こちらでは学習データ、独立した十分性ラベル、router学習と費用比較を用意していない. |

ここからの判断は、実行成功を「不要情報の証明」に読み替えたり、証拠台帳や十分性gateという名前を付けたりして新規性を主張しない、ということになる. 反証可能な追加規則、一般的な対照との差、証拠を作る費用までを具体化する必要がある. P113の指紋照合はこの意味的な十分性を検証したものではない. 新規性と品質を保った総費用削減は未確立である.

比較のために未見12課題へアクセスしたり、各先行方式のコードを実行したりしていない. これらの資料の採録状況はここでは確認していない.
