## 実装と研究上の判断

保留APIの引数だけを修正し、後続プログラムを維持する操作を、そのまま新提案の中核にはしない。ControlScopeのArgと操作範囲が重なるためである。型付きの正常値、Python例外、変数の保持も、通常の実行基盤として扱う。

[P49](P49_findings.md)の非自明な名前対応候補は限定的で、[P50](P50_findings.md)の型による候補も通常の決定的な対応との比較が先に必要だった。これらの少数候補を理由に、複雑な再開処理や有利な例だけの追加生成へ進めない。実行前の拒否と実行後の例外を混ぜず、後者で副作用がなかったと推測して自動再実行しない。

[P78](experiments/P78_api_error.md)は、失敗通知の違いを全仕事の観測へ結び付ける比較である。成功すれば失敗通知の設計判断を支える局所結果となり得るが、新しい制御アルゴリズムの成立にはならない。失敗時や差がない場合も、固定８条件を全て残す。

原稿へ使う場合は、保持、表示、API失敗通知、終了通知を別の操作として記述する。過去のP55/P71/P76を修正後の通常基準の因果対照に置かない。必要な情報と処理、最終品質を保って総費用を減らす最終目標に対し、各結果がどの判断を支え、どこをまだ支えないかを示す。
