# 整合版台帳の実行接続を準備する

2026年10月21日。P17は生成中、P18はその終了待ち。この変更ではモデル推論・環境操作を追加しない。将来の基準比較用に `native_ledger_aligned` を実行器と監査器へ接続した。**新規方式でも、性能改善の結果でもない。**

採用条件は[P17の固定仕様](experiments/P17_ledger_contract.md)のまま。全出力の形式と内容を確認する前に、修正版を有効と決めない。今動いているP17/P18の凍結コード・入力・予算を変更しない。P19という識別子を実行器で受け付ける準備だけで、P19の課題群・実行計画・自動開始はまだない。未閲覧の確認群も使っていない。

## 変える部分と比較で固定する部分

P17と同じ要求出典 `task`、現在見える操作記録と前の台帳で引用済みのID、最低１件の出典、空でないキーをモデルへ宣言し、同じ制約で受け取る。要求文だけでは操作の実施を証明しないという指示も同じ。過去に保管しただけで今回見せていない・前台帳にも引用していない記録は、利用可能IDに加えない。

履歴量による生成開始、直近２spanと操作・結果の対応を保つ保持、未処理要求の保持方法、不適合時に元の履歴を残す方針は従来台帳から変えない。不適合の再試行や出典の自動補完を加えない。成功・不適合・使用量不明の生成をすべて記録し、採用された記憶だけの費用にしない。

出典IDを検査しても内容の正しさは保証できない。例えば `task` だけを引用した `done` 項目も、形式としては適合し得る。今回の受取検査を「完了の証明器」と説明しない。意味は別の照合対象である。

## 検証

制御用の模擬入力で次を確認した。実タスクの性能試験ではない。

- P17の全span入力と、この実行接続の初回台帳入力・ツール定義が完全一致する。
- 同じ有効草案なら、従来台帳と保持対象・モデルへの実行入力・費用計上が一致する。
- 前台帳の出典は引き継ぎ、未提示かつ未引用の保管記録は拒否する。
- 不適合は元の履歴へ戻し、再送せず、生成費用を残す。使用量不明の呼び出しも消さない。
- 記録から入力・ツール宣言・費用・環境保存境界を再照合し、保存済みの宣言を改変した場合に検出する。

追加７検査を含め315件合格。既存のP13/P14ファイルは凍結作業木で保存し、新版で過去の原記録を上書きしない。

## 採らなかった案

旧台帳ファイルを直接変更すると、実行中のP17の依存ソースと過去の校正を変えてしまうため、実行接続は別モジュールにした。共有部分の整理は結果確定後の保守課題であり、実験途中のリファクタリングを優先しない。空の出典へ任意IDを付ける方法や、形式不適合をそのまま採用する方法も、意味上の支持を増やさないため採らない。

新しい閾値、キャッシュ制御、記憶の意味的な確定条件を同時に加える案は見送る。基準修正と別機構の寄与を分けるためであり、それらが一般に無効という判定ではない。
