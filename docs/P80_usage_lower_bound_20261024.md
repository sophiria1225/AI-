# P80の不明生成に残った補助的な費用下限

2026-10-24。[P80の終了結果](P80_findings.md)では表示Mが787,092 token、非表示Hは既知780,394 token＋使用量不明１生成だった。今回、閉じた推論器の数値ログを全143生成へ順番に対応させ、142件の既知の入力処理数と出力数がすべてクライアント側の記録と一致することを確認した。

Hの書出しの最後の生成では、送信前の同じ推論器による入力計数が37,527 token、生成進捗の最大値が2,130 tokenだった。固定版の推論器では、生成数の増加は入力処理完了後にのみ起きる。したがって下記の前提の下で、この要求の論理費用は少なくとも39,657 token、H全体は少なくとも820,051 tokenとなる。Mの確定全費用より少なくとも32,959 token大きく、この補助下限でも全体削減は成立しない。

| 集計 | 論理token | 値の性質 |
|---|---:|---|
| M全体 | 787,092 | 全終端応答が既知 |
| Hの終端応答が既知の部分 | 780,394 | 不明１生成を含めていない |
| Hの不明生成 | 39,657以上 | 入力計数37,527＋観測した生成進捗2,130 |
| H全体 | 820,051以上 | 補助記録に基づく下限 |
| H−M | 32,959以上 | 上記の対応・計数の前提の下での下限 |

## 対応と限界

[解析コード](../scripts/inspect_budget_visibility_usage_bounds.py)は、所有した１slotの推論器の全開始・解放を取り込み、重複・並行・未完了・切詰め・不明な取消しを拒否する。固定順の全143要求と143開始を対応させ、既知142件の入力処理数＝全入力−cache入力、および出力数の一致を要求する。入力計数だけで実際の実行を推定せず、不明要求に生成進捗と取消しがなければ下限を出さない。取消し付近で観測した処理も費用へ含める。

この対応は、記録外の生成がない所有推論器の完全な直列ログを前提とし、全既知件の一致で裏付ける順序対応である。クライアント要求のhashを推論器のtask IDへ暗号学的に結び付けたものではない。入力計数と実生成は同じmessages/toolsを用いる固定実装であり、実行前の計数値そのものを終端使用量へ書き戻さない。推論器の[固定ソース](https://github.com/ggml-org/llama.cpp/blob/620d2225cc436ab0b001e3200e590e3b286ef9ab/tools/server/server-context.cpp)の生成状態への遷移と進捗カウンタを確認し、Git blobとローカルソースを照合した。

[全143行と出典](../reports/P80_usage_lower_bounds_20261024.json)。元の不明１生成、全８条件の成否、採用基準未達、原資料・主原稿・別稿はそのまま保持した。完全な終端使用量を復元した報告ではなく、事後の補助解析である。論理tokenはcache入力を含み、金額やFLOPs・実時間ではない。追加の生成、入力計数、API、評価、保留課題閲覧はすべて０。新規手法として数えない。
