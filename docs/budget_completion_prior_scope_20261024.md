# 予算内で出力を完成させる案の先行範囲

2026-10-24。[P86](../materials/20261024_output_budget_scope/README.md)で全855要求の独立した推論予算が未指定だったため、通常対照の[P87](experiments/P87_fixed_reasoning_budget.md)を実行している。以下は実行条件を変更するものではなく、次の案を通常手法と取り違えないための原典確認である。

## 残りtokenで完成できる候補だけを残す処理は既出

Dangらの[原著v1](https://arxiv.org/html/2606.01926v1)の§2–3.2では、任意の長さなら完成できる接頭辞と、指定された長さまでに完成できる接頭辞を区別している。有限オートマトンの到達状態と、残りのtoken数で受理状態へ届くかという逆向きの到達可能性から次tokenを制限する。したがって「文法だけでは予算切れが残る」「残り長を考慮して完成を保証する」という一般構想は既出である。対象の制約がそのオートマトンで表現されるという前提があり、任意のPythonの意図や環境上の効果まで保証するものではない。会議掲載は[ICML 2026の書誌](https://proceedings.mlr.press/v306/dang26c.html)で確認したが、ここで本文を読んだ版はarXiv v1である。

[Decode-Time Grammars v1](https://arxiv.org/html/2607.18357v1)の§4.3は、予算が尽きると文法上は可能な接頭辞のまま終わる問題を区別し、Dangらを参照している。§7.1–7.2の完了と適用範囲も確認した。引用先の原著を上記の通り確認しており、この節の言い換えだけを原著の保証として用いていない。

[GRID v1](https://arxiv.org/html/2607.11951v1)の§5では、デコーダを所有する場合、最短の合法な補完に必要な**語彙token数**を予約し、残り枠が小さくなると補完とEOSを出す構成を述べている。logitsを制限するだけの構成とは保証が異なる。局所的なマスクは元モデルの大域的な条件付き分布を保存せず、制約を満たしても品質は別に測る必要がある。この論文の全ベンチマークや実装は再現していない。

## このハーネスで区別すべき三つの条件

| 制御の対象 | そこで確認できること | 残る確認 |
|---|---|---|
| 推論ブロックを一定長で終える通常設定 | 公開出力へ移る機会を作る | 終了タグ、再開、公開コードの長さを含む完成は保証されない |
| JSONや道具呼出しの文法を予算内で閉じる | 指定された形式の完成 | `code`が文字列であるだけでは、そのPythonの構文や意図は保証されない |
| Pythonの構文を読み取れることを検査する | 構文木が得られる | APIの前提、参照の実在、作用、目的の達成、全仕事の費用は未検証 |

これは本研究側の整理であり、各先行論文の実験結果ではない。現在のP87はJSON、必須引数、非空Python ASTまでを確認する通常対照の局所診断である。コードは実行せず、同じ既知１課題から事後選択した２文脈を使う。P87の結果だけで課題品質や新規手法を主張しない。

新提案の候補とするには、単なる推論予算設定や最短補完との機能差を示し、取得済み状態・残る必要処理との対応を公開情報から決める規則、状態変化時の更新、失敗と検証を含む追加費用を定める必要がある。これらを具体化する前に新しい生成枠を増やさない。一方で、この先行確認だけから全ての具体的な改善案が存在しないとも結論しない。
