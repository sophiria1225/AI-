# P122から既定のP123へ継続する処理

ユーザーの「止めてと言うまで実験を進める」という指示に従い、P122全件閉鎖後の確認と、既に用意したP123の有限比較を接続する. P122は固定24条件の実行を続け、現在の方法や順序は変えない.

終了印、所有server閉鎖、全件監査、既存collectorの完了を待つ. 全24枠、固定seed、全要求と役割別費用、集計と材料の指紋を再確認する. 反復の採用基準と写真の局所的な確認は、それぞれ元の規則で再計算する. 全枠を表に残し、成功損失や不明な使用量を隠さない.

全24枠が評価済みで使用量が既知、監査が正常な場合、[作成済みのP123仕様](experiments/P123_whole_task_rolling_checkpoint.md)を実行用configに固定する. P122の科学的な採用基準の成否にかかわらず、同じ４課題、３方式、１回、80要求・450,000 token・1,800秒の各条件上限を使う. 好ましい結果からseed、課題、予算、方式を選び直さない. 不明・欠測・監査異常がある場合は記録を保持して次の生成を開始しない.

結果と固定計画は専用の作業木でcommit、対象リポジトリだけへpushとPRを作成し、同じ完全headのpush・pull_request両workflowと両job成功後にmergeする. P123専用実行木をそのheadに固定し、24のnative事前計数とactivation後に12条件を一度だけ実行する. P123の所有server閉鎖後は全件監査と集計を行う. 失敗枠の穴埋めや自動再試行はしない.

継続処理は停止印と各処理の開始印を確認する. ユーザーの停止指示では継続処理と所有する実験を停止する. 新しい実験は有限仕様を持つ単位で進め、P123終了後の次の研究判断には全件の結果を用いる. この自動接続自体を新規性や品質維持の成果とは扱わない. 原稿は今回の接続で変更しない.
