# 履歴要約の作業稿: 改善の範囲と残る研究課題

2026年10月25日. [作業稿](../papers/202610_letter/checkpoint_cost_v01/README.md)の主張を、公開済みの全条件、費用内訳、入力診断と照合した. 新しいモデル生成、API実行、課題評価、入力tokenの再計数は行っていない. 原稿PDFと元の結果は変更していない. 数値の照合は[確認記録](../reports/checkpoint_letter_claim_review_20261025.json)に残す.

## 現時点で書ける中心結果

「既知の写真課題において、要約を次の行動と同じ応答へ含める方式は、別呼出しの要約と同じく課題に成功し、全モデル要求の入力と出力の合計を139,871から129,374 tokenへ7.50%減らした. 一方、CSV課題では成功を失った.」

7.50%の分母は写真の別呼出し要約139,871である. 全履歴保持、直近窓、既存研究の実装に対する削減率ではない. 同時出力は実行役で7,958 token増えたが、別呼出し要約18,455 tokenの差を含めると10,497 token少ない. 要約を作る追加指示、schema、出力も合計に入っている. 写真ではモデル要求が17から16へ減り、API要求は両方式102だった. [P120全件](P120_findings.md).

同時出力の要約部分だけの生成費用は分離測定していない. 「専用呼出しがない」を「要約費用が０」としない. P121のDは、実際の後続行動と予算通知を固定した入力差である. 特にCSVでは古い履歴へ戻す仮想総量が450,000 tokenの仕事予算を超えるため、実行可能な全保持経路や実測節約に置き換えない. [P121全件](P121_findings.md).

## 新規性の評価

本実装はハーネスによる履歴表示、要約の要求と採用、ツール実行の制御である. その実装形式だけから新規性は生じない. 内部状態の更新と行動生成を同じ工程へ結び付ける考えはMEM1にあり、構造化状態の更新と行動を生成する方式はSKILL.stateにもある. 今回の四つの要約欄と一度だけの起動は実装上の違いだが、その違いが新しい一般原理や独自の便益を生む証拠はまだない. [MEM1 v1 §3.1](https://arxiv.org/html/2506.15841v1#S3.SS1)、[SKILL.state v1 §3.1–3.2](https://arxiv.org/html/2608.26263v1#S3).

局所的なtoken短縮と全仕事費用を区別し、後続の取得や行動の変化を含めて評価する必要性も先行研究で扱われている. 本稿では論理tokenを主指標にしており、その研究の課金額や成功調整済み費用と同一ではない. 厳密な記録や負の結果を残したこと自体を新規手法とはしない. [Token Reduction Is Not Cost Reduction v5 §1, §13](https://arxiv.org/html/2607.12161v5).

現在の独自性の候補は、この状態保持型の実行系で、要約の要求、採用、入力差、作成費用、全仕事の結果を同じ条件へ対応付けた限定的な実証である. 通常の直近窓や先行手法を今回と同じ条件で実装比較した結果ではなく、それらへの優越性は示していない. **新提案手法として採録に足る新規性が確立したとは判断しない.**

## 品質を保つ削減へ残った課題

必要なのは、仕事が終わるまで使う情報を残しながら、作成費と後続入力を合わせて減らせる規則である. 要約後に何回呼ぶかは実行前には不明であり、P121で分かった写真２回、CSV19回をそのまま実行時の判断材料にはできない. 写真には同時出力、CSVには別要約を結果を見て割り当てても、検証済みの自動選択法にはならない.

将来の候補には、判断時点で利用できる情報、保持すべき状態、要約の作成時点、失敗時の費用を具体的に定める必要がある. 固定した候補を、別要約と通常の履歴保持を含む対照で比較し、全課題の成否と総費用で判断する. 現時点ではその規則を実証しておらず、予算の増加やCSVだけの再試行で品質維持を示したことにしない.

10月25日の区切りではモデル実験を追加せず、現行原稿の検討を進める. 著者、所属、公式様式は未完了. 先行研究との差と評価の小ささが科学的な残件であり、組版を整えるだけでは解消しない. 未見12課題、元の失敗と欠測、全ての採用判定を維持する. [実験の区切り](letter_experiment_cutoff_20261025.md).
