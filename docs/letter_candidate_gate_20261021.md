# 今回の候補をレターの主張へ進める条件

2026年10月21日。P16は生成中、意味判定前。投稿期限に合わせて、広い機能追加ではなく、次の順で採否を判断する。

1. **現象があるか。** 固定した４課題の元入力で、実行証拠がない操作完了を記憶へ書く例があるか。APIや仕様を調べたという正しいdoneは誤りに数えない。形式不適合は意味判定できない出力として残す。
2. **単純対処では足りないか。** 未送信の明記で十分なら、用途別表示の新手法としては進めない。表示を除いた条件で形式不適合が増えて見かけ上の誤り数が減っただけでも採用根拠にしない。
3. **何を失うか。** 除去による追加価値が残る場合に限り、同じ操作直前の環境から修復を比較する。元の要求を一律に外しても同じ費用で修復できるなら、用途別表示を複雑化する理由はない。
4. **既存方式との違いが残るか。** 状態付き記憶、拒否の記録、修正情報の保持、用途別可視性は既出。機能が等価なら新アルゴリズムとはしない。実験的知見としても、既知の注意点を一例で再現するだけでは不足と判断する。

導入確認の４課題・１seedから有意な一般優位を主張しない。追加実験に進む場合、別の課題と種を先に固定し、全費用、悪影響、近接方式と同等の単純対照を含める。
元の４課題で方式を選んだ結果と、新しい課題で確認する結果を混ぜない。

現象が出ない場合は、旧接続の１失敗を現在の標準接続の一般問題として押し通さない。
対象や入力を変更する追加探索は、新しい仮説・変更理由・費用を別に記録し、最初から決めた主実験とは呼ばない。
期限が近いことは、差がない結果に新しい名称を付ける理由にはしない。

P16の結論に関係なく、前半再生の照合、費用記録、意味判定基準、原記録は残す。
これらは研究基盤として有用だが、その完成だけをレターの新規性とはしない。
