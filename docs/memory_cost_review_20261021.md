# 記憶費用・校正の追加原典確認

2026年10月21日、P17生成中に確認。これらを新しい手法として採用した報告ではない。[原典・版・ハッシュ・確認範囲](../reports/memory_cost_sources_20261021.json)を残した。各方式の性能再現と正式採録の独立確認は未実施。

| 原典 | 今回確認した範囲と重なり | 本研究での扱い |
|---|---|---|
| [Self-Compacting Language Model Agents](https://arxiv.org/html/2606.23525v1) | 導入と方式。作業の区切りに応じた圧縮、既存会話へ指示を追加してKVキャッシュを再利用する設計 | 「必要なときだけ圧縮」「要約時にキャッシュを使う」だけを新規性にしない。原方式の完全再現とは呼ばず、比較時の具体的な基準候補にする |
| [What Does Context Compression Cost an Agent?](https://arxiv.org/html/2608.16370v1) | 要旨と導入。圧縮後の再取得費用と最終成功の違いを扱う。詳細実験は今回未精読 | 成功だけでは費用が分からないという一般論を自分たちの発見にしない。現在の記録では、再取得、記憶生成、入力再処理を分けて調べる |
| [Persistent Memory in Multi-Agent LLM Inference](https://arxiv.org/html/2610.07782v1) | 1、4、5、7節。作動しない部品、条件汚染、複数軸の変更、反復変動に対する監査と、独立項目で共有記憶を評価する限界 | 自作基準の修正や正しい費用計上だけを独自機構としない。一課題内の状態保持と、課題をまたぐ記憶を区別する |
| [Grounding Agent Memory](https://arxiv.org/html/2609.11060v1) | 1〜3節。終了した課題の後、記憶管理役が読取専用ツールで環境を調べ、記憶を更新する方式 | 記憶を環境で再確認する一般構想も既出。今回の途中状態だけのP17と、課題終了後の持続記憶は対象時点が異なる |

近接した題名があることだけで、全ての具体的改良に研究余地がないと判断しない。一方、これらの一般機能をつなぎ、新しい名称を付けることも貢献の代わりにしない。方式を選ぶときには、入力・更新規則・費用・比較できる範囲まで対応付ける。

P16の記録通り条件では、４入力とも３回のリクエストは同一だったが、公開出力は３種類だった。[構造監査](../reports/P16_structural_audit.json)。これは固定seedで完全再現するとは限らないという実測であり、キャッシュを原因と確定した結果ではない。キャッシュ量・実行順・推論内部状態の影響を混ぜないため、以後も実行順と反復を残す。

llama.cppの[公式サーバー説明](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)も、キャッシュ利用とバッチサイズの差による非決定性を明記している。したがって、固定seedなのに出力が違うこと自体を新規発見とはしない。現在の実行版における具体的な原因の同定は別の確認が必要。

検索で見つかったContext Compaction Provenance (CCP) LabはSSRNの本文取得がHTTP 403だった。検索断片だけで具体的方式や優劣を確定せず、今回の本文比較の根拠には使わない。
