# 実行証拠・意味的な再利用の追加照合

P6で見た「送信されなかった操作を台帳が完了にする」例から、証跡付き記憶を新規技術だと早合点しないため、以前は要旨中心だった2原典の本文を追加確認した。P7の生成や条件は変更していない。正式な査読採録は未確認で、著者公開原稿として扱う。

## Cordon

[Cordon](https://arxiv.org/html/2606.17573v1)の4.2–4.3節では、ツールの結果へ実行基盤がハンドルを付け、後続の要約や成果物との依存を記録する。モデルが語った記憶を事実の原簿にしない、という立場も明示されている。4.6節は部分的な実行後の復旧と作用不明の扱い、6.5節は観測・仲介できる操作への適用範囲を説明する。

従って、実行ID・参照・実行状態を記憶へ付けること自体を独自の中核にはしない。一方、観測可能な作用を管理することと、自由文の「要求を満たした」という主張を安価かつ正しく判定することは同じではない。この点は本文の限定を踏まえた研究側の整理であり、Cordonを今回の台帳へ実装して比較した結果ではない。新規な空白が証明されたとも扱わない。

## Incremental Consistency Execution

[原稿](https://arxiv.org/html/2609.24090v1)の3節では、出力項目ごとの依存・同等性判定・版を使い、変更後も同等な結果を再利用する。3.2.3–3.2.5節は摂動と反例による適用範囲の更新、複数項目の変化と再実行を扱う。5節では、作用を隔離できる検証環境、決定的に実行できる同等性規則、元情報の再取得などを必要条件としている。

依存を使った部分再計算や、反例に応じた範囲の縮小だけでも差にならない。また、既知の反例を除くという本文の性質を、未観測の全入力に対する正しさの保証へ拡大解釈しない。今回の未実行操作の誤完了は、そもそも検証済みの出力を再利用している状況ではないため、この方式の反証例とは呼べない。

## 今の実験への反映

P7は単純な退避と実行状態の明示で足りるかを調べる。足りるなら通常の基盤改善として採用する。足りない場合も、参照が正しいか、要求を満たしたか、元の観測が既に目的状態を示すかを分けて確かめる。次の機構を選ぶには、この照合で残る問題と、既存方式との差が必要になる。

P8の結果には、複数操作の順序・送信・未実行・作用不明を検査する[監査](../scripts/audit_native_execution.py)を加えた。これは成果物の最終正しさの代用ではない。環境への追加操作やモデル推論を使わず、既存の実行記録から計測の整合性を確認する。

初回調査の確認範囲を消さず、追加の範囲・原典ハッシュを[記録](../reports/R18_runtime_followup_sources.json)に残す。原稿の全文、タスク入力、操作本文は公開しない。
