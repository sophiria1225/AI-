# AIハーネス研究

**研究の主目的は、AIオーケストレーションに伴う不要な情報取得・共有・呼び出し・実行をハーネスで削減し、タスクの性能を維持することです。** 履歴・作業状態・担当再編は、そのための制御対象や手段です。現在の引き継ぎ比較は、入力削減が必要情報の欠落や再取得で逆効果にならないかを調べる局所検証で、目的自体を引き継ぎへ変更していません。[ユーザーと確認した目的・費用・評価方針](docs/research_objective_20261022.md)。

**09時台の実装：P33の３条件を固定。** 全32分岐の[費用分解](docs/cost_profile_20261022.md)から、操作・コード・状態を残して古い長い出力だけを省く対照を追加しました。全履歴／出力省略／省略＋変数・API一覧を、同じ４課題・予算で比較します。全前半の再生と493検査は合格、初回入力の短縮は確認済み。総費用と成功は全12実行終了後に判断します。[仕様・採否基準](docs/experiments/P33_output_views.md)／[現在の進捗](https://github.com/sophiria1225/AI-/issues/168)。通常の観測省略や一覧の提示を新規性とはしていません。

## 実装と記録の扱い

`scripts/`に実行・計測・評価、`configs/`に固定条件、`tracking/tasks.json`にIssue・Projectの作業定義を置きます。段階ごとにブランチとPRを作り、CIと記録確認を経て反映します。

モデル重み、元データ、模擬資格情報、完全な履歴、独立評価の追加情報はGitへ入れません。原記録は実験機の`records/`、独立評価は`private_eval/`へ分離します。
実験機はM3 Ultra・メモリ256GiB。論理的な担当が増えてもモデル重みを複製せず、一つのモデルを順番に利用します。

GitHubの変更先は **sophiria1225/AI-だけ**です。専用Projectには当リポジトリのIssueだけを登録します。[作業ルール](AGENTS.md)を守ります。

```bash
# 進捗文書の生成（外部への書き込みなし）
python3 scripts/sync_tracking.py
# 許可されたIssueとProjectへ同期
python3 scripts/sync_tracking.py --publish
# 共通の検査
python3 -m unittest discover -s tests -v
```
